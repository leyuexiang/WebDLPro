# 场景发布变更检查表

发生场景、动作、关键环节、二维节点或三维映射变化时完整执行。勾选项必须以代码、测试或最终产物证据为依据。

## 一、变更前审计

- [ ] 运行 `node .agents/skills/scene-release-gate/scripts/inspect-release-contract.mjs`，保存当前摘要。
- [ ] 检查工作区已有修改，区分本次变更与用户未提交内容。
- [ ] 明确预期新增、删除或修改的动作、场景、关键环节、节点和映射。
- [ ] 搜索同类成熟场景的现有实现和测试，不根据截图或记忆猜测协议。

## 二、能力分类

### 仅导航场景

- [ ] 登记稳定的 `action.<scene>.overview`（场景总览动作）。
- [ ] 动作指向场景默认拓扑，且 `unityAction.type` 为 `none`（无三维动作）。
- [ ] 场景的 `supportedActionIds`（支持动作标识）反向包含该动作。
- [ ] 三维场景映射存在，但未核验的节点、流程步骤和路线保持空数组。
- [ ] 未创建虚假关键环节、资源标识、相机位或状态节点。

### 有关键环节的场景

- [ ] 登记 `action.<scene>.<detail>`（关键环节动作）和 `process-detail.<scene>.<detail>`（关键环节标识）。
- [ ] 动作使用 `enterProcessDetail`（进入关键环节）并引用同一关键环节标识。
- [ ] 关键环节完整包含 `resourceId`、`cameraPoseId`、`stateNodeId` 和 `topologyDataContextId`。
- [ ] 场景的 `supportedActionIds` 同时包含总览与关键环节动作。
- [ ] 第三层拓扑上下文只加载登记文件，并使用显式 `penId → nodeId`（图元标识到节点标识）绑定。
- [ ] 三维场景映射只登记已核验节点、流程步骤和路线。
- [ ] 二维选择、三维反向选择、设备状态和双击交互复用稳定节点标识。

## 三、发布链路同步

- [ ] `scene-topology-manifest.json`（场景拓扑结构清单）的 `actions` 包含全部公开动作。
- [ ] 每个场景的 `supportedActionIds` 与动作目标场景一致，无悬空或漏引。
- [ ] `processDetails`（关键环节目录）与关键环节动作一一对应。
- [ ] `unitySceneMappings`（三维场景映射）的场景、节点和步骤与已交付能力一致。
- [ ] `release-manifest.json.workflowActions`（发布摘要流程动作）与结构清单动作集合完全相同。
- [ ] 本地自测页逐项通过公开 `workflow.trigger`（流程触发）调用，不使用内部视图捷径。
- [ ] 所有变更回到源生成器实现；未直接修改任何既有发布目录。

## 四、双层门禁与测试

- [ ] 绝对契约明确列出本次必须发布的动作、关键环节和仅导航场景能力边界。
- [ ] 相对一致性校验比较结构清单、发布摘要、场景反向引用、关键环节和三维映射。
- [ ] 正向测试证明新增能力存在、字段完整且语义正确。
- [ ] 负向测试分别删除结构动作、摘要动作、场景反向引用、关键环节字段和映射，确认门禁失败。
- [ ] 覆盖“结构清单与发布摘要同时漏项”的情况，确认绝对契约仍能拦截。
- [ ] 仅导航场景出现流程步骤、关键环节或未核验节点时，门禁必须失败。
- [ ] 关键环节缺少资源、相机位、状态节点、拓扑上下文或三维进入动作时，门禁必须失败。

## 六、验证与打包

在 `power-data-web` 目录执行与变更对应的专项测试，然后执行：

```powershell
npx vitest run tests/configured-power-scenes-manifest.spec.ts tests/release-artifact-contract.spec.ts
npm run test:unit
npm run typecheck
npm run build
```

包含关键环节时，读取 `audit-process-detail-production.mjs` 的当前参数后执行生产审计。完成后生成全新的发布目录，并执行：

```powershell
npm run validate:release-artifact -- --root <新发布目录>
```

- [ ] 重新运行技能检查脚本并保存变更后摘要。
- [ ] 最终发布目录未覆盖任何历史目录。
- [ ] 最终产物门禁为零问题。
- [ ] 直接读取包内两个清单，确认动作、场景、关键环节和映射符合预期。
- [ ] 记录测试、类型检查、构建、审计、发布目录和最终门禁结果。

任一必需项缺失时不得声明发布完成；将缺失资源、协议输入或合作方确认项列为明确阻塞项。
