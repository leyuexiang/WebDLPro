# 场景发布门禁同步

## 目标

让场景能力从源清单到合作方最终产物保持完整一致。每次场景、关键环节、拓扑动作或三维映射变化时，同时更新实现、发布摘要、绝对契约、相对一致性校验、负向测试、自测入口和文档，避免“项目内可用，但合作方清单不可见”。

## 适用边界

适用于新增或删除场景、开放场景导航、接入关键环节、调整二维与三维映射，以及输出测试包、联调包或正式包。仅修改拓扑视觉、普通页面样式或不影响发布能力清单的代码时，不触发本技能；这类拓扑实现使用 `$json-topology-replication`。

## 当前事实来源

不得把历史动作数量、场景数量或关键环节数量写成永久事实。开始和结束时均从仓库根目录执行：

```powershell
node .agents/skills/scene-release-gate/scripts/inspect-release-contract.mjs
```

该摘要来自 `createConfiguredPowerScenesManifest()`（配置场景清单生成函数）。把其输出与本次需求对比，明确新增、删除和保留项。需要定位实现、门禁或文档时读取 [项目文件地图](references/project-map.md)；发生任一契约变化时完整读取 [变更检查表](references/change-checklist.md)。

## 执行流程

1. 审计当前清单和工作区，识别用户已有改动；不得回退或覆盖无关变更。
2. 将需求归类为场景导航、关键环节、拓扑节点映射或既有契约修改，并列出预期契约差异。
3. 从源生成器完成实现，同步结构清单、场景反向动作、关键环节目录、三维映射和发布摘要。不得直接修补打包后的文件。
4. 同步两类门禁：绝对契约验证预期能力确实存在；相对一致性验证结构清单、发布摘要、场景引用和映射互相一致。
5. 为新增能力和每种漏同步方式补充有业务意义的正向及负向测试。
6. 更新三份核心规范、对应场景实施状态、任务总览和本次发布记录。数量和清单必须由当前代码重新统计。
7. 本地自测入口必须使用合作方公开的 `workflow.trigger`（流程触发）路径，逐项覆盖发布动作；禁止用内部 `view.open`（视图打开）捷径代替验收。
8. 完成测试、类型检查、生产构建和关键环节审计后生成新发布目录；旧发布目录不得覆盖。
9. 对最终发布目录执行产物门禁，并直接读取包内清单复核动作、场景、关键环节和映射。保存命令、发布目录、统计结果和失败项作为交付证据。

## 契约规则

- 仅导航场景的总览动作使用 `unityAction.type: none`（无三维动作），不得虚构流程步骤、关键环节或三维节点。
- 新关键环节必须同时登记动作标识、关键环节标识、资源标识、相机位标识、状态节点标识、拓扑数据上下文、`enterProcessDetail`（进入关键环节）动作、场景反向引用和第三层显式拓扑绑定。
- 发布摘要中的 `workflowActions`（流程动作摘要）必须覆盖结构清单全部公开动作，且不得多出未知动作。
- 结构清单与摘要同时漏项时，相对校验无法发现，因此绝对契约必须独立声明本次应发布能力。
- 删除或降级能力与新增能力执行相同审计，并同步清理全部反向引用、测试和文档；不得只删除单侧记录。
- 包内最终文件是交付事实。源代码测试通过但最终目录未通过产物门禁，不得声明完成。

## 强制停止条件

遇到以下任一情况时不得打包或交付：动作仅存在于结构清单或发布摘要一侧；场景未反向声明动作；关键环节缺少任一固定映射；仅导航场景伪造三维能力；自测页绕过公开动作；核心文档与当前清单漂移；最终产物未校验或校验失败。

## 交付内容

先报告最终动作、场景、关键环节数量和本次差异，再列出实现、门禁、测试、文档、发布目录及验证结果。存在未交付的三维资源或映射时，明确标为阻塞项，不得以占位数据冒充完成。
