## 本轮补充的测试实现

在 `Assets/Tests/PlayMode/MultiSceneCoordinatorPlayModeTests.cs` 中增加“全能力测试控制器通过桥接接收受控场景动作”用例。测试控制器具备以下边界：

1. 只存在于播放模式测试程序集，不进入场景目录、正式场景、资源包或发布映射。
2. 所有动作只执行常数时间字段记录，不创建 Unity 对象、不持有场景句柄、不启动循环或协程，不增加运行包内存与每帧开销。
3. 流程、聚焦、节点四态、路径、显隐分别记录独立参数，避免后续命令覆盖字段后产生假阳性。
4. 测试经正式 `UnityIframeBridgeManager`（Unity 内嵌框架桥接管理器）分派，不直接调用控制器，从而覆盖载荷校验、能力检查、当前控制器重绑和命令结果回传。

## 风险与后续边界

1. 其余八个场景的正式模型、动作、四态、路径和设备映射仍待任务-039—047交付，并由任务-053逐场景验收。
2. 浏览器宿主页、外层嵌入壳与真实 WebGL 的完整三层端到端截图和失败场景归档属于任务-052；本任务只验证 Unity 运行时和构建边界。
3. 目标硬件的长时间内存、加载耗时和帧率预算属于任务-054，不以本轮批处理耗时替代。
4. Unity 批处理测试命令不得额外附加 `-quit`；Unity 2022 测试运行器会自行退出，提前退出参数可能只完成脚本编译而不生成测试报告。正式构建入口仍需使用 `-quit`。
5. 新版正式网页图形构建必须验证元数据发布标识与主播放器及场景资源目录完全一致，并通过前端发布门禁；成功前任务保持“已实现待验收（90%）”。
