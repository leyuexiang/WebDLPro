## 本轮补充的测试实现

在 `Assets/Tests/PlayMode/MultiSceneCoordinatorPlayModeTests.cs` 中增加“全能力测试控制器通过桥接接收受控场景动作”用例；并在 `Assets/Tests/EditMode/BusinessSceneBootstrapAssetTests.cs` 中增加真实燃气三模型四态登记前置条件用例。测试控制器和资产测试具备以下边界：

1. 只存在于播放模式测试程序集，不进入场景目录、正式场景、资源包或发布映射。
2. 所有动作只执行常数时间字段记录，不创建 Unity 对象、不持有场景句柄、不启动循环或协程，不增加运行包内存与每帧开销。
3. 流程、聚焦、节点四态、路径、显隐分别记录独立参数，避免后续命令覆盖字段后产生假阳性。
4. 测试经正式 `UnityIframeBridgeManager`（Unity 内嵌框架桥接管理器）分派，不直接调用控制器，从而覆盖载荷校验、能力检查、当前控制器重绑和命令结果回传。
5. 编辑器资产测试显式复现播放器的节点缓存和四态登记初始化顺序，再逐项验证三个真实模型的渲染器、材质槽、`_BaseColor`（基础颜色）属性和渲染器归属；不会伪造平台状态、设备编号或运行时清单。

## 风险与后续边界

1. 其余八个场景的正式模型、动作、四态、路径、`doubleClickBehavior` 和 `nodeId → 可选 sceneNodeId` 结构映射仍待任务-039—047交付，并由任务-053逐场景验收；真实设备标识只由平台内部维护，不进入 Unity 构建或我方结构清单。
2. 对存在 `sceneNodeId` 映射的节点，必须验证四态实际作用到对应模型；Unity 不支持、超时或节点失败时，外层二维成功隔离由任务-038、048、052验证，不在 Unity 内部伪造外层结果。
3. 浏览器宿主页、外层嵌入壳与真实 WebGL 的完整三层端到端截图和失败场景归档属于任务-052；本任务只验证 Unity 运行时和构建边界。
4. 目标硬件的长时间内存、加载耗时和帧率预算属于任务-054，不以本轮批处理耗时替代。
5. Unity 批处理测试命令不得额外附加 `-quit`；Unity 2022 测试运行器会自行退出，提前退出参数可能只完成脚本编译而不生成测试报告。正式构建入口仍需使用 `-quit`。
6. Unity 节点状态迟到隔离已使用壳内本地快照序号和物理场景激活代次；平台 `sourceRevision` 和 `statusUpdatedAt`只作诊断，较小或相同来源修订的后到合法完整快照仍必须生效。
7. 结构版本4的编辑器模式、播放模式和正式网页图形构建已于2026-08-14重新归档并通过；真实平台结构清单读取、真实三维状态和基础视觉恢复仍由任务-038、049、052按其各自验收范围继续处理，不影响本任务关闭。
