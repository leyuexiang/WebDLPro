# 任务-013：外部事件上报实施状态

**状态：** 进行中（80%）
**最后更新：** 2026-08-05
**前置核对：** 任务-009、011 已完成；任务-027 已提供正式清单驱动的设备双击意图；任务-037 已交付三维反向选择的清单映射、回环阻断与受控上报，真实发布环境仍待联调。

## 本轮已交付

1. 新增 `power-data-web/src/host-bridge/host-event-sender.ts`，作为普通业务上行事件的唯一受控发送器。
2. 发送器统一从当前 `HostBridge`（外层桥）安全上下文补齐实例标识、会话标识、递增消息标识和时间戳；业务层不能直接接触父窗口或目标来源。
3. 已实现以下协议载荷转换与发送前复校：
   - `command.result`（命令结果）：强制复用生命周期结果中的 `replyTo`（回复关联标识）。
   - `view.changed`（视图变更）：仅允许稳定上下文处于 `ready`（就绪）后上报。
   - `topology.node.dblclick`（拓扑节点双击）：仅接收任务-027已从正式清单解析出的设备意图，`deviceId`（设备标识）在类型上必填，事件消息标识同时作为关联标识。
   - `state.snapshot`（状态快照）：强制带查询命令的 `replyTo`，仅承载有限运行状态。
   - `system.error`（系统错误）：仅接收 `HostProtocolError`（外层协议受控错误），不接收原始 `Error`（异常对象）。
   - `scene.object.selected`（三维对象选择）：只接收任务-037以当前原子清单映射出的场景、三维节点、设备和二维节点标识；组合根再次核对握手及稳定上下文后发送，不透传 Unity 原始对象或消息标识。
4. 新增 `host-event-sender.spec.ts`，验证命令关联、已提交视图门禁、设备双击必填标识、状态查询关联、错误脱敏和非法运行时载荷拒绝发送。
5. 新增 `host-runtime-composition.ts`，在嵌入壳中将真实 `HostBridge`（外层桥）、握手、命令生命周期、任务-012分派器、任务-033 `view.open`（原子打开视图）事务与事件发送器装配为唯一链路；只在合法嵌入启动参数、唯一拓扑运行时和 Unity 运行时均就绪后启动。
6. 初始 `system.init`（系统初始化）与普通 `view.open` 复用同一个原子事务；稳定提交后才上报 `view.changed`（视图变更）。`state.get`（状态查询）产生带原查询 `replyTo`（回复关联标识）的状态快照，`command.result`（命令结果）始终走生命周期回包。
7. 拓扑双击仅在握手完成且设备意图的场景/拓扑与当前稳定上下文一致时转换为 `topology.node.dblclick`（拓扑节点双击）；三维反向选择仅在同样的上下文校验通过后转换为 `scene.object.selected`（三维对象选择）。
8. 三维反向选择的外层关联标识由嵌入壳生成；Unity 内层消息标识只在固定容量去重表中使用，避免把时间戳或运行时格式透传到外层协议。
