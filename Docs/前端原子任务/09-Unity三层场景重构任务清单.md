### 更新规则

1. 每个任务只能有一个当前状态。
2. “已实现”不等于“已完成”；必须同时满足需求、边界和验收要求。
3. 外部资料缺失时标记“待外部资料”，在备注中写明缺失项、责任方和解除条件。
4. 一个任务出现范围变化时，先更新任务边界，再继续实现，禁止在代码中临时扩大范围。
5. 验收证据至少记录资源版本、场景版本、浏览器、硬件、测试时间和结果摘要。
6. 如果发现任务无法独立验收，应在不修改已完成任务边界的前提下拆出新任务，不直接把新需求塞入当前任务。

## 二、执行总原则

- 所有绑定使用稳定 ID，不使用模型名称、文件名、层级路径或坐标猜测。
- 第一层只放九个代表性建筑低模和必要的管道、区域效果，不放九个完整业务场景设备。
- 第一层只有异常状态才触发停流和区域效果，正常状态不配置影响效果；其他状态保留扩展入口。
- 区域正式效果只实现半透明区域覆盖和静态区域边界；粒子、脉冲和扫描线不进入第一版默认实现。
- 模型异常、告警、描边、内部颜色和闪烁继续使用现有高亮插件。
- 透明、不透明、流动等渲染模式由少量共享材质变体负责；颜色、透明度、闪烁和流速由材质属性块负责。
- 厂房可以是一个 Mesh、多个材质球，只做整体控制，不做局部墙体和屋顶控制。
- 厂房壳体资源加载后常驻；进入内部时只隐藏或整体半透明，不卸载壳体。
- 设备细节按需加载，状态先进入缓存，模型加载完成后重放最新状态。
- 五个页面独立接收平台状态，不要求平台方提供共享连接。
- 不在本次重构中强制引入 Addressables（可寻址资源系统），优先延续现有 AssetBundle（资产包）方案。

### R-004：三层稳定标识与绑定表

- 正式设备预制体、动态节点 Renderer/高亮绑定、本地细节加载器和厂房点击入口尚未提供，因此当前未接入九个业务场景；异常设备首次显示的真实高亮、正式模型资源释放和页面联调仍待外部资源。

### R-014：沙盘到二层及厂房内部下钻

**平台返回沙盘方案（用户确认）：**

全局沙盘只有三维场景，没有对应的全局拓扑图。平台触发业务场景返回时，只切换到全局 `Overview` 场景；网页隐藏拓扑区域并清空当前业务拓扑选择，不新增或伪造全局 `topologyId`。

返回必须经过统一联动协调器，固定顺序为：校验返回命令 → 开始新 `transitionId` → 隐藏并阻断旧业务拓扑 → 切换 `Overview` → 清空业务选择 → 提交全局沙盘稳定状态。切换期间禁止出现“全局沙盘 + 旧业务拓扑”的可操作组合；失败、超时、快速重复返回、旧回调和释放竞态沿用现有事务取代与恢复规则。

**当前实施记录（2026-08-27）：**

- 平台已确认复用 `system.init` 与 `view.open`：传入 `sceneId="overview"` 时必须省略 `topologyId`；业务场景仍必须携带合法 `topologyId`。`overview` 是独立 `ViewSceneId`，不加入九项业务 `SceneId` 闭集，也不写入业务场景拓扑清单。
- 前端事务在 Unity 返回匹配的新 `sceneActivationId` 后，停用而不销毁唯一拓扑 Canvas，清空二维选择和业务状态投影，再提交无 `topologyId` 的全局沙盘稳定上下文；`view.changed`、初始化确认和状态快照均真正省略该字段。
- 从沙盘重新打开业务场景时，复用同一 Canvas，预解析并激活目标业务拓扑后才提交；总览切换失败、超时和旧回调不会清空上一业务稳定上下文或覆盖新事务。
- 前端类型检查、330 项单元测试和生产构建均通过；新增覆盖业务场景切入总览、总览无拓扑出站事件、单画布停用与再次业务激活的回归测试。Unity 的 Bootstrap 平台命令链路播放模式测试已通过。
- 新增 `BusinessScenePointerContracts` 和 `BusinessSceneInteriorEntryController`：厂房入口只接受显式 `sceneId`、`interiorId`、交互 Collider、设备挂载点、细节目录、加载器、状态重放器及壳体材质绑定，不从对象名称、层级路径或坐标推导业务关系。
- `PowerPlantProcessController` 增加可选优先点击消费者槽位。同一鼠标射线先交给厂房入口；入口消费后立即结束处理，不再触发普通节点 Focus、交互描边或 `objectSelected` 回传。未配置入口时原有选择路径保持不变，点击热路径不做组件扫描。
- 入口进入时复用 R-013 的细节加载与状态重放事务；设备首次显示前保持隐藏，状态失败保留壳体；返回先恢复壳体再释放设备细节，入口 Collider 在内部显示时关闭以避免遮挡，释放与重复进入保持幂等。
- R-014 新增编辑模式测试 3/3 通过，覆盖显式碰撞命中、未登记碰撞体拒绝、状态重放失败保壳体、返回资源释放和普通节点点击优先级；编译通过，Unity 控制台无警告和错误。
- 当前 `CoalPower` 场景仅有现有流程控制器和环境/设备对象，未发现正式厂房专用 Collider、九场景细节目录、设备细节加载器或设备资源包；因此尚未猜测并写入场景绑定。正式资源交付后还需补齐场景装配、真实设备首次高亮和平台端点击联调。

**需求：**

- 建筑点击只根据配置查找目标业务 `sceneId`。
- 不使用模型名、层级路径或屏幕坐标作为跳转参数。
- 沙盘到二层使用现有场景切换事务。
- 二层到内部设备属于当前业务场景的细节加载，不应重复创建 Unity 运行包。

**验收要求：**

1. 九个建筑均能进入唯一对应业务场景。
2. 场景切换期间不会出现可操作的错配视图。
3. 切换失败时能保留或恢复上一个稳定视图。
4. 厂房点击只加载当前业务场景设备细节。
5. 返回操作能恢复厂房壳体视图，并清理设备细节运行资源。
6. 快速重复点击、快速返回和重复进入不会产生并发下钻事务。
7. 平台触发业务场景返回时，必须通过同一原子事务切换到全局 `Overview` 三维场景、隐藏网页拓扑并清空业务拓扑选择；不能只调用 Unity 场景切换而遗留旧拓扑。
8. 返回事务成功后网页只保留全局三维沙盘作为可操作内容，不提交全局 `topologyId`；旧业务拓扑、业务选择和业务动作不得继续生效。
9. 返回期间隐藏旧业务拓扑并阻断交互；切换失败、超时、快速重复返回和旧回调均必须保持或恢复上一稳定组合。
10. 全局沙盘没有对应拓扑图，不新增伪造拓扑、不使用默认业务拓扑，也不把 `overview` 加入九项业务 `SceneId` 闭集。
11. 平台返回命令的来源校验、请求标识、成功/失败回执和网页隐藏拓扑行为有明确契约。

### R-015：五页面独立状态接入与场景投影

**需求：**

支持五个页面各自接收外部平台设备状态，并将状态投影到各自的沙盘、二层壳体或设备细节 Unity 实例。

**边界：**

- 每个页面拥有独立状态缓存、页面会话、Unity 桥接和场景视觉状态。
- 不要求平台方改造为共享 WebSocket 连接。
- 一个页面的状态、场景切换、释放和错误不能修改其他页面。
- 不把页面之间的缓存共享作为本次必要条件。

**验收要求：**

1. 五个页面可以同时打开并分别显示不同场景。
2. 一个页面收到异常时，其他页面不会误变色或误停流。
3. 每个页面只向当前 Unity 实例投影当前场景目标。
4. Unity 场景尚未就绪时，状态不会丢失，加载完成后能重放最新快照。
5. 页面关闭或释放后，本页监听器、状态缓存、队列和 Unity 资源全部停止。
6. 五页面分别重连时不会产生重复状态覆盖或旧会话回写。

### R-016：五实例性能、内存与浏览器稳定性

**需求：**

在目标浏览器和目标设备上验证五个页面同时运行的内存、显存、帧率、加载和图形上下文稳定性。

**边界：**

- 不以资源本地化或浏览器下载缓存代替运行时内存测试。
- 不以单页面测试结果推断五页面可用。
- 不通过无条件增大 WebGL 内存上限掩盖资源和渲染问题。

**验收要求：**

1. 记录单沙盘、单二层壳体、单设备细节和五实例同时运行的内存峰值。
2. 记录首帧、场景切换、设备加载和返回耗时。
3. 记录五实例同时收到异常状态时的状态更新耗时和帧率。
4. 页面隐藏后能暂停或降低非关键渲染和拓扑重绘。
5. 连续下钻、返回、切换和状态更新后没有持续内存增长。
6. 浏览器没有出现 WebGL 图形上下文丢失、黑屏或实例互相影响。
7. 记录不同质量档位下的性能差异，并冻结正式默认档位。

## 五、执行期间的防跑偏检查

每次开始一个任务前，先回答以下问题并记录在任务备注中：

1. 本任务修改的是哪一层：沙盘、二层壳体、设备细节、状态层还是发布层？
2. 本任务是否引入了新的业务 ID？如果引入，是否同步更新绑定表和清单校验？
3. 本任务是否改变了外部状态协议？如果改变，是否确实属于本计划范围？
4. 本任务是否把资源加载、视觉效果和业务影响关系耦合在一起？如果是，应重新拆分。
5. 本任务是否增加了每帧遍历、材质复制、粒子对象、协程或无限缓存？如果是，必须先说明容量和释放路径。
6. 本任务是否改变厂房从整体控制到局部控制的范围？如果是，必须新增任务，不得直接扩大 R-012。
7. 本任务是否把五个页面改造成共享连接或共享缓存？这不是当前方案的必要条件，必须单独评审。
8. 本任务是否依赖美术尚未确认的模型结构、UV 或材质属性？如果是，状态标记为“待外部资料”。
9. 本任务是否有可重复的验收步骤和证据位置？没有则不得标记为已完成。
