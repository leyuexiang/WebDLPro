### 更新规则

1. 每个任务只能有一个当前状态。
2. “已实现”不等于“已完成”；必须同时满足需求、边界和验收要求。
3. 外部资料缺失时标记“待外部资料”，在备注中写明缺失项、责任方和解除条件。
4. 一个任务出现范围变化时，先更新任务边界，再继续实现，禁止在代码中临时扩大范围。
5. 验收证据至少记录资源版本、场景版本、浏览器、硬件、测试时间和结果摘要。
6. 如果发现任务无法独立验收，应在不修改已完成任务边界的前提下拆出新任务，不直接把新需求塞入当前任务。

## 二、执行总原则

- 所有绑定使用稳定 ID，不使用模型名称、文件名、层级路径或坐标猜测。
- 第一层只放九个代表性建筑低模和必要的管道、区域效果，不放九个完整业务场景设备。
- 第一层只有异常状态才触发停流和区域效果，正常状态不配置影响效果；其他状态保留扩展入口。
- 区域正式效果只实现半透明区域覆盖和静态区域边界；粒子、脉冲和扫描线不进入第一版默认实现。
- 模型异常、告警、描边、内部颜色和闪烁继续使用现有高亮插件。
- 透明、不透明、流动等渲染模式由少量共享材质变体负责；颜色、透明度、闪烁和流速由材质属性块负责。
- 厂房可以是一个 Mesh、多个材质球，只做整体控制，不做局部墙体和屋顶控制。
- 厂房壳体资源加载后常驻；点击厂房后按需加载第二层整套内部设备，进入内部时只隐藏或整体半透明壳体。
- 第一层沙盘和第三层关键环节只显示占满子应用可视区的三维画面；只有第二层厂区同时显示三维画面和当前业务拓扑。“全屏三维”不代表自动调用浏览器原生全屏接口。
- 第三层按业务场景配置 0～多个关键环节，不写死每场景三个；当前首批仅燃煤、燃气各三套。
- 关键环节命令由 `workflow.trigger → actionId → processDetailId` 显式映射到新增白名单命令，只加载当前目标资源，并将相机切换到远离厂区的显式观察位；提交时停用拓扑并切换为全屏三维，不再激活关键环节拓扑，也不再通过凸显第二层单个模型并隐藏其他模型实现。R-016 起第三层禁止调用旧的其余模型半透明、全量显隐、包围盒聚焦、拓扑过滤和全场景管道停控；旧 `enterProcessStep` 仅允许作为历史兼容代码保留。
- 关键环节状态先进入缓存，模型加载完成后重放最新快照；设备四态只改变状态视觉，不控制管道流动、模型动画或粒子特效的播放与停止。
- 第三层动态效果使用独立播放控制器；本地自测页通过 `process-detail.playback`（关键环节播放命令）提供播放/停止按钮，正式平台仍需按权限边界接入，模型点击触发另行完成。
- 同一实例默认最多激活一套关键环节资源；切换、返回、失败和释放均必须清理句柄、动画、粒子和状态绑定。
- 五个页面独立接收平台状态，不要求平台方提供共享连接。
- 不在本次重构中强制引入 Addressables（可寻址资源系统），优先延续现有 AssetBundle（资产包）方案。
- `/gas-topology-json-preview` 是原始 JSON 拓扑替代显示方案的独立验证页；不计入 R-001—R-021，不接入正式场景清单、状态缓存、Unity 桥接或发布入口。确认替换正式拓扑前，必须另立任务完成资源预算、交互、状态投影、无障碍和发布回归。

### R-012：第二层厂房整体多材质显示与透明状态

**需求：**

支持一个 Mesh、多个材质球的厂房壳体进行整体不透明、整体半透明、整体隐藏和整体恢复。

**边界：**

- 以厂房整体为一个绑定目标。
- 不控制局部屋顶、墙体或单独材质区域。
- 每个材质槽保留原始贴图和表面参数。
- 使用共享透明材质变体和属性块，不为每个材质槽无界复制材质。

**验收要求：**

1. 所有材质槽都能进入整体透明状态。
2. 所有材质槽都能恢复原始外观。
3. 厂房整体隐藏时不会释放壳体资源。
4. 厂房整体半透明时内部设备可见，且透明排序问题已记录并达到可接受标准。
5. 异常高亮插件与壳体透明状态不会互相覆盖。

**明确不做：**

- 不要求局部墙体透明。
- 不要求屋顶单独隐藏。
- 不要求不同材质槽表达不同业务状态。

**当前实施记录（2026-08-27）：**

- 新增 `BusinessSceneShellVisualRuntime`：厂房壳体通过稳定 `shellId`、显式 `Renderer` 列表和原材质到共享透明变体的映射一次性登记，不扫描对象名称或层级。
- 初始化会原子校验全部 Renderer 和非空材质槽；任一槽位缺少透明变体，或透明材质不提供颜色/透明度逻辑属性时整体拒绝，不产生局部透明状态。
- 整体半透明只切换到预配置共享透明材质，并通过材质属性块逐槽写统一透明度；不使用 `renderer.material`，不创建运行时材质副本，也不修改共享材质资产。
- 整体隐藏只关闭已登记壳体 Renderer，不停用壳体根节点，因此同层级内部设备、挂载点和业务脚本保持可用；整体不透明和整体恢复分别支持强制显示与精确恢复登记启用状态。
- 每个材质槽登记时保存完整属性块；恢复顺序固定为原始 `sharedMaterials` 后恢复原属性块，原本为空的槽位会明确清除覆盖，释放前恢复基线且重复释放幂等。

### R-013：第二层整套内部设备按需加载与状态重放

**需求：**

点击厂房后加载当前业务场景第二层整套内部设备，并将状态缓存中的最新设备状态应用到新加载模型。

**推荐顺序：**

```text
点击厂房
→ 保持壳体
→ 加载第二层整套内部设备
→ 加载成功
→ 应用最新状态
→ 壳体隐藏或半透明
→ 显示内部设备
```

**边界：**

- 设备未加载完成前不能隐藏壳体。
- 设备加载失败时保留壳体并返回结构化错误。
- 不要求平台重新发送状态；使用页面已有状态快照重放。
- 整套内部设备退出后释放其独占资源，厂房壳体继续保留。
- 本任务不加载或控制第三层关键环节资源。

**验收要求：**

1. 第二层整套内部设备加载成功后能显示正确设备模型。
2. 加载期间到达的新状态最终以最新状态为准。
3. 异常设备在首次显示时即显示正确高亮效果。
4. 加载失败时厂房壳体仍可操作。
5. 重复点击不会并发创建多个整套内部设备实例。
6. 返回厂房后再次进入不会累积旧设备对象、监听器或材质。

**当前实施记录（2026-08-27）：**

- 新增 `BusinessSceneDetailStateSnapshotMirror`：只接受当前业务场景显式声明的最多 500 个 `sceneNodeId`，按本地 `snapshotSequence` 原子替换完整快照；未知、重复、超量节点整体拒绝，相同或更小序号幂等忽略。
- 状态镜像不是新的业务权威来源；网页现有 `TopologyDeviceStateCache` 仍保存完整权威快照。Unity 镜像只保留当前场景的有限投影，使设备返回后再次创建的新实例能重放同一最新序号，无需平台重新发送状态或新增外层命令。
- 新增 `BusinessSceneInteriorRuntime`，固定进入顺序为：保持壳体 → 加载未激活设备 → 同步读取并重放最新状态 → 切换壳体整体隐藏或半透明 → 最后激活设备。读取状态到设备激活之间不跨帧，避免显示点击时捕获的旧快照。
- `BusinessSceneDetailRuntime` 在提交加载结果时强制保持设备根节点未激活；状态注册或重放失败时立即释放设备句柄，壳体不切换、不暴露部分状态设备。
- 加载和状态应用期间重复点击幂等合并；加载中返回会使旧事务失效并进入清理状态，在旧协程真正结束前拒绝重新进入，避免同时启动多个有效设备加载事务。
- 返回厂房固定先隐藏设备、恢复壳体，再释放设备独占实例与资源租约；完整释放同时恢复壳体基线，重复返回和释放保持幂等。
- R-013 定向编辑模式测试 3/3 通过；排除因用户工作区已删除 Highlight Plus（高亮插件）源码而失效的旧源码读取测试后，其余编辑模式回归 50/50 通过，Unity 控制台无警告和错误。测试覆盖完整快照缺失节点清除、加载期间新状态覆盖、首次显示前重放、同序号返回重入、状态失败保留壳体、加载中返回和并发重入阻断。
- 正式设备预制体、动态节点 Renderer/高亮绑定、本地细节加载器和厂房点击入口尚未提供，因此当前未接入九个业务场景；异常设备首次显示的真实高亮、正式模型资源释放和页面联调仍待外部资源。

### R-016：第三层命令加载、远端相机与返回事务

**需求：**

收到新增白名单关键环节命令时加载目标细节资源，完成最新状态重放后将相机切换到远离所属厂区的专用观察位，同时停用拓扑并让三维画面占满子应用可视区；返回时恢复第二层观察位、进入前的厂区拓扑和三维拓扑并存布局，并释放第三层资源。外层仍通过 `workflow.trigger` 进入，但必须经 `actionId` 显式映射到 `processDetailId`，不得复用旧 `enterProcessStep`。

**推荐顺序：**

```text
workflow.trigger
→ 校验 actionId 并解析 processDetailId
→ 若当前不在目标场景，自动切换到目标业务场景默认拓扑并确认 sceneActivationId
→ 阻塞式重放目标场景最新权威设备状态
→ 调用新增白名单关键环节命令
→ 校验场景与关键环节映射
→ 加载目标资源但保持隐藏，并重放环节设备状态
→ 准备显式相机位
→ 停用拓扑输入与重绘
→ 原子切换为全屏三维并显示目标资源
→ 切换到关键环节专用相机位
→ 成功后释放上一套关键环节资源
```

**边界：**

- 不再通过凸显第二层单个模型并隐藏其他模型实现关键环节；旧 `enterProcessStep` 的显隐、相机复位和包围盒聚焦不得进入本事务。
- 关键环节稳定状态不携带 `topologyId`，不得激活总拓扑或流程过滤拓扑；停用的唯一拓扑画布不得接收输入或继续布局、重绘。
- R-016 新链路通过验收后，旧关键环节半透明表现正式停用；停用不等于立即删除，R-021 需在历史二维兼容回归后删除无有效引用的旧第三层专用代码。
- 远端展示锚点、相机位置和旋转全部显式配置。
- 第二层整套内部设备可以保持已加载，但不得为切换第三层而全量遍历其 Renderer。
- 加载、状态重放或相机准备失败时保留上一稳定视图。
- 拓扑暂停必须保留同一个画布组件实例，只暂停输入、尺寸监听、布局和重绘；禁止以条件卸载方式销毁后重建。
- 第三层不得依赖停用整个第二层业务根节点完成空间隔离，必须使用显式远端展示锚点和专用相机位。
- 进入事务必须拆分为准备和提交两阶段；准备阶段保持目标资源隐藏且不移动相机，拓扑与布局就绪后才提交资源和相机。

**验收要求：**

1. 首批六个关键环节动作分别经 `actionId → processDetailId` 映射加载唯一正确资源并切换到正确观察位。
2. 关键环节画面中不会看到厂区模型与细节模型挤在同一空间。
3. 快速切换只提交最后有效事务，不产生多个活动实例。
4. 返回第二层后相机、交互和状态恢复正确，第三层资源释放。
5. 失败、超时、场景切换和迟到回调不会覆盖新稳定视图。
6. 关键环节只显示全屏三维画面，不显示或激活任何拓扑；返回第二层时恢复进入前的厂区拓扑和三维拓扑并存布局。
7. 进入、切换和退出关键环节期间，不出现“关键环节三维画面 + 厂区旧拓扑”的可操作组合，也不重建唯一拓扑画布。
8. 已在第三层时可直接切换到同场景另一关键环节，不强制先返回第二层；新资源提交成功前保留旧稳定视图，成功后只保留一套活动实例。
9. 第二层业务根节点在第三层期间可保持加载，不以整体停用掩盖远端空间配置缺失。
10. Unity 的资源显示与相机切换不得早于拓扑暂停和全屏布局提交。
11. 从沙盘或任意其他稳定业务场景触发已登记关键环节时，系统必须自动稳定目标业务场景并完成最新状态重放后进入第三层，不得要求用户手动预先进入对应场景。

**当前实施与纠偏记录（更新至 2026-09-01）：**

### R-017：第三层设备状态同步与故障视觉

**需求：**

将页面最新完整设备状态投影到当前关键环节细节模型，使同一逻辑设备在第二层和第三层保持一致，并复用现有四态与高亮视觉。

**边界：**

- 只投影当前细节资源显式登记的 `sceneNodeId`。
- 同一逻辑设备可在第二层和第三层绑定不同 Renderer，但状态来源必须一致。
- 模型加载完成前不显示未重放状态的设备。
- 缺失状态恢复基础视觉，不自动解释为离线。
- 每套关键环节可显式登记多个设备状态绑定；不得把整套模型压缩成单一 `stateNodeId` 后覆盖所有 Renderer。
- 正式视觉复用现有高亮能力表达描边、内部颜色和闪烁；材质属性块统一染色只允许作为资源或插件未就绪时的临时降级。

**验收要求：**

1. 进入关键环节时无需平台重发即可显示最新状态。
2. 加载期间到达的新快照最终覆盖旧快照。
3. 正常、告警、故障、明确离线与第二层显示语义一致。
4. 故障设备首次显示即使用现有故障颜色、描边、内部颜色和闪烁。
5. 切换环节、返回第二层和跨场景后无状态串场。
6. 一个关键环节内多个设备可独立显示不同四态，状态更新只访问已登记目标，不扫描完整模型层级。
7. 正式故障视觉包含已确认的描边、内部颜色和闪烁；临时统一染色不得作为正式验收证据。

**当前实施与纠偏记录（2026-08-31）：**

- 已实现燃气轮机单状态节点的加载后最新快照重放、后续更新、缺失恢复和四态材质视觉。
- 当前绑定只有一个 `stateNodeId`、一个视觉适配器，并使用材质属性块统一染色，尚未证明多设备独立状态和现有高亮能力复用。
- 多设备结构应在第二套资源装配前完成；正式高亮接入可等待目标 Renderer 与高亮插件资源确认，但未完成前 R-017 不得关闭。

### R-018：第三层独立播放控制与动态资源生命周期

**需求：**

将 3ds Max 导入的旋转/位移动画、环节内部管道流动和粒子特效统一登记到独立播放控制器。设备四态只改变状态视觉，不得隐式播放或停止动态效果。后续优先预留通过点击显式登记模型进行本地播放和停止，当前阶段不要求新增父页面到 Unity 的完整播放控制协议。

**边界：**

- 不在状态热路径扫描 Animator（动画状态机）、Animation（动画）、ParticleSystem（粒子系统）或 Renderer。
- 每个动态目标必须有稳定 `dynamicTargetId`；可点击目标必须另有稳定交互目标 ID、明确碰撞体和所属 `processDetailId`。
- 正常、告警、故障、离线及状态清除均不改变播放许可，状态投影代码不得调用播放控制器。
- 模型点击只在目标关键环节已稳定激活时生效；不根据对象名称、层级路径或坐标推断播放对象。
- 重复播放、重复停止和重复点击保持幂等；切换、返回、失败和释放必须停止并清理动态对象及交互监听。
- 保留内部 `setProcessDetailPlayback` 能力用于测试或未来扩展，但当前不把外层播放命令作为 R-018 完成前置。

**验收要求：**

1. 正常、告警、故障、离线及状态清除只改变视觉，不改变动画、粒子或管道播放状态。
2. 独立播放和停止命令幂等，不重复创建控制器、材质、粒子实例或协程。
3. 若采用模型点击，只有显式登记且属于当前活动环节的碰撞体可触发播放控制，普通设备选择与相机交互不受影响。
4. 切换、返回和释放后没有残留动画、粒子、材质属性块、碰撞监听或播放许可。
5. 自测页不得再以 `normal` 模拟播放、以 `fault` 模拟停止；设备状态测试和动态播放测试必须分离。
6. R-016 起第三层不产生旧的其余模型半透明状态；R-021 完成静态引用审计并删除无有效引用的旧第三层专用代码。

**当前实施与纠偏记录（2026-08-31）：**

- Unity 内部已提供独立播放许可，设备四态更新只改变视觉；幂等播放、停止和状态不干扰播放的编辑模式测试已建立。
- 发布自测页已删除 `normal/fault` 状态模拟播放按钮、状态消息和结果文案，改为在关键环节稳定态显示受控“播放/停止”按钮；手测同时验收三层视图链路和独立播放命令。
- 新增播放与四态解耦发布契约测试，并同步更新既有燃气发布契约；前端完整单元回归和生产构建通过。
- 模型点击方案尚未冻结具体交互对象；待模型 Collider 和稳定交互目标映射确认后实施，当前不阻塞页面按钮和三层视图链路验收。

### R-019：五页面独立状态接入与场景投影

**需求：**

支持五个独立浏览器标签页或父页面实例各自接收外部平台设备状态，并将状态投影到各自的第一层沙盘、第二层壳体与整套内部设备，或当前第三层关键环节 Unity 实例。

**边界：**

- 每个页面实例拥有独立状态缓存、页面会话、一个 Unity 桥接、一个 `VisualizationRuntimeHost` 和场景视觉状态；本任务不要求在单个页面实例内并存多个 Unity WebGL 实例。
- 不要求平台方改造为共享 WebSocket 连接。
- 一个页面的状态、场景切换、释放和错误不能修改其他页面。
- 不把页面之间的缓存共享作为本次必要条件。

**验收要求：**

1. 五个页面可以同时打开并分别显示不同场景。
2. 一个页面收到异常时，其他页面不会误变色或误停流。
3. 每个页面只向当前 Unity 实例投影当前场景目标。
4. Unity 场景尚未就绪时，状态不会丢失，加载完成后能重放最新快照。
5. 页面关闭或释放后，本页监听器、状态缓存、队列和 Unity 资源全部停止。
6. 五页面分别重连时不会产生重复状态覆盖或旧会话回写。

### R-020：五实例性能、内存与浏览器稳定性

**需求：**

在目标浏览器和目标设备上验证五个页面同时运行的内存、显存、帧率、加载和图形上下文稳定性。

**边界：**

- 不以资源本地化或浏览器下载缓存代替运行时内存测试。
- 不以单页面测试结果推断五页面可用。
- 不通过无条件增大 WebGL 内存上限掩盖资源和渲染问题。

**验收要求：**

1. 记录单沙盘、单第二层壳体、单第二层整套内部设备、单第三层关键环节和五实例同时运行的内存峰值。
2. 记录首帧、场景切换、设备加载和返回耗时。
3. 记录五实例同时收到异常状态时的状态更新耗时和帧率。
4. 页面隐藏后能暂停或降低非关键渲染和拓扑重绘。
5. 连续下钻、返回、切换和状态更新后没有持续内存增长。
6. 浏览器没有出现 WebGL 图形上下文丢失、黑屏或实例互相影响。
7. 记录不同质量档位下的性能差异，并冻结正式默认档位。
8. 沙盘和关键环节模式下拓扑输入、布局和重绘保持停用；切回厂区时复用原画布恢复，不产生重复监听器或缓存。

6. 旧有场景切换、厂区拓扑联动、第二层加载和设备状态回归不退化；历史关键环节过滤拓扑不再作为新第三层显示要求。
7. R-016 起第三层代码路径不再调用旧半透明、全量显隐、包围盒聚焦和全场景管道停控；R-021 完成静态引用审计，删除不再被历史二维兼容使用的旧第三层专用代码，并记录保留代码及其唯一兼容用途。
8. 沙盘与关键环节均为全屏三维，厂区为三维与拓扑并存；模式切换的布局、唯一画布保活、拓扑停用/恢复、直接切换和失败回滚测试全部通过。
9. 第三层设备四态与播放状态完全解耦；正式测试和自测页面均不再以正常或故障状态模拟播放与停止，自测页使用独立受控播放命令。
10. 发布目录、回滚版本、浏览器限制、硬件限制和已知问题均有说明。
11. 遗留问题必须拆成后续任务，不能留在“已完成”任务的隐含范围内。

## 五、执行期间的防跑偏检查

每次开始一个任务前，先回答以下问题并记录在任务备注中：

1. 本任务修改的是哪一层：沙盘、第二层壳体、第二层整套内部设备、第三层关键环节、状态层还是发布层？
2. 本任务是否引入了新的业务 ID？如果引入，是否同步更新绑定表和清单校验？
3. 本任务是否改变了外部状态协议？如果改变，是否确实属于本计划范围？
4. 本任务是否把资源加载、视觉效果和业务影响关系耦合在一起？如果是，应重新拆分。
5. 本任务是否增加了每帧遍历、材质复制、粒子对象、协程或无限缓存？如果是，必须先说明容量和释放路径。
6. 本任务是否改变厂房从整体控制到局部控制的范围？如果是，必须新增任务，不得直接扩大 R-012。
7. 本任务是否把五个页面改造成共享连接或共享缓存？这不是当前方案的必要条件，必须单独评审。
8. 本任务是否依赖美术尚未确认的模型结构、UV 或材质属性？如果是，状态标记为“待外部资料”。
9. 本任务是否有可重复的验收步骤和证据位置？没有则不得标记为已完成。
10. 本任务是否把关键环节数量写死为三个，或假定所有场景数量相同？如果是，必须改成场景级可变列表。
11. 本任务是否仍通过凸显第二层单个模型并隐藏其他模型实现第三层？如果是，已偏离当前方案。
12. 本任务是否让设备四态隐式改变了关键环节管道、动画或粒子的播放状态？如果是，已违反独立控制基线。
13. R-016 起是否仍调用旧关键环节其余模型半透明、全量显隐、包围盒聚焦或全场景管道停控？如果是，必须阻断验收。
14. R-021 是否完成旧第三层专用代码的静态引用审计，并区分删除项与历史二维兼容保留项？未完成则不得封板。
15. 沙盘或关键环节是否仍显示、激活或重绘拓扑？如果是，已偏离当前三种视图模式。
16. 厂区是否同时保留三维画面和合法业务拓扑？如果任一被无故隐藏，必须阻断验收。
17. 第三层是否通过条件卸载销毁拓扑画布、停用整个第二层业务根节点或在拓扑暂停前显示模型并移动相机？如果是，必须归入 R-016 纠偏。
18. 运行时是否写死燃气场景、燃气轮机、单一状态节点或单一动态目标？如果是，R-015、R-017 不得完成。
