# 测试包与正式包输出标准

**生效日期：** 2026-08-15

**适用范围：** 后续全部本地测试包、合作方联调包和正式发布包。

**依据：** 0813燃气联动包的最终视觉交互效果、合作方核查反馈、双方“各自独立服务并由平台通过内嵌框架加载”的会议结论。

> **2026-08-15 最新协议修正：** 平台不向我方注入设备编号或绑定映射。合作方包必须直接携带或只读加载我方不可变结构清单；平台读取 `nodeId` 并在平台内部绑定真实设备。任务-056的本地迁移已完成，旧设备编号注入包仍不得标记为符合最新联调协议。

## 一、不可回退基线

后续包必须先完整继承0813燃气联动包已经确认的能力，再叠加节点状态和部署能力：

1. 燃气总览固定为23个节点、22条连线；三个关键环节固定为16/13、13/6、15/10，并由总览过滤派生。
2. 子图复用总览层级、坐标、`nodeId`、节点、连线和三维映射，不复制逻辑节点定义。
3. 拓扑保持紧凑图标、框下小字、直线优先且冲突时最少绕行、缩放平移、原生全屏和单画布复用。
4. 已登记的三个二维节点支持三维聚焦描边；空白点击清除二维选中和三维交互描边；返回总览必须在三维成功后恢复完整二维总图。
5. 一页只能有一个Unity实例和一个拓扑画布。合作方交付入口不得包含内部测试按钮、测试状态或自测页面。
6. 页面启动、Unity 握手和首个稳定视图提交前必须使用覆盖三维与拓扑区域的不透明整区遮罩，完全挡住 Unity 内部加载画面；遮罩只显示等待指示器，不显示伪造的百分比、进度文字或进度条，稳定视图提交后自动解除。

## 二、三类包

| 包类型 | 标识 | 用途 | 本机地址 | 自测页 | 安全传输 |
| --- | --- | --- | --- | --- | --- |
| 本地测试包 | `local-test` | 开发与自动回归 | 允许 | 可显式启用 | 可使用HTTP（超文本传输协议） |
| 合作方联调包 | `partner-integration` | 双方独立服务联调 | 禁止 | 禁止 | 内网可使用HTTP，目标环境按双方安全要求 |
| 正式包 | `standalone-formal` | 正式独立服务部署 | 禁止 | 禁止 | 与联调包相同，按实际部署环境决定 HTTP 或 HTTPS；固定来源模式可额外启用 HTTPS 门禁 |

包类型必须写入 `release-manifest.json`（发布摘要），禁止根据目录名、端口或是否存在自测页猜测。

## 三、清单与节点协议

1. 每张有业务节点的源拓扑，其全部节点必须声明 `doubleClickBehavior: "emit-node"`。`none` 只保留为旧协议解析和防御测试类型。
2. 非业务说明、层级标题和分组应使用 `layers`、标题或图例表达，不得创建伪业务节点。
3. 包内 `scene-topology-manifest.json` 是壳直接运行的唯一结构清单；不得包含 `deviceId`、`deviceMappings`、`platformBindingCount` 或绑定修订字段。
4. `nodeId` 必须在同一 `resourceKey` 内全局唯一；过滤视图复用源节点编号，不得为同一逻辑节点重复定义编号。
5. 平台只读取结构清单中的 `nodeId`，在平台内部绑定真实设备编号；绑定结果不得回写或改写我方清单。
6. 全部节点可双击上报不等于全部节点都有三维目标。燃气当前只允许三个已登记 `sceneNodeId` 派生三维状态和聚焦，其余节点只更新二维状态并上报 `nodeId`。
7. 发布摘要必须声明 `node-events`、`node-states` 和 `node-scene-mapping` 能力；不得再声明消费平台设备映射。未交付的三维路径和其余八场景内容可继续明确排除。

## 四、独立服务地址

合作方联调包和正式包支持两种来源模式。当前受控内网阶段默认的“运行时同源模式”不要求构建时知道服务器 IP，也不要求预先登记平台实际来源；服务启动后，浏览器使用当前实际访问地址派生 Unity 与结构清单地址。固定来源模式保留给后续外网部署或安全加固；两类包的独立访问、平台 iframe 嵌入和通信规则相同。

| 配置 | 含义 | 禁止事项 |
| --- | --- | --- |
| 监听地址 | 我方服务绑定的网络接口，例如 `0.0.0.0` | 不得当作浏览器地址 |
| 监听端口 | 我方服务实际监听端口 | 不得隐式决定生产域名 |
| 浏览器公开来源 | 固定模式下的平台实际加载来源；运行时模式下由当前页面 `window.location.origin`（窗口来源）派生 | 不得把 `0.0.0.0` 当浏览器来源 |
| 平台父页面来源 | 固定模式下的已登记来源；运行时模式下由平台写入 iframe 查询参数 `parentOrigin` | 不能把监听地址或任意路径当来源 |
| Unity父页面来源 | 始终为我方壳当前来源，运行时模式由当前页面来源派生 | 不得从平台父源字段复制 |
| Unity入口地址 | 运行时模式固定为当前服务下的 `/unity/index.html`；固定模式为受控完整地址 | 不得修改 Unity 压缩资源 |
| 结构清单地址 | 运行时模式固定为当前服务下的 `/scene-topology-manifest.json`；固定模式同源派生 | 不得指向平台接口 |

`0.0.0.0` 只表示服务监听所有网卡，不是浏览器访问地址。合作方联调包可监听 `0.0.0.0`，启动后直接用该服务在局域网中的实际地址访问；服务换 IP 或端口不需要重新构建。运行时模式直接访问不依赖平台，只有需要双向 `postMessage`（跨窗口消息）通信时才要求平台在 iframe 地址中追加 `parentOrigin`、`instanceId` 和 `protocolVersion`。其中 `parentOrigin` 是本次嵌入的实际父页面来源，不是需要在构建时写死的部署配置；消息建立后仍以浏览器实际 `event.origin`（事件来源）和 `event.source`（事件窗口）校验为准。

当前正式包与合作方联调包均按上述受控内网策略输出：未提供固定平台来源不得阻断打包、启动或独立访问。内容安全策略可由启动环境通过 `POWER_ALLOWED_FRAME_ANCESTORS`（允许嵌入祖先来源）收紧；未设置时仅允许受控内网联调使用放宽策略。后续进入外网或需要安全加固时，必须切换固定来源模式，并补齐精确来源、HTTPS 和嵌入祖先限制。

平台服务与我方可视化服务各自独立运行。平台只配置内嵌框架地址和全屏权限，不导入后修改我方摘要脚本、样式、Unity加载脚本或Unity压缩资源。当前燃气包的结构清单固定随包同源提供，响应必须使用 `Cache-Control: no-cache`、不依赖浏览器Cookie，并在十秒内返回；其他场景以后若改用我方独立静态地址，必须另行建立来源所有权、版本和摘要一致性门禁。

### 独立服务根入口

1. 合作方联调包和正式包的平台内嵌地址应携带 `parentOrigin`（平台父来源）、`instanceId`（实例标识）和 `protocolVersion`（协议版本）三个查询参数；直接打开服务地址时可省略，页面仍可独立显示。
2. 根入口只保留上述参数并在同一内嵌窗口中进入 `/shell/embed`（协议壳入口）；不得再创建一层我方宿主内嵌框架。`release-manifest.json`（发布摘要）必须将该入口模式标记为 `platform-direct-shell-redirect`。
3. 嵌入平台时，协议壳的直接父窗口必须是平台，消息 `event.origin`（事件来源）和 `event.source`（事件窗口）仍需匹配；脱离平台直接访问时不创建外层通信桥，不影响页面和三维资源运行。
4. 平台必须先注册消息监听器，再设置内嵌地址；收到 `system.ready`（系统就绪）后使用当前会话标识发送 `system.init`（系统初始化）。交付包根页不得代替平台自动发送初始化命令。
5. 本地测试包可继续使用同源根宿主自动初始化，但 `release-manifest.json`（发布摘要）必须将入口模式标记为 `local-bootstrap-host`，不得与交付包混用。

## 五、发布目录

```text
<唯一发布标识>/
├─ index.html
├─ shell/
├─ unity/
│  └─ webgl-protocol-capabilities.json
├─ scene-topology-manifest.json       # 唯一结构清单，三类包均必须存在
├─ server.mjs
├─ README.md
├─ release-manifest.json
├─ artifact-integrity.json
└─ self-test.html                     # 仅本地测试包显式启用时允许存在
```

1. 发布目录名必须是唯一发布标识；存在同名目录时构建失败，禁止覆盖历史包。
2. `release-manifest.json` 必须记录包类型、部署模式、禁止产物补丁、来源配置、结构清单版本、Unity发布标识、节点和连线数量、可上报节点数量、已含能力和排除能力。
3. `artifact-integrity.json`（产物完整性清单）必须记录除自身外全部文件的字节数和安全哈希算法（SHA-256）摘要，Unity大型资源采用流式计算，不得整体读入内存。
4. 三类包都必须包含不带设备字段的结构清单；合作方联调包和正式包不得依赖平台注入版运行时清单。
5. `README.md` 只保留联调启动、停止、公开入口、内嵌方式、全屏权限、成功判据、清单责任、能力边界和常见启动问题；不得写内部自测入口、测试证据、研发进度或本机临时地址。

## 六、自动失败条件

出现以下任一情况必须停止构建或部署，不得生成“可交付”结论：

1. 任一业务源节点不是 `emit-node`。
2. 结构清单含 `deviceId`、`deviceMappings`、`platformBindingCount` 或绑定修订字段。
3. 发布摘要缺少节点事件、节点状态或节点到三维映射能力，或错误声明消费平台设备映射。
4. 合作方联调包或正式包包含自测页、内部按钮、合成数据或测试标识。
5. 合作方联调包或正式包的文本产物含 `127.0.0.1`、`localhost` 或浏览器地址中的 `0.0.0.0`。
6. 固定来源模式缺少浏览器公开来源、平台父源、Unity父源、Unity入口或结构清单地址。
7. 固定来源模式的正式包任一公开地址未使用HTTPS；运行时同源模式按实际部署网络策略执行。
8. 固定来源模式的内容安全策略未精确允许实际平台父源、Unity来源或清单来源；运行时局域网模式必须保留由部署环境通过 `POWER_ALLOWED_FRAME_ANCESTORS` 收紧的能力，但当前内网阶段不以固定平台来源或精确嵌入祖先作为打包、启动或独立访问的失败条件。
9. 发布摘要与实际目录、自测页、Unity标识、清单版本或节点数量不一致。
10. 合作方联调包或正式包依赖平台注入版运行时清单，或携带合成设备编号和绑定映射。
11. Unity协议能力文件缺失、发布标识不一致、结构版本或必需命令不完整。
12. 构建后任一文件集合、字节数或安全哈希算法摘要变化。
13. 目标发布目录或暂存目录已存在。
14. 合作方联调包或正式包的根入口再嵌套一层我方宿主，代替平台发送初始化命令，或未完整保留三个协议查询参数。
15. Unity 构建入口未在 `BuildPipeline.BuildPlayer` 前将 `PlayerSettings.insecureHttpOption` 设为 `InsecureHttpOption.AlwaysAllowed`，或构建结束后未恢复编辑器原值；局域网 HTTP 打开后出现 `Insecure connection not allowed`、`Non-secure network connections disabled` 或场景资源未加载。

## 七、执行命令

`npm run build` 只执行通用前端生产构建，不生成发布摘要、结构清单、Unity资源和产物完整性清单；其输出不得直接交付平台，也不得改名冒充联调包或正式包。燃气可交付目录必须由以下专用发布器生成并通过发布产物复核。

本地测试包可使用默认回环配置；合作方联调包的监听端口固定为 `5575`，省略 `--port` 时发布器也会自动使用该端口，显式传入其他端口必须停止构建。合作方联调包和正式包都可以省略全部来源参数启用运行时同源模式，也可以全部提供以启用固定来源模式：

```powershell
node scripts/build-gas-power-smoke-release.mjs `
  --package-type partner-integration `
  --release-id <唯一发布标识> `
  --unity-release-id <Unity发布标识> `
  --listen-host 0.0.0.0 `
  --port 5575 `
  --include-self-test false
```

上面命令生成运行时同源的合作方联调包；若采用固定来源模式，再同时传入 `--public-origin`、`--platform-parent-origin`、`--unity-parent-origin` 和 `--unity-entry-url`。`--manifest-url` 通常不需要传入。

`--manifest-url`（结构清单地址）通常省略；如为部署复核而显式填写，必须严格等于 `<我方公开来源>/scene-topology-manifest.json`。

构建完成和部署完成后都必须执行只读复核：

```powershell
npm run validate:release-artifact -- --root <发布目录>
```

只有报告为 `valid`、问题数为0，且合作方实际平台完成结构清单读取、平台内部节点绑定、节点双击、节点状态快照、二维/三维联动和全屏验收后，才能把合作方联调或正式发布标记为完成。
