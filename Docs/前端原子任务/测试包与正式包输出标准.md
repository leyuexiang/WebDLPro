# 测试包与正式包输出标准

本文只描述当前可执行的构建、验证和交付规则，不保存历史包目录、阶段性数量和完成比例。发布结果以最终产物为准。

## 一、包类型

| 包类型 | 用途 | 必须包含 | 禁止包含 |
| --- | --- | --- | --- |
| `local-test` | 本地浏览器回归 | 自测页、结构清单、Unity 资源、诊断入口 | 未验证的外部来源配置 |
| `partner-integration` | 合作方联调 | 结构清单、Unity 资源、公开协议入口 | 自测页、网页播放/停止控件、平台设备编号 |
| `standalone-formal` | 正式部署 | 与联调包相同的运行资源和协议契约 | 调试入口、测试夹具、可变外部清单地址 |

## 二、不可回退基线

1. `scene-topology-manifest.json` 是我方结构事实源；平台只能读取 `nodeId`，真实设备编号由平台内部维护。
2. 业务场景目录当前为十三项；`overview` 通过 `overviewSceneId: "overview"` 独立声明，不写入业务场景数组。
3. 当前公开动作由生成器产生，发布摘要 `workflowActions` 必须逐项镜像结构清单 `actions`；不可在文档中手写固定动作数量。
4. `action.scene.overview` 是唯一全局总览动作标识。仅导航场景使用 `unityAction.type: "none"`，不得虚构流程步骤、第三层或三维节点。
5. 第三层动作必须同时具备 `processDetailId`、资源标识、相机位、状态节点和 `topologyDataContextId`，并有场景反向引用。
6. 拓扑版本、场景映射、动作、资源和协议版本必须在同一发布事务中生成；不得修改打包后的清单或 Unity 压缩资源。

## 三、构建来源

发布必须从源生成器执行，不得复制历史发布目录：

```powershell
cd power-data-web
node scripts/build-gas-power-smoke-release.mjs --release-id <不可变发布标识> --package-type <local-test|partner-integration|standalone-formal>
```

具体参数以当前脚本帮助和 `package.json` 为准。普通 `npm run build` 只验证前端，不构成可交付包。

## 四、双层门禁

先执行结构清单校验，再执行最终产物门禁：

```powershell
npm run validate:manifest -- --manifest <工作区内清单.json> --report <工作区内报告.json>
npm run validate:release-artifact -- --root <新发布目录>
```

绝对契约必须独立验证当前生成器声明的公开动作、场景边界和第三层字段；相对校验必须比较结构清单、发布摘要、场景反向动作、关键环节目录和三维映射。两份清单同时漏项也必须失败。

## 五、自测与联调

1. 本地自测按钮必须通过公开 `workflow.trigger`（流程触发）和稳定 `actionId` 执行，不能用内部 `view.open`（视图打开）捷径替代。
2. 逐项验证场景进入、默认拓扑、二维节点选择、三维聚焦、三维反选、完整设备状态、镜头复位、场景复位、第三层进入/退出和释放。
3. 合作方联调必须额外确认：同源结构清单读取、平台内部节点绑定、双击事件、完整状态快照、二维/三维联动和全屏显示。
4. 未确认的节点、路线、四态资源或第三层能力必须明确标记为不支持或待确认，不得用占位数据发布。

## 六、最终产物检查

最终目录必须至少包含：

- `scene-topology-manifest.json`；
- `release-manifest.json`；
- `unity/` 及其能力元数据；
- `shell/`、公共拓扑资源和完整性摘要；
- 与包类型相符的自测和诊断边界。

检查结果必须为 `valid` 且问题数为零。发布目录必须新建，不覆盖历史目录；失败时只能修复源生成器后重新生成。

## 七、维护规则

发布记录、包路径、哈希和统计保存在发布系统或产物元数据中，不追加到本文。场景或动作契约变化时，必须同步更新生成器、门禁、正负向测试、协议规范和[十三场景当前配置基线](06-十一场景当前配置基线.md)。
