# Unity WebGL 场景资源依赖优化设计

## 背景与目标

燃煤、燃气和其他业务场景的场景资源包冷加载闭包包含同一个约 461.5 MiB 的 `scene-shared` 包。检查场景依赖来源后发现，八个业务场景引用 `ProcessDetailCatalog.asset`；该目录在编辑器版本中通过 `EditorPrefab` 保存关键环节预制体。`EditorPrefab` 只在 `UNITY_EDITOR` 条件下存在，但原构建器使用递归依赖扫描，把这些仅供编辑器回退加载的预制体及模型也计入播放器共享包。关键环节本已有独立资源包，可在用户进入关键环节时按需下载。

本变更的目标是让业务场景包只包含播放器场景实际需要的资源，并阻止一个场景的共享包把其他消费者的资源一并带入。场景动作、场景映射及目录协议保持不变。

## 设计

### 运行时依赖扫描

- 从场景资产开始，以显式栈遍历直接资源依赖；每个资源的一层依赖查询在一次构建中只执行一次。
- 到达 `ProcessDetailCatalog.asset` 时保留目录本身及其运行时元数据，但停止向下展开。其 `EditorPrefab` 引用只用于 Unity 编辑器中的直接加载；WebGL 关键环节资源由 `ProcessDetailBundles` 独立目录提供。
- 其他场景直接引用仍完整递归展开。若场景或其他预制体真实直接使用某个关键环节模型，该引用仍会保留。
- 内容摘要使用过滤后的运行时依赖集合，因此发布评审反映播放器实际下载资源。

### 共享资源分组

- 按每个资源的精确消费者场景集合分组。只有消费者集合完全相同的资源才进入同一个共享资源包。
- 单场景资源继续由对应场景包承载，不创建共享包。
- 共享包名由排序后的场景标识签名计算完整 SHA-256（安全哈希）得到，保证名称稳定、路径安全，并避免依赖资产数据库枚举顺序。
- 现有场景目录仍使用 schemaVersion 2（目录结构版本 2）。运行时加载器已经按目录声明递归下载包依赖，不需要协议或运行时目录结构升级。

## 质量属性

- 依赖图遍历采用集合去重，时间复杂度与本次可达依赖边数成正比；一层 AssetDatabase 查询在所有场景之间共享缓存。
- 运行时场景包持有的资源租约仍由现有加载器管理。关键环节包仍由既有关键环节加载器在进入详情时取得。
- 本变更不自动修改 FBX（Filmbox 三维交换格式）源文件或模型导入质量参数，避免未经过画面回归的几何失真。

## 验证方案

1. 编辑器单元测试验证：相同消费者集合会合并、不同集合会隔离、单场景资产不会进入共享组、分组和包名与输入顺序无关。
2. 真实资产测试验证：主场景依赖仍包含关键环节目录资产，但不会只因目录的编辑器预制体字段而包含这些预制体；场景本身的直接引用不被误删。
3. 使用新 `unityReleaseId` 构建 Unity WebGL 播放器和全部场景/关键环节包，确认构建后目录的 `releaseId` 与播放器 `buildId` 一致。
4. 比较新旧各场景冷加载闭包的传输体积。重点确认燃煤、燃气不再依赖包含所有关键环节模型的大共享包。
5. 在 Chrome 中冷缓存测试 `workflow.trigger`：总览、燃煤总览、燃气总览、燃煤汽轮机详情、燃气轮机详情和风电场景；再测燃煤/燃气/风电连续切换。

## 交付边界

公开动作、业务场景和关键环节契约保持不变；本次只改变场景资源依赖扫描和共享包分组。旧发布目录保持不可变；新构建需使用新的唯一发布标识。
