新增 `power-data-web/scripts/validate-scene-topology-manifest.mjs`（场景拓扑清单校验命令）。它通过 Vite（前端构建工具）的服务端模块加载器复用运行时同一份 `validateSceneTopologyManifest`（场景拓扑清单校验器），不会复制或漂移校验规则。

```powershell
cd F:\WorkSpace\WebDLPro\power-data-web
npm run validate:manifest -- --manifest <工作区内正式清单.json> --report <工作区内既有目录/契约报告.json>
npm run build:release -- --manifest <工作区内正式清单.json> --report <工作区内既有目录/契约报告.json>
```

`validate:manifest`（清单校验）输出 UTF-8（统一码转换格式）JSON（JavaScript 对象表示法）报告，且只记录工作区相对路径、稳定问题代码和脱敏中文摘要；不输出原始清单、绝对路径或异常堆栈。`build:release`（发布构建）必须先执行同一校验，只有报告有效时才运行类型检查和生产构建。

| 结果 | 退出码 | 发布行为 |
| --- | ---: | --- |
| 清单有效 | 0 | 生成有效报告；`build:release`继续执行生产构建 |
| 清单契约无效 | 1 | 生成问题报告；`build:release`在构建前停止 |
| 参数、路径、读取、解析、报告写入或校验器加载失败 | 2 | 停止；不把未确认清单交给构建 |

命令只接受工作区内的相对路径。报告父目录必须由发布流水线预先创建；命令不会创建或覆盖工作区外文件。

## 契约覆盖范围

复用的校验器会阻断下列发布缺口：

1. 九个固定场景缺失、重复或默认拓扑跨场景。
2. 场景、拓扑、动作、设备映射和 Unity 场景映射版本不一致。
3. 多拓扑归属错误、拓扑节点或连线的孤立引用、场景动作目标错误。
4. 动作引用未登记的三维节点、路径或流程步骤。
5. 双击设备节点缺少 `deviceId`（设备标识）、设备映射遗漏二维节点、二维和三维节点映射不一致。
6. 三维节点未在所属 Unity 场景映射中登记，以及同一三维节点由多个设备状态源驱动。
