# 场景拓扑动作映射规范

**适用范围：** 九个 Unity 业务场景、全部二维拓扑、外部菜单和子项动作。

**目标：** 让外部业务动作、Unity 场景操作、拓扑切换和节点标识通过稳定配置关联，禁止在组件中硬编码或根据名称猜测。

> **2026-08-15 最新会议修正：** 平台不向我方注入真实设备编号。平台只读取 `nodeId`，在自身系统内维护 `nodeId → 真实设备编号`。我方双击事件、状态快照和三维反向选择均以 `nodeId` 为关联键；本文旧版“平台运行时设备映射”段落只作为历史实现，不得作为新包契约。

---

## 一、核心原则

1. 外部父页面只发送 `sceneId`、`topologyId` 或 `actionId`，不发送 Unity 方法名、场景文件路径、模型名称和层级路径。
2. 当前子应用根据受版本控制的动作定义解析目标场景、目标拓扑和 Unity 命令。
3. 我方场景、拓扑、动作和 Unity 映射必须随同一个结构清单版本原子发布；平台只读取节点编号并在平台内部绑定真实设备，不改变或注入我方清单。
4. 未登记、版本不一致或存在孤立引用时禁止发布，不能在运行时按中文标题或相似字符串推断。
5. 同一动作的场景与拓扑变化属于一个事务，只允许一起成功提交或一起失败。

---

## 二、标识职责

| 标识 | 事实来源 | 用途 |
| --- | --- | --- |
| `sceneId` | 九场景固定目录 | 当前 Unity 业务场景 |
| `topologyId` | 拓扑交付清单 | 当前二维拓扑 |
| `actionId` | 外部前端与可视化团队共同确认 | 父页面菜单、按钮或子项动作 |
| `nodeId` | 单套拓扑定义 | 二维节点选择与绘制 |
| `deviceId` | 平台内部设备主数据 | 只在平台内部与 `nodeId` 绑定，不进入我方清单、消息和状态缓存 |
| `sceneNodeId` | Unity 场景映射表 | 三维聚焦、状态和对象选择 |
| `processId`、`stepId`、`routeId` | Unity 场景流程配置 | 受控流程和路径命令 |

`nodeId`、`deviceId` 和 `sceneNodeId` 不能默认视为同一个值。`nodeId` 是我方与平台共同使用的逻辑关联键，`deviceId` 只存在于平台内部，`sceneNodeId` 由我方静态清单显式登记。壳根据 `nodeId` 命中的节点读取 `sceneNodeId`，禁止根据名称、位置或数组顺序推导。

各类节点的字符格式、业务分段、唯一性范围、Unity 对象显示名、历史标识冻结和改名发布规则，统一见[场景模型节点与拓扑节点命名规范](场景模型节点与拓扑节点命名规范.md)。

## 四、配置模型

### 4.1 场景定义

```ts
/** 场景定义只登记稳定业务标识和受控资源键，不暴露文件系统路径。 */
interface SceneDefinition {
  sceneId: SceneId
  title: string
  unitySceneKey: string
  defaultTopologyId: string
  topologyIds: readonly string[]
  supportedActionIds: readonly string[]
  sceneMappingVersion: string
  resourceVersion: string
  switchStrategy: 'unload-first' | 'preload-then-unload'
}
```

`preload-then-unload` 仅允许内存压测通过的轻量场景使用；默认必须为 `unload-first`。

### 4.2 拓扑定义

```ts
/** 一套拓扑只能属于一个场景，但同一设备可出现在该场景的多套拓扑中。 */
interface TopologyDefinition {
  topologyId: string
  sceneId: SceneId
  title: string
  configVersion: string
  nodes: readonly TopologyNodeDefinition[]
  edges: readonly TopologyEdgeDefinition[]
}

/** 真实设备编号不属于我方清单；节点只登记逻辑编号和可选三维映射。 */
interface TopologyNodeDefinition {
  nodeId: string
  title: string
  sceneNodeId?: string
  deviceType?: string
  iconKey: string
  x: number
  y: number
  deviceStatus: 'normal' | 'alarm' | 'fault' | 'offline'
  doubleClickBehavior: 'emit-node' | 'none'
}
```

结构清单必须声明节点是否允许节点双击上报，但不得出现 `deviceId`。新的业务源拓扑节点必须使用 `doubleClickBehavior: 'emit-node'`；平台只读取这些节点的 `nodeId`，不得新增或修改该行为。概念分组、层级标题和非业务说明使用元数据表达，不得作为伪业务节点进入发布清单；`none` 只保留为兼容解析和防御测试类型。

### 4.3 动作定义

```ts
/**
 * actionId 是父页面唯一需要理解的动作标识。
 * targetSceneId、targetTopologyId 和 unityAction 由发布清单控制。
 */
interface ActionDefinition {
  actionId: string
  title: string
  targetSceneId: SceneId
  targetTopologyId: string
  allowedParameters: readonly string[]
  unityAction: UnityActionDefinition
  failurePolicy: 'keep-current-context' | 'commit-view-with-warning'
}

type UnityActionDefinition =
  | { type: 'none' }
  | {
      type: 'enterProcessStep'
      processId: string
      stepId: string
      defaultUnitId?: string
      isolate: boolean
    }
  | {
      type: 'focusNode'
      sceneNodeId: string
      isolate: boolean
    }
  | { type: 'resetScene' }
  | {
      type: 'setRouteFlow'
      routeId: string
      enabled: boolean
    }
```

`commit-view-with-warning` 只适用于不影响场景正确性的非关键展示动作。流程步骤、场景加载和关键聚焦默认使用 `keep-current-context`。

### 4.4 平台内部设备绑定（不进入我方协议）

```ts
/**
 * 平台根据自身绑定面板读取 nodeId 并生成内部关系；该关系不进入我方清单。
 * 一个真实设备可以由平台绑定多个 nodeId；我方只接收和处理 nodeId。
 */
interface DeviceMappingDefinition {
  deviceId: string
  nodeIds: readonly string[]
}
```

以上类型仅用于解释平台内部数据，不是我方接口类型，不得打包、不跨窗口传递、不进入前端状态。平台绑定时只需保存 `resourceKey + nodeId + deviceId` 关系；我方不校验平台设备编号格式，也不感知平台绑定数量。

## 六、解析与执行规则

### 6.1 `view.open`

1. 校验 `sceneId` 存在。
2. 校验 `topologyId` 属于该场景。
3. 有 `actionId` 时校验动作目标与场景、拓扑一致。
4. 创建新的 `transitionId`。
5. 预解析目标拓扑。
6. 场景不同则切换 Unity 场景；场景相同则复用当前场景。
7. 执行可选 Unity 动作。
8. 激活目标拓扑并提交上下文。

### 6.2 `workflow.trigger`

1. 按 `actionId` 获取动作定义。
2. 拒绝未在 `allowedParameters` 中声明的参数。
3. 将允许参数与动作默认值合并，外部参数不能覆盖 `processId`、`stepId`、`sceneNodeId` 和 `routeId`。
4. 按目标场景是否变化决定是否发送 `switchScene`。
5. 执行映射后的 Unity 动作。
6. 激活映射拓扑。
7. 成功后递增 `contextRevision`。

### 6.3 拓扑单击

1. 立即更新当前 `nodeId` 选择和路径高亮。
2. 有 `sceneNodeId` 时发送受控 `focusNode`。
3. 没有三维映射时只保留二维选择，不猜测模型。
4. 来源为 Unity 反向选择时不再次发送 `focusNode`。

### 6.4 拓扑双击

1. 复用单击后的选中结果。
2. `doubleClickBehavior` 必须为 `emit-node`。
3. `nodeId` 必须存在且来自当前结构清单。
4. 向父页面发送 `topology.node.dblclick`。
5. 不重复发送相同三维聚焦命令。

### 6.5 节点状态全量快照

1. 校验信封、会话、`sourceRevision`、四态枚举、带时区的国际标准时间、1至500项上限；同批重复 `nodeId` 防御性按最后一项生效。
2. `items` 表示当前 `resourceKey` 全部已上报节点的完整状态；每份合法快照直接整体替换旧状态表，不跨批次增量合并。`sourceRevision` 只用于诊断，禁止按其大小或 `statusUpdatedAt` 拒绝快照。
3. 壳有限保存最新一份完整快照，按 `nodeId` 更新当前二维拓扑。新快照未出现的旧状态覆盖必须清除；未知 `nodeId` 直接忽略且不回失败。
4. 二维快照替换和拓扑应用成功后，外层命令立即返回成功。
5. 切换场景或拓扑后必须从最新完整快照重新投影；平台不因切换重复推送。
6. 存在静态 `sceneNodeId` 映射的节点向对应三维目标同步 Unity 四态；三维不支持、超时、节点拒绝或部分失败只写固定容量内部诊断，不影响、延迟或重复外层成功回执。
7. Unity 恢复就绪或场景重新激活后，只补同步当前最新快照，禁止重放已被后续合法快照替换的旧批次。
8. 渲染器可比较新旧完整快照并局部更新差异节点，但这种性能优化不得被描述为协议语义上的增量合并。

## 七、发布校验规则

### 7.1 场景校验

- 九个固定 `sceneId` 必须齐全且唯一。
- 每个场景必须有 `unitySceneKey`、默认拓扑、拓扑清单、映射版本和资源版本。
- 默认拓扑必须属于当前场景。
- `supportedActionIds` 中每个动作必须存在且目标场景一致。

### 7.2 结构清单校验

- `topologyId` 全局唯一。
- 每个 `nodeId` 在同一 `resourceKey` 内全局唯一；过滤视图引用总图同一节点，不重复定义。
- 每条边的起终节点必须存在。
- 清单不得包含 `deviceId`、`deviceMappings`、`platformBindingCount` 或绑定修订字段。
- `doubleClickBehavior: 'emit-node'` 是新的业务节点双击许可；平台不得修改该字段。
- 可三维聚焦或状态联动节点必须有 `sceneNodeId`；没有三维映射的节点仍可参与二维状态。
- 每个 `nodeId` 最多声明一个 `sceneNodeId`；同一场景内一个 `sceneNodeId` 最多反向对应一个 `nodeId`。

### 7.3 动作校验

- `actionId` 全局唯一。
- 目标场景和目标拓扑必须存在且相互匹配。
- Unity 动作引用的流程、步骤、节点和路径必须存在于目标场景映射版本。
- 外部允许参数必须为稳定业务范围参数，禁止颜色、材质、脚本名和资源路径。
- 关键动作不得使用会在失败后提交错配视图的失败策略。

### 7.4 版本校验

以下结构版本必须作为我方一个发布事务提交：

- 场景拓扑清单版本。
- Unity 构建标识。
- Unity 场景映射版本。
- 拓扑配置版本。
- 动作映射版本。
- 可绑定节点和三维映射版本。

平台内部绑定不改变我方结构清单版本，也不提供我方可见的绑定修订。壳只加载并校验一份不可变结构清单；平台需要刷新绑定时自行刷新其业务数据，必要时由父页面重新初始化壳。

## 九、禁止项

1. 禁止用中文标题、数组顺序、图片名称或坐标邻近关系推断映射。
2. 禁止外部父页面直接下发 Unity 方法名和任意参数。
3. 禁止在 Vue 组件中用 `if (sceneId === ...)` 硬编码九场景流程。
4. 禁止一个动作分别更新场景和拓扑而不经过统一事务。
5. 禁止在原始拓扑、场景代码或组件条件分支中写入或等待 `deviceId`；双击直接发送清单中的 `nodeId`，平台内部设备绑定不得改变我方行为。
6. 禁止用 Unity 层级路径作为 `sceneNodeId`。
7. 禁止跨版本混用拓扑、动作和 Unity 映射缓存。
8. 禁止为每套拓扑或每个场景创建隐藏内嵌框架、隐藏画布或常驻渲染实例。
