# 场景拓扑动作映射规范

## 一、核心原则

外部只发送稳定 `actionId` 或受控视图意图。子应用从版本化结构清单解析场景、视图模式、第二层拓扑或第三层关键环节，再执行单一原子事务。禁止让父页面传入 Unity 方法、场景文件、模型路径、材质或任意坐标。

## 二、标识职责

| 标识 | 用途 |
| --- | --- |
| `actionId` | 外部菜单和公开工作流入口 |
| `sceneId` | 目标业务场景 |
| `topologyId` | 第二层业务拓扑 |
| `processDetailId` | 第三层关键环节 |
| `topologyDataContextId` | 第三层独立二维数据上下文 |
| `nodeId` | 二维选择、状态和平台内部设备绑定键 |
| `sceneNodeId` | Unity 聚焦、状态和反向选择目标 |

平台内部 `deviceId` 不进入动作、结构清单、跨窗口消息或前端缓存。

## 三、动作结构

```ts
interface WorkflowActionDefinition {
  readonly actionId: string
  readonly title: string
  readonly targetSceneId: string
  readonly targetViewMode: 'overview' | 'business' | 'process-detail'
  readonly targetTopologyId?: string
  readonly processDetailId?: string
  readonly allowedParameters: readonly string[]
  readonly unityAction: Readonly<{ type: string }>
  readonly failurePolicy: 'keep-current-context'
  readonly configVersion: string
}
```

字段约束：

1. `overview` 视图不携带 `targetTopologyId` 或 `processDetailId`，Unity 动作为 `none`。
2. `business` 视图必须携带属于目标场景的 `targetTopologyId`，不得携带 `processDetailId`。
3. `process-detail` 视图必须携带 `processDetailId`，不得携带第二层 `targetTopologyId`。
4. 关键动作失败策略固定为保留当前稳定上下文。
5. 默认参数白名单为空；新增参数必须是可校验的稳定业务值。

## 四、第二层与第三层

第二层动作提交目标场景和默认拓扑。命名镜头按钮不属于公开工作流动作，只发送 `moveCameraToPose({ cameraPoseId })`，不改变流程、拓扑选择、第三层或设备状态。

第三层动作必须引用完整目录项：

- `sceneId`；
- `processId`；
- `stepId`；
- `processDetailId`；
- `resourceId`；
- `cameraPoseId`；
- `stateNodeId`；
- `topologyDataContextId`。

第三层拓扑上下文只解析到一份完整文件和该文件的显式 `penId → nodeId` 绑定，不进入第二层组合筛选。

## 五、双向一致性

1. `actions` 中指向业务场景的动作必须出现在该场景的 `supportedActionIds`。
2. 场景 `supportedActionIds` 中的每个标识必须存在且目标场景一致。
3. `release-manifest.json.workflowActions` 必须逐项镜像结构清单公开动作。
4. 结构清单与发布摘要同时漏项时，绝对契约仍必须阻断发布。
5. 第三层动作、第三层目录、Unity 资源目录和二维上下文必须一一对应。

## 六、导航场景边界

仅开放导航的场景使用 `unityAction.type: 'none'`，三维节点、流程步骤、路线和第三层目录保持空集合。不得为了让合作方菜单可见而伪造 `enterProcessStep` 或 `enterProcessDetail` 能力。

## 七、事务顺序

1. 校验动作、目标和当前结构版本。
2. 建立递增事务编号并取消或取代旧事务。
3. 切换 Unity 场景，等待成功回执。
4. 执行动作要求的复位或第三层准备与提交。
5. 提交二维拓扑和稳定上下文。
6. 发送命令结果与视图变化事件。

迟到回执、旧场景事件、版本不匹配、能力未声明或超时均不得覆盖最后稳定上下文。

## 八、验证

每次动作集合变化必须覆盖：

- 目标场景、视图、拓扑或关键环节字段；
- 场景反向索引；
- 发布摘要镜像；
- 仅导航场景无虚假能力；
- 第三层固定字段和二维上下文；
- 两份清单同时漏项的负向门禁；
- 本地自测使用 `workflow.trigger`（流程触发），不使用内部视图捷径。

当前动作和第三层集合以 `power-data-web/scripts/build-gas-power-smoke-release.mjs` 与 `power-data-web/scripts/release-artifact-contract.mjs` 为准，快速摘要见[十一场景当前配置基线](06-十一场景当前配置基线.md)。
