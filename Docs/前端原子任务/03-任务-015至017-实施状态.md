3. `BusinessSceneControllerBase`默认拒绝未声明能力，也拒绝“能力位已声明但派生类未覆写”的虚假实现，返回 `capability-not-implemented`，不会伪造成功。
4. `UnavailableBusinessSceneController`让八个空场景显式返回内容未交付或能力不支持，并提供无资源副作用的幂等释放。
5. `BusinessSceneControllerRegistry`先解析场景内接口组件，再调用按 `sceneId` 登记的适配工厂；燃气适配器只通过实际 `PowerPlantProcessController` 组件解析，不从场景文件名或对象名称推断。
6. `UnityIframeBridgeManager`只持有 `IBusinessSceneController` 和 `MultiSceneCoordinator`，源码与测试均证明其不直接依赖燃气控制器。

燃气适配器的四态视觉更新和路径流动仍显式不支持：正式设备四态映射尚未提供，且用户已删除燃气动态 `setRouteFlow`。这些属于任务-021和任务-040的正式映射范围，不影响任务-016的“显式能力缺失、禁止静默执行”验收。

## 五、任务-017状态

`MultiSceneCoordinator`已实现：

1. 正式目录校验与未知场景拒绝。
2. 单工作协程串行处理加载，避免多个异步切换同时写活动状态。
3. 默认先释放并卸载旧业务场景，再附加加载目标场景。
4. 控制器解析、能力一致性校验和异步初始化。
5. 新事务立即废弃旧事务提交权。
6. 迟到加载完成后主动卸载迟到场景，不留下隐藏业务场景。
7. 目标失败时尝试重新加载并初始化上一个稳定场景。
8. 恢复成功和恢复失败均返回结构化结果。
9. 重复释放幂等，释放后拒绝新切换。

任务-017已满足运行时协调范围的验收。运行模式测试从正式 Bootstrap 启动，先实际加载燃气场景；再请求燃煤占位场景时，控制器按预期返回 `scene-content-unavailable`，协调器卸载失败目标并恢复燃气场景，始终仅保留一个已加载的业务场景。快速连续请求时，旧事务返回 `command-superseded`，最新事务成功，旧回调不能改写当前活动场景。

八个场景仍是受控占位内容，因此不计作九个业务场景的内容、资源内存或业务动作验收；这些属于任务-039至047、任务-053和任务-054，不阻塞任务-017的协调器交付。
