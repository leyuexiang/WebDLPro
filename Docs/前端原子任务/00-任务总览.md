# 当前文档索引与事实源

本文只维护当前有效入口，不记录任务进度、历史包路径、阶段性完成比例或聊天结论。实现与文档冲突时，以运行时代码、Unity 序列化配置、自动化测试和发布门禁共同证明的行为为准。

## 一、事实源优先级

1. 发布清单生成器与最终产物门禁：`power-data-web/scripts/build-gas-power-smoke-release.mjs`、`power-data-web/scripts/release-artifact-contract.mjs`。
2. Unity 场景与能力目录：`Assets/Configuration/BusinessSceneCatalog.asset`、`Assets/Configuration/ProcessDetailCatalog.asset`。
3. 前端运行时登记、拓扑版本清单和显式绑定：`power-data-web/src/config/`、`power-data-web/src/modules/visual/topology-preview/`、`power-data-web/src/modules/visual/topology/`。
4. 自动化测试：`power-data-web/tests/`、`power-data-web/src/**/*.spec.ts`、`Assets/Tests/`。
5. 本目录中的规范文档。文档用于解释稳定规则，不保存可由代码计算的数量副本。

## 四、维护规则

1. 不再新增“任务编号-实施状态”“某日构建记录”“完成比例”类文档。
2. 场景数量、动作数量、节点数量、第三层数量和散列值从代码或产物重新生成，不在多份文档中手工复制。
3. 发布记录属于发布产物元数据或外部发布系统，不追加到规范文档。
4. 新需求若改变稳定规则，更新对应规范；若只完成一次实现，不新增永久实施记录。
5. 已取消、已替代或未进入当前清单的设计不得继续作为开发入口。需要保留的历史可从版本控制记录追溯。

## 五、当前硬边界

- 业务场景目录包含十一项；`overview` 是独立总览，不计入业务场景数组。
- 当前联合清单发布十项公开动作、三项第三层关键环节；具体集合以生成器和最终产物门禁为准。
- `nodeId`、`sceneNodeId`、`deviceId` 职责分离，平台内部设备编号不得写入我方清单。
- 第二层拓扑按显式组合键切换完整输入文件；第三层只按稳定上下文加载唯一完整文件，不显示筛选轨。
- 当前发布清单的下钻说明集合为空。现存通用下钻组件不代表任何场景已发布该能力。
