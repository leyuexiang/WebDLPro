## 完成结论

任务-023、024已按“每个系统维护一套总拓扑，关键环节只过滤总图事实”的最终规则完成。子层级不再保存另一份节点、连线或映射定义；运行时从来源总拓扑的预构建索引一次投影可见节点和连线，只覆盖显式二维坐标，并始终复用一个活动画布。

## 交付内容

| 范围 | 当前实现 | 完成依据 |
| --- | --- | --- |
| 过滤类型 | `TopologyDefinition.filter` 固定包含 `sourceTopologyId`、`visibleNodeIds`、`visibleEdgeIds`、可选 `allowedOrphanNodeIds`、`nodeLayoutOverrides` | 子层级的本地 `nodes`、`edges` 必须为空，不复制业务事实；允许孤立节点必须来自资料且与实际孤立集合完全一致 |
| 清单校验 | 校验同场景来源、禁止嵌套过滤、节点和连线存在性、连线两端、孤立节点、重复项及排布完整性 | 非法过滤清单在注册表创建前受控拒绝 |
| 一次投影 | `TopologyRegistry` 先为总图建立节点、连线映射表，再按显式标识生成过滤视图 | 不执行“可见节点 × 总图节点”或“设备 × 拓扑 × 节点”嵌套扫描 |
| 状态投影 | 过滤视图与来源总图共用节点事实，并预展开设备到所有可见二维目标的索引 | 切换后使用最新权威快照重建，不复制设备状态来源 |
| 单画布运行时 | `TopologyRuntime` 提供准备、事务激活、选择、视图状态、设备状态和释放接口 | 总图与三个关键环节连续切换时 Unity 内嵌框架和拓扑画布均不重建 |
| 有限缓存 | 准备结果、视图状态和状态派生缓存均有固定容量，淘汰后可由注册表与权威快照恢复 | 释放时清空缓存并释放画布、图元回调和缓冲区 |

## 边界

- 本次关闭的是多拓扑类型、注册表和单画布运行时能力，不代表其余八个场景已有正式拓扑内容。
- 当前燃气测试包明确排除正式设备绑定和设备状态；平台运行时注入、基础与运行时双清单、五百台容量及三维状态失败隔离继续由任务-038、048、049、052验收。
- 不根据节点标题、图元、模型名、截图或坐标补充三维映射。
- 无 `actionId` 的 `view.open` 返回总览仍只负责激活二维来源总图，不能据此推断Unity行为；需要同步恢复三维时，必须使用清单中显式登记的总览动作。当前燃气包已通过 `action.gas-power.overview` 完成该闭环，其他场景不得按名称或默认拓扑猜测总览动作。
