# 调度中心场景拓扑与合作方清单

## 场景入口

| 字段 | 发布值 |
| --- | --- |
| 场景标识 | `dispatch` |
| 场景名称 | 调度中心 |
| 默认拓扑标识 | `topology.dispatch.overview` |
| 入口动作 | `action.dispatch.overview` |
| 动作目标视图 | `business` |
| 动作目标拓扑 | `topology.dispatch.overview` |
| 三维引擎（Unity）动作类型 | `none`（无三维动作） |
| 场景支持动作 | `action.dispatch.overview` |

合作方必须通过 `workflow.trigger`（流程触发）调用 `action.dispatch.overview`。结构清单的 `actions` 和场景反向索引 `supportedActionIds` 均登记该动作；合作方摘要 `release-manifest.json.workflowActions` 由同一结构清单生成，包含动作标识、标题、目标场景、目标视图和目标拓扑。

## 交互与 Unity 边界

- 图元点击：仅在当前 Meta2D（网页二维组态画布）中选中图元，并高亮其直接关联线。
- 空白或不可选图元点击：仅清除当前二维选择并恢复线条原始样式。
- 不登记图元到业务节点的 `penId → nodeId` 映射。
- 不登记业务节点到 Unity 节点的 `nodeId → sceneNodeId` 映射；合作方场景节点、流程步骤和路线数组为空。
- 不登记调度中心关键环节，不发送三维聚焦、反向选择、双击节点或三维清选事件。
- 前端动作和二维拓扑已接入；没有修改或验证离线 Unity 工程，不声明三维映射或实机联调已完成。

## 合作方验收清单

1. 读取 `scene-topology-manifest.json`，确认 `dispatch` 默认拓扑为 `topology.dispatch.overview`，唯一支持动作是 `action.dispatch.overview`。
2. 确认该动作目标为 `dispatch`、`business`、`topology.dispatch.overview`，且 Unity 动作类型是 `none`。
3. 读取 `release-manifest.json.workflowActions`，确认存在 `action.dispatch.overview`；使用公开 `workflow.trigger` 验证该入口能到达调度中心拓扑。
4. 确认最终包内存在上表拓扑 JSON 和公共 WebP 文件；对比拓扑 SHA-256 与 `b2235a0ca3a7bb484b4c926519cfd016ae75517c2c4887498a926ca9ce797ef8`，源图元数应为 94，运行时移除空组合容器后为 93。
5. 点击设备图元并点击空白，确认选中与连线高亮仅作用于二维画布；确认结构清单没有调度节点、三维节点、路线、流程步骤或关键环节。
