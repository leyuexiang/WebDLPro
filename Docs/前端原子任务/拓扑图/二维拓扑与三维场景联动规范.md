# 二维拓扑与三维场景联动规范

**适用范围：** 所有同时展示二维拓扑和三维场景的工艺页、专题页与总览页。

**依赖规范：** [图元与设备状态规范](图元与设备状态规范.md)、[二维拓扑布局与交互规范](二维拓扑布局与交互规范.md)。本规范不新增设备状态，所有设备状态仅允许使用正常（`normal`）、告警（`alarm`）、故障（`fault`）、离线（`offline`）四态；容器、缩放、连线与协议标签的布局要求统一以前述布局规范为准。

## 一、联动目标与状态边界

1. 二维拓扑、设备详情、工艺导览和三维场景必须以同一稳定 `nodeId` 关联；不得使用 Unity 层级名、模型文件名或显示名称关联。
2. `selectedNodeId` 是用户交互选中状态，`deviceStatus` 是设备运行状态；两者必须独立保存、独立更新。选中效果只能叠加在设备状态之上，不得替换状态图元或状态材质。
3. 实时状态变化只能更新对应节点的二维图元与三维模型外观，不得改变当前选中节点、镜头位置、拓扑缩放或已高亮路径；用户选择节点才允许触发镜头聚焦。
4. 同一 `nodeId` 的二维和三维状态必须由同一份已经标准化的 `deviceStatus`、`statusUpdatedAt` 驱动。状态无效、缺失或超时必须先归一为离线，再同步至两端。
5. 三维运行时不可用、未声明所需能力或命令失败时，二维选中与状态展示仍必须立即生效；页面应保留可诊断的降级原因，不能伪造三维已聚焦或已着色。

## 二、选择、聚焦与描边

### 2.1 二维拓扑发起选择

用户点击二维设备图元时，工艺动作协调器必须按以下顺序处理：

1. 生成本次选择的关联标识 `selectionId`，更新 `selectedNodeId`，并保留当前设备的 `deviceStatus`。
2. 二维拓扑立即为目标图元叠加可见选中描边，并高亮该节点关联路径；描边不得使用状态 SVG 替换、遮挡或伪造设备状态。
3. 三维运行时处于就绪状态且声明 `focusNode` 能力时，下发节点聚焦命令；三维必须将镜头定位到目标模型可完整辨识的视角，并为目标模型叠加描边效果。
4. 三维命令失败、超时或不支持时，只记录可诊断结果，不撤销已完成的二维选中与详情定位。

二维拓扑的描边与三维模型的描边都必须使用区别于红、黄、灰状态色的统一选中色，并保持足够对比度。描边属于单独渲染层，不能改写模型基础材质、状态透明度或图元资产。

### 2.2 三维场景发起选择

用户点击三维模型时，三维仅回传稳定 `nodeId` 和 `selectionId`。前端收到事件后更新二维选中描边、关联路径、导览和详情；不得把同一选择再次下发为 `focusNode`，避免形成命令回环。若用户从导览选择步骤，则由配置解析目标 `nodeId` 后复用本节的同一选择流程。

### 2.3 聚焦与描边约束

1. `focusNode` 的成功回执表示已接受聚焦请求，不等待镜头动画结束，避免长动画占用命令确认表。
2. 三维描边应通过后处理、额外渲染通道或等效的非破坏性方案实现；不得为每次选择复制模型、克隆材质或反复创建渲染资源。
3. 切换选中节点时必须移除旧节点描边，仅保留当前 `selectedNodeId` 的描边；解除选择、切页、释放运行时后必须清理描边资源和动画回调。

## 三、三维设备状态视觉映射

| 设备状态 | 二维表现 | 三维模型表现 | 选中时的处理 |
| --- | --- | --- | --- |
| 正常 `normal` | 使用 `_normal.svg`。 | 使用模型默认材质与默认透明度，不附加状态特效。 | 只叠加选中描边和镜头聚焦。 |
| 告警 `alarm` | 使用 `_alarm.svg`。 | 模型保持可辨识的半透明效果，并叠加红黄色调；默认不闪烁，避免与故障混淆。 | 保留红黄色调，仅叠加独立选中描边。 |
| 故障 `fault` | 使用 `_fault.svg`。 | 模型保持半透明效果，叠加红色闪烁；闪烁只改变状态特效强度，不得反复创建或替换材质。 | 保留红色闪烁，仅叠加独立选中描边。 |
| 离线 `offline` | 使用 `_offline.svg`。 | 模型保持半透明效果，并叠加灰色调；不得显示为正常材质。 | 保留灰色调，仅叠加独立选中描边。 |

半透明度、故障闪烁频率、告警色阶和描边宽度属于三维样式清单，由发布版本统一登记；页面配置和实时消息不得任意传入颜色、材质路径、动画速度或着色器参数。状态切换应复用受控材质变体、材质属性块（`MaterialPropertyBlock`）或等效渲染参数，禁止按设备和每次状态更新创建材质实例。

## 四、网页图形通信契约

所有消息沿用网页图形（`WebGL`）现有安全信封、精确来源校验、实例标识和命令确认机制。新增或扩展的载荷如下：

| 方向 | 类型 | 必填载荷 | 处理要求 |
| --- | --- | --- | --- |
| 前端 → 三维 | `focusNode` | `nodeId`、`selectionId` | 聚焦目标模型并叠加选中描边；节点不存在、未映射或不可聚焦时返回失败原因。 |
| 前端 → 三维 | `setNodeVisualState` | `nodeId`、`deviceStatus`、`statusUpdatedAt` | 仅更新该节点的三维状态外观；仅接受四态枚举，过期消息与当前状态相同消息不重复渲染。 |
| 三维 → 前端 | `objectSelected` | `nodeId`、`selectionId` | 表示用户在三维中选中模型；前端只同步二维、导览和详情，不回发同一次选择。 |
| 三维 → 前端 | `commandResult` | `requestId`、`success`、失败时的 `errorCode` 与 `message` | 聚焦、状态映射缺失或渲染失败均必须可诊断。 |

`setNodeVisualState` 必须由三维运行时在就绪消息的 `commandCapabilities` 中显式声明。前端只在该能力已协商、状态时间戳较新且状态值确有变化时发送；同一动画帧内同一节点的多条状态更新只保留最新一条，禁止高频消息堆积为无界命令队列。

## 五、配置、验收与可观测性

1. 发布校验必须验证每个三维映射节点同时具备稳定 `nodeId`、四态状态支持和可聚焦能力；未映射的节点可以只显示二维状态，但必须标记“无三维映射”。
2. 当三维运行时声明 `focusNode` 或 `setNodeVisualState` 能力时，场景映射版本必须与二维拓扑配置版本一致；版本不一致时禁止执行对应联动并降级。
3. 自动化测试至少覆盖：拓扑点击后的二维描边和三维聚焦描边、三维点击不产生命令回环、四态二维与三维同步、离线归一、状态与选中叠加、状态更新不改变镜头或选中、过期状态丢弃、运行时降级和释放清理。
4. 诊断事件必须记录 `nodeId`、`selectionId`、`deviceStatus`、`statusUpdatedAt`、运行时标识、场景映射版本、命令结果和降级原因；不得记录 Unity 内部对象路径或无界状态历史。
