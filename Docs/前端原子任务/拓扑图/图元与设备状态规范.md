# 拓扑图图元与设备状态规范

**适用范围：** 所有二维工艺拓扑、网络拓扑、站房拓扑和专题拓扑。
**正式资源基准：** `F:\WorkSpace\WebDLPro\power-data-web\src\assets\topology-icons`。
**受控登记表：** `power-data-web/src/services/topology/topology-icon-registry.ts`；运行时只能经图元键与四态查询该登记表，不能拼接文件路径。
**历史来源：** `Docs/前端原子任务/拓扑图/icons_3d` 只保留为设计资料和资源核对来源，生产源码、构建产物及运行时均不得依赖该目录。
**配套规范：** 节点的容器、多图切换、连线、缩放、拖拽、全屏与性能约束统一遵循[拓扑容器与多图切换规范](拓扑容器与多图切换规范.md)。
**当前视觉基线：** `Builds/Releases/燃气发电场景与拓扑图联动包0813`；只复用其中的图元比例、文字位置、边框、提示和选中表现，不复制燃气业务映射。

> **2026-08-14 节点协议修正：** 平台不向我方注入设备编号。状态快照、双击和三维映射均以 `nodeId` 为关联键；平台内部自行维护 `nodeId → 真实设备编号`。

## 一、图元使用规则

1. 每个设备节点必须使用资源目录中的拟物化 Cisco 风格 SVG 图元；不得以圆形、矩形、字符、表情或临时图标替代正式设备图元。
2. 图元按“设备类型 + 设备状态”成套选择，命名规则为 `icon_<设备类型>_<状态>.svg`；业务配置只保存受控的图元键，不得将外部输入直接拼接为文件路径。
3. 每个可展示节点必须具备稳定 `nodeId`、图元键和发布基线；我方结构清单不得出现 `deviceId`。需要三维聚焦或状态联动的节点由我方提供稳定 `sceneNodeId`；业务节点声明 `doubleClickBehavior: 'emit-node'` 后可直接上报 `nodeId`。
4. 选中、悬停、禁用和搜索命中属于交互表现，不得覆盖或伪造设备状态；状态图元始终由设备状态决定，交互效果只能作为额外描边、外发光或提示信息。
5. 分层拓扑中的层级颜色只用于层级色带、贴合图元的内侧边框和导视文字；它不代表设备状态，也不能替换四态图元。设备状态由四态图元和完整提示表达，不再叠加右上角状态圆点；节点选中时使用独立青色描边与发光，仍须保留层级边框和状态图元。
6. 新拓扑的深色画布、图元、层级边框、提示和选中描边必须遵循[拓扑容器与多图切换规范](拓扑容器与多图切换规范.md)的已确认制作基线；画布不得额外绘制右上角状态圆点。不得以燃气节点名称、模型名称或截图推断图元键、设备状态或三维映射。
7. 图元必须是节点的主要视觉内容，并完全铺满图标盒；约0.5像素的层级描边覆盖在图元边缘内侧，不是图元留白。常规画布图标约28—40像素，常驻文字位于图标盒外下方，以约6.4—7.2像素单行小字或完整悬浮提示呈现，不能扩大图标盒或挤占图标区域。选中外框属于临时交互叠加，只围绕图标盒，常规外扩2像素，极低画布外扩1像素；路由和命中另行合并图标与文字边界。
8. 完整提示必须同时支持鼠标悬浮、键盘聚焦、节点选中和触屏单击；提示只展示已发布标题、可选业务说明和明确状态，不得暴露内部路径或用未确认资料补全文案。
9. 拟物化 Cisco 风离线图元的右上角徽标必须使用透明填充和灰色虚线描边，不能使用白色实心填充；该规则保证图元在白色资源展示页和深色生产画布中保持一致。正常、告警和故障徽标继续使用各自明确的状态色。

## 二、设备状态标准

| 状态中文名 | 状态值 | 对应图元后缀 | 含义 | 数据处理规则 |
| --- | --- | --- | --- | --- |
| 正常 | `normal` | `_normal.svg` | 已收到有效状态，设备运行正常。 | 只能由状态服务明确给出；不得因缺少数据默认正常。 |
| 告警 | `alarm` | `_alarm.svg` | 设备可通信，但存在需要关注的告警。 | 告警解除后由状态服务更新为其他明确状态。 |
| 故障 | `fault` | `_fault.svg` | 已确认故障、保护动作或不可用故障状态。 | 不得仅根据前端阈值或展示文案推断。 |
| 离线 | `offline` | `_offline.svg` | 平台已明确判定通信中断、状态超时或设备不可达。 | 只消费平台明确下发的离线状态，壳不得自行根据长时间未推送或请求失败推断。 |

设备状态必须由平台状态服务标准化为上述四个互斥值。平台约每5秒聚合且只在状态集合变化时推送，壳无需心跳，也不得因一段时间未收到新快照、请求失败或节点未绑定而自行推断正常、告警、故障或离线。

## 三、配置与实时数据约束

字段分为我方结构字段和实时状态字段；平台内部设备绑定不进入本表：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `nodeId` | 逻辑节点标识 | 在同一 `resourceKey` 内全局唯一，用于二维选择、双击、状态和可选三维映射。 |
| `sceneNodeId` | 三维节点标识 | 可选；用于 Unity 聚焦、状态和对象选择，不得使用 Unity 层级路径。 |
| `iconKey` | 图元键 | 必须在受控图元登记表中存在，并且具备四个状态 SVG。 |
| `deviceStatus` | 平台实时四态 | 仅允许 `normal`、`alarm`、`fault`、`offline`；结构清单中的同名值只作为无实时数据时的发布基线。 |
| `statusUpdatedAt` | 平台状态时间 | 必填带时区的国际标准时间字符串，只用于显示、日志和诊断；壳不据此判断快照新旧，也不自行启动离线计时器。 |
| `doubleClickBehavior` | 节点双击能力 | 结构清单声明，平台只读；新的业务源拓扑节点使用 `emit-node`。`none` 仅用于旧协议解析和防御测试。 |

`device.states.update.items` 在数据语义上是当前 `resourceKey` 全部已上报节点的完整快照，命令名为兼容既有协议保留。壳始终有限保存最新一份，最多500项；每份合法快照到达后按 `nodeId` 直接整体替换旧状态表，`sourceRevision` 即使因平台重启变小也只能用于诊断。旧快照中存在而新快照中消失的状态覆盖要被清除，节点恢复发布基线或“状态待接入”展示，不能保留旧颜色，也不能伪造为离线。同批重复节点以最后一项为准，未知节点忽略。渲染层比较新旧快照后，只局部更新差异节点，不得因完整替换重建整张拓扑。

## 四、发布与验收

1. 发布校验必须验证每个 `iconKey` 都能解析出四个状态图元。
2. 组件测试必须覆盖四种平台明确状态的图元切换、状态与选中效果叠加、完整快照替换、消失节点清除、同批重复最后一项生效、未知节点忽略、较小修订仍应用和非法载荷拒绝。没有节点状态时不发送空状态命令，结构清单仍可启动。
3. 性能测试必须验证最多500项的完整快照只局部更新差异节点，不重建画布、不丢失拓扑选择或缩放状态；超过协议容量时整批拒绝，不得静默截断。
4. 未接入真实状态契约的页面可以展示结构化“状态待接入”说明，但不得批量伪造为正常状态。
5. 视觉回归必须验证图元尺寸优先级、一行小字省略、完整提示、触屏选中读取，以及缩放和平移后提示仍与节点命中区域一致。

## 五、二维与三维联动

壳按结构清单中的 `nodeId → 可选 sceneNodeId` 派生三维目标，并将最新四态尽力同步到对应目标；同一场景内一个 `sceneNodeId` 最多反向对应一个 `nodeId`。选中效果仍作为独立叠加层。二维拓扑应用是外层状态命令的主成功条件；三维能力缺失、超时、节点拒绝或部分失败不得回滚二维状态，也不得把外层 `command.result` 改为失败，只能进入固定容量内部诊断并在 Unity 恢复后按最新快照补同步。其余节点聚焦、双向选择、节点双击、材质映射和性能规则统一遵循[多拓扑与 Unity 多场景联动规范](多拓扑与Unity多场景联动规范.md)。
