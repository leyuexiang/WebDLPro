# 拓扑图图元与设备状态规范

**适用范围：** 所有二维工艺拓扑、网络拓扑、站房拓扑和专题拓扑。
**资源基准：** `F:\WorkSpace\WebDLPro\Docs\前端原子任务\拓扑图\icons_3d`。
**配套规范：** 节点的容器、连线、协议标签、缩放、拖拽、全屏与性能约束统一遵循[二维拓扑布局与交互规范](二维拓扑布局与交互规范.md)。

## 一、图元使用规则

1. 每个设备节点必须使用资源目录中的拟物化 Cisco 风格 SVG 图元；不得以圆形、矩形、字符、表情或临时图标替代正式设备图元。
2. 图元按“设备类型 + 设备状态”成套选择，命名规则为 `icon_<设备类型>_<状态>.svg`；业务配置只保存受控的图元键，不得将外部输入直接拼接为文件路径。
3. 每个可展示的设备节点必须同时具备稳定 `nodeId`、图元键和设备状态；缺任一项时不得发布为正式拓扑节点。
4. 选中、悬停、禁用和搜索命中属于交互表现，不得覆盖或伪造设备状态；状态图元始终由设备状态决定，交互效果只能作为额外描边、外发光或提示信息。

## 二、设备状态标准

| 状态中文名 | 状态值 | 对应图元后缀 | 含义 | 数据处理规则 |
| --- | --- | --- | --- | --- |
| 正常 | `normal` | `_normal.svg` | 已收到有效状态，设备运行正常。 | 只能由状态服务明确给出；不得因缺少数据默认正常。 |
| 告警 | `alarm` | `_alarm.svg` | 设备可通信，但存在需要关注的告警。 | 告警解除后由状态服务更新为其他明确状态。 |
| 故障 | `fault` | `_fault.svg` | 已确认故障、保护动作或不可用故障状态。 | 不得仅根据前端阈值或展示文案推断。 |
| 离线 | `offline` | `_offline.svg` | 通信中断、状态超时、状态无效或设备不可达。 | 状态未上报、超过契约时效或无法标准化时，统一归一为离线。 |

设备状态必须由领域状态服务标准化为上述四个互斥值。前端只消费标准化结果，不自行将指标值、告警文字或请求失败猜测为正常、告警或故障。

## 三、配置与实时数据约束

每个设备节点至少需要以下数据字段：

| 字段 | 类型 | 约束 |
| --- | --- | --- |
| `nodeId` | 稳定业务标识 | 与拓扑、详情、导览和三维映射使用同一标识。 |
| `iconKey` | 图元键 | 必须在受控图元登记表中存在，并且具备四个状态 SVG。 |
| `deviceStatus` | 四态枚举 | 仅允许 `normal`、`alarm`、`fault`、`offline`。 |
| `statusUpdatedAt` | 时间戳 | 用于判断状态是否超过实时协议约定的有效期。 |

实时更新只替换发生变化节点的 `deviceStatus` 和 `statusUpdatedAt`，不得因单个设备状态变化重建整张拓扑。图元资产缺失、状态值非法或状态超时必须进入可诊断降级，并记录稳定节点标识和原因。

## 四、发布与验收

1. 发布校验必须验证每个 `iconKey` 都能解析出四个状态图元。
2. 组件测试必须覆盖四种状态的图元切换、状态与选中效果叠加、非法状态降级和状态超时转离线。
3. 性能测试必须验证单设备状态变更只更新目标节点，不重建画布、不丢失拓扑选择或缩放状态。
4. 未接入真实状态契约的页面可以展示结构化“状态待接入”说明，但不得批量伪造为正常状态。

## 五、二维与三维联动

当拓扑页面接入三维场景时，四态状态必须同时驱动对应模型的视觉状态，选中效果必须作为独立叠加层。节点聚焦、二维与三维双向选择、三维描边、状态材质映射、通信载荷及性能验收，统一遵循[二维拓扑与三维场景联动规范](二维拓扑与三维场景联动规范.md)；本规范中的图元资产规则不得被三维联动逻辑覆盖或绕过。
