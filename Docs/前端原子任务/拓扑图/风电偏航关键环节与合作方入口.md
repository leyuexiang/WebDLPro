# 风电偏航关键环节与合作方入口

## 一、公开入口

合作方从结构清单的 `actions` / `release-manifest.json.workflowActions` 读取偏航第三层动作：

| 字段 | 固定值 |
| --- | --- |
| `actionId` | `action.wind-power.yaw-system` |
| `sceneId` | `wind-power` |
| `processId` | `wind-power-generation` |
| `stepId` | `yaw-system` |
| `processDetailId` | `process-detail.wind-power.yaw-system` |
| `resourceId` | `process-detail-resource.wind-power.yaw-system` |
| `cameraPoseId` | `camera-pose.wind-power.yaw-system` |
| `stateNodeId` | `node.wind-yaw-system` |
| Unity 动态目标节点编号 | `node.wind-yaw-system` |
| `topologyDataContextId` | `process-detail.wind-power.yaw-system` |

入口通过外层 `workflow.trigger`（工作流触发）执行，载荷 `actionId` 为 `action.wind-power.yaw-system`。合作方应以该公开动作编号发现并进入第三层；只登记第二层 `asset.wind-yaw-system → node.wind-yaw-system` 映射不足以生成菜单入口。

## 二、专属二维拓扑

源文件为用户提供的 `偏航.json`，SHA-256（安全散列算法 256 位）为 `86767c78df1d0ea12ed8b34e3ed8834caa0ba27d13a0dbd6e2011ac175d7dddd`。文件共 15 个图元，图元编号唯一。前端运行路径为 `public/topology/process-detail/wind-power/yaw-system/topology.json`，公共拓扑上下文锁定相同散列和图元数量，发布门禁会校验随包文件。

源图主控制器与电机、角度传感器、减速机、液压站、制动器共六个图元开放二维选中。它们没有独立的 Unity 场景编号，不能从第二层整机编号推导子设备映射。图中的其余元素保留原有展示和连线；第三层不启用筛选轨，也不执行输入文件里的事件脚本或模拟数据。

原 JSON 中的 PNG（便携式网络图形）路径只作为来源记录。运行时统一映射到已存在的公共 WebP（网页图片格式）资源，包含控制器图标、设备图标和流光装饰，不需要新增 PNG 或额外资源副本。

## 三、发布与验收

发布生成器、绝对动作门禁、第三层目录门禁和正负向测试都必须同时登记偏航第三层。即使结构清单和摘要一起删掉偏航动作，绝对门禁也应拒绝；缺少偏航 JSON、散列、图元编号或固定目录字段同样应拒绝。

合作方收到新包后应检查 `workflowActions` 包含上述动作，并在 Unity 资源包中确认对应偏航关键环节资源已由其 Unity 发布基线提供；随后通过公开工作流动作进入偏航第三层，并确认加载专属 15 图元拓扑。前端源码及静态门禁通过不替代合作方包的 Unity 运行时联调。
