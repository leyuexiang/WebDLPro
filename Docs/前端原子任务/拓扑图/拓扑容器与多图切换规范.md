# 拓扑容器与多图切换规范

**适用范围：** 当前可视化子应用中的所有工艺拓扑、网络拓扑和站房拓扑。

**关联规范：** 图元与状态遵循[图元与设备状态规范](图元与设备状态规范.md)；场景联动遵循[多拓扑与 Unity 多场景联动规范](多拓扑与Unity多场景联动规范.md)。

---

## 零、已确认的制作基线

燃气发电分层通信拓扑是当前唯一已经由用户确认视觉效果的参考实现。后续新建的工艺、网络和站房拓扑必须复用本规范的容器、分层、节点、连线、文字、全屏和交互规则；只能替换经过正式清单确认的业务数据，不能复制燃气的节点名称、层级名称、设备标识、三维标识、坐标或连线关系。

基线对应的通用能力如下：

1. 深色工业风画布，层级色带、设备卡片、状态图元、连线发光和选中描边处于不同视觉层，不相互覆盖语义。
2. 层级、颜色、节点坐标、协议标签和连线证据均来自清单；未声明时使用中性未分类表现，不推断为燃气样式或已确认关系。
3. 常规态拓扑与 Unity 实际视口共用宽度；全屏态解除该常规宽度，改为当前子应用视口内的自适应覆盖层。
4. 所有尺寸变化只重算现有画布和必要路径，不新建画布、图元缓存或交互监听器。

## 一、容器职责

1. 拓扑容器是当前子应用的下半区，不依赖门户、页面导航、工艺导览或设备详情。
2. 容器按当前 `topologyId` 渲染一套拓扑，同一时刻只保留一个活动画布。
3. 一个 `sceneId` 可以登记多套 `topologyId`，默认拓扑和允许拓扑由场景清单决定。
4. 拓扑切换只能由联动协调器发起，组件不得自行修改当前场景或向父页面发送原始消息。
5. 切换期间必须与 Unity 场景或动作处于同一个 `transitionId`，禁止提前暴露新拓扑为可操作状态。

---

## 二、拓扑配置边界

1. 节点、层级、连线、协议文字、方向和坐标必须由拓扑配置提供，不得根据标题、截图、三维模型名称或坐标邻近关系猜测。
2. `topologyId` 全局唯一；每个 `nodeId` 在所属拓扑内唯一。
3. `nodeId` 只表示二维节点；外部业务设备使用 `deviceId`；三维模型使用 `sceneNodeId`。
4. 同一设备可出现在多套拓扑中，因此多个 `nodeId` 可以映射到同一个 `deviceId`。
5. 状态、选中、缩放和平移不能修改业务关系、节点坐标和连线方向。
6. 分层展示是可选的纯二维元数据：`layers[]` 定义 `layerId`、标题、纵向位置和颜色；节点以可选 `layerId` 显式归属层级。缺失时按未分层通用拓扑绘制，不得依据坐标或名称补全层级。
7. 边可选携带协议或介质标签及连线证据状态。标签仅用于二维可读性；证据状态仅决定实线、虚线和颜色，不代表运行时通信协议、设备状态或 Unity 路由。

后续拓扑清单至少按以下展示字段建模；业务映射字段仍按正式映射清单单独维护：

| 字段 | 作用 | 制作约束 |
| --- | --- | --- |
| `layers[].layerId/title/y/color` | 分层色带、左侧层级导视和节点边框色 | 必须由业务资料明确提供；颜色应具有足够对比度。 |
| `nodes[].layerId` | 节点所属展示层级 | 只能引用同一拓扑已经声明的层级。 |
| `edges[].protocolLabel` | 连线旁的协议或介质说明 | 空间不足或发生碰撞时可隐藏标签，不可压住节点文字。 |
| `edges[].evidenceStatus` | 已核验、待确认、概念或未分类的连线视觉 | 未声明时必须使用中性未分类虚线，不能默认为已核验。 |
| `nodes[].sceneNodeId` | 可选三维聚焦目标 | 只有正式登记且 Unity 声明能力时才可使用。 |

## 三、容器布局

1. 子应用根区域使用上下两区网格。先为拓扑保留响应式最小可读高度，再在剩余高度内计算 Unity 的 16:9 视口；拓扑不能被三维区持续挤压，也不得以内容高度撑开根页面。
2. 常规桌面宽度下，拓扑最小可读高度采用 `clamp(320px, 42dvh, 460px)`；小于 `720px` 宽度时采用 `clamp(300px, 48dvh, 420px)`。低于可读下限时显示结构化“容器尺寸不足”，不得继续裁切节点和文字。
3. 常规态拓扑面板的宽度必须等于 Unity 实际 16:9 视口宽度并水平居中；标题、图例、状态摘要、画布和全屏入口与 Unity 左右边界对齐。超宽屏未使用区域统一采用纯黑壳层背景，不把拓扑青色背景扩展到两侧。
4. 拓扑面板、标题、图例、状态摘要、画布和缩放工具栏必须位于同一容器；画布使用标题和状态摘要之外的全部剩余高度。
5. 拓扑全屏使用当前子应用内的固定定位遮罩，不调用或依赖浏览器原生全屏。四边采用响应式安全边距；全屏态必须解除“与 Unity 同宽”的常规约束，标题、图例和状态摘要占用自身高度，唯一画布填充其余高度。必须提供关闭按钮和 `Esc` 退出。
6. 退出全屏后恢复同一画布实例以及当前拓扑的缩放、平移和选中状态；外层父页面不得因拓扑内容出现滚动条，缩放和平移均在画布内部完成。

## 四、画布视觉与文字基线

1. 画布使用深蓝黑底和低对比网格；分层拓扑在画布内绘制半透明层级色带、虚线分隔线和独立的左侧层级导视区。层级标题、节点、连线和标签不得侵入该导视区。
2. 节点使用深色圆角设备卡片：状态 SVG 图元为主体，层级色只用于边框，状态圆点独立显示。选中时叠加青色外框和发光，不能替换图元、层级色或设备状态。
3. 已核验连线使用青色实线；待确认和概念连线使用各自的虚线与色彩；未分类连线使用中性虚线。选中路径可以加粗、提亮和增强发光，但不能改变连线证据含义。
4. 协议或介质标签必须放置在正交路径的可用线段上，并与节点卡片、层级导视区、边界和其他标签进行碰撞检测。没有安全位置时隐藏该标签，禁止为了完整显示而压住内容。
5. 节点标题按画布实际像素宽度换行，不按字符数截断。常规视口最多两行十像素字；宽度小于 `1000px` 的紧凑视口最多四行八像素字；超过承载能力时仅最后一行追加省略号。节点卡片边界必须始终限制在可视区域内。
6. 层级、连线、节点、图元、状态圆点和选中描边按该顺序由下至上绘制。新拓扑不得用纯色矩形、文字或临时表情替代正式图元，也不得把选中效果写入设备状态。

## 五、多拓扑切换

### 5.1 准备与激活

拓扑切换分为两个阶段：

1. `prepare(topologyId, transitionId)`：读取、校验和预计算轻量拓扑数据，但不改变活动画布。
2. `activate(topologyId, transitionId)`：仅在协调器确认场景和动作满足提交条件后替换活动拓扑。

旧 `transitionId` 的准备结果不得激活。准备失败时必须保留当前拓扑，不得清空活动画布。

### 5.2 画布与缓存

1. 始终复用一个活动画布适配器，不为每套拓扑创建隐藏画布。
2. 可缓存最近使用拓扑的解析结果，但必须设置容量上限并按最近使用策略淘汰。
3. 可按 `topologyId` 保存有限视图状态：缩放、平移、选中节点和选中路径。
4. 图元图片按受控资源地址缓存，同一地址只加载一次；缓存必须有释放策略。
5. 拓扑版本变化时清除对应解析和视图缓存，禁止跨版本复用旧路径。

## 六、更新性能

拓扑定义、选择、状态和尺寸必须使用独立更新路径：

| 变化 | 允许执行 | 禁止执行 |
| --- | --- | --- |
| `topologyId` 或拓扑版本变化 | `setTopology`、重建节点索引和路径缓存 | 保留旧版本路径 |
| 选中节点或路径变化 | `setSelection`、局部重绘 | `setTopology`、重新加载图元 |
| 单设备状态变化 | 更新目标节点状态、局部重绘 | 重建全图布局和连线路径 |
| 容器尺寸变化 | 重算画布尺寸和必要路径 | 创建新画布实例 |
| 缩放或平移 | 更新视图变换并重绘 | 修改配置坐标或业务关系 |

连续回调必须合并到下一动画帧。设备像素比建议上限为 `2`，防止高分屏缓冲区无限扩大。

## 七、节点交互

### 7.1 单击

1. 单击命中后立即更新本地 `nodeId` 选择和关联路径。
2. 有 `sceneNodeId` 时，由协调器向 Unity 发送 `focusNode`。
3. 三维不可用或聚焦失败时保留二维选择，不伪造成功。
4. 拖拽结束后的浏览器单击事件必须被忽略，避免误选经过节点。

### 7.2 双击

1. 双击不延迟第一次单击，仍保留本地选中结果。
2. 只有 `doubleClickBehavior: 'emit-device'` 且存在 `deviceId` 的节点允许上报。
3. 双击向协调器发出设备事件，再由外层桥发送 `topology.node.dblclick`。
4. 双击产生的重复单击通过选择关联标识幂等去重，不重复发送相同三维聚焦命令。
5. 概念分组、层级标题和无设备标识节点不得发送设备双击事件。

### 7.3 缩放、拖拽与可访问性

1. 支持滚轮、工具栏放大缩小、重置和按住左键拖拽。
2. 默认缩放为 `100%`；当前建议范围继续使用 `55%` 至 `225%`。
3. 画布、工具栏按钮和全屏按钮必须具备明确中文无障碍名称。
4. 容器尺寸变化后重新计算可视坐标，不裁切层级文字、节点名称和控件。

## 八、节点与连线布局

1. 层级标题使用独立左侧导视区，节点、连线和标签不得侵入。
2. 无冲突的同层相邻节点优先水平直连；无冲突的同列相邻节点优先垂直直连。
3. 直线穿过第三方节点、复用其他主干或产生非端点交叉时，改用独立避让通道。
4. 同一节点同一侧的多条边分配不同端口，并按稳定边标识排序。
5. 跨层和跨列边使用不同通道，禁止公共长主干覆盖多条业务关系。
6. 箭头方向按路径最后一段计算，必须与配置方向一致。
7. 协议或介质文字与线体保留间隔，并执行节点、导视区、边界和其他标签碰撞检测。
8. 连线在节点下方绘制，节点、图元、状态和选中描边在上方绘制。

路径缓存只在拓扑定义、拓扑版本、容器尺寸或路由规则版本变化时重建。常规状态和选择更新必须复用缓存。

---

## 九、释放规则

拓扑运行时释放时必须：

1. 取消待执行动画帧。
2. 断开尺寸观察器。
3. 移除全局键盘监听器。
4. 释放图元加载回调和画布引用。
5. 清理当前活动拓扑和有限缓存。
6. 阻止旧拓扑异步回调更新新实例。

## 十、验收清单

- [ ] 一个场景可登记并切换多套拓扑。
- [ ] 同一时刻只有一个活动画布。
- [ ] 准备失败时保留当前拓扑。
- [ ] 旧事务准备结果不能激活。
- [ ] 选择变化不重建拓扑和路径缓存。
- [ ] 单设备状态变化只更新目标节点。
- [ ] 单击立即选中并按映射聚焦三维。
- [ ] 双击额外上报正确 `deviceId`，不重复聚焦。
- [ ] 全屏、缩放、拖拽、重置和退出状态恢复可用。
- [ ] 常规态拓扑与 Unity 视口同宽；全屏态覆盖整个子应用可视区域，右侧不残留 Unity 区域。
- [ ] 分层色带、连线证据、协议标签、状态图元和选中描边均由显式配置或受控运行时状态驱动。
- [ ] 紧凑视口下层级标题、节点名称、协议标签与缩放控件不重叠；无安全位置的标签被隐藏而非覆盖内容。
- [ ] 连续切换后观察器、动画帧、图元回调和画布缓存不累积。
