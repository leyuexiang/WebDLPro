# 拓扑容器与多图切换规范

**适用范围：** 当前可视化子应用中仅在第二层厂区模式显示的工艺拓扑、网络拓扑和站房拓扑。

**关联规范：** 图元与状态遵循[图元与设备状态规范](图元与设备状态规范.md)；场景联动遵循[多拓扑与 Unity 多场景联动规范](多拓扑与Unity多场景联动规范.md)。

> **2026-08-14 节点协议修正：** `nodeId` 是平台与我方共同使用的逻辑关联键。平台内部维护 `nodeId → 真实设备编号`，不向拓扑壳注入设备编号；双击和状态快照均只使用 `nodeId`。

> **2026-08-30 展示范围：** 第一层沙盘和第三层关键环节均为全屏三维，不显示拓扑。本规范只约束第二层厂区的拓扑容器；进入沙盘或关键环节时必须停用并隐藏唯一画布，暂停输入、尺寸观察、布局和重绘，返回厂区时复用原画布恢复。

## 零、已确认的制作基线

燃气发电分层通信拓扑是当前唯一已经由用户确认视觉效果的参考实现，现行可复现交付物为 `Builds/Releases/燃气发电场景与拓扑图联动包0813`，包内发布标识为 `gas-power-platform-release-5550-20260813-2015`。后续新建的工艺、网络和站房拓扑必须复用本规范的容器、分层、节点、连线、文字、全屏和交互规则；只能替换经过正式清单确认的业务数据，不能复制燃气的节点名称、层级名称、设备标识、三维标识、坐标或连线关系。

基线对应的通用能力如下：

1. 深色工业风画布，层级色带、状态图元、连线发光和提示层处于不同视觉层，不相互覆盖语义；节点没有独立卡片底板或节点级附加外框。
2. 层级、颜色、节点坐标、协议标签和连线证据均来自清单；未声明时使用中性未分类表现，不推断为燃气样式或已确认关系。
3. 常规态拓扑与 Unity 实际视口共用宽度；全屏态与三维容器统一调用浏览器原生全屏接口，拓扑面板直接成为全屏元素并填满屏幕，不再使用只能覆盖子应用视口的固定定位遮罩。
4. 所有尺寸变化只重算现有画布和必要路径，不新建画布、图元缓存或交互监听器。
5. 每个系统只维护一份总拓扑事实；厂区子层级拓扑是总拓扑的受控过滤视图，必须保留当前主题从顶层到底层的完整相关节点与连线，无关节点和连线只隐藏，不复制、改写或删除总拓扑事实。过滤视图不得作为第三层关键环节画面。
6. 节点视觉尺寸由画布宽高、最密层节点数和相邻层净距共同计算；图元与文字可缩小，但命中区保持独立可用。未选中节点不绘制常驻外框；节点被选中时必须叠加独立、可撤销的选中反馈。
7. 连线按稳定边标识计算，任意角度直线优先；只有直线穿过第三方完整节点边界、与已接受线路共线重叠或发生非端点交叉时，才按最少拐点、最短长度绕行。

0813 历史燃气回归夹具固定为总览23节点/22连线、燃气轮机16/13（允许孤立2个）、余热锅炉13/6（允许孤立6个）、蒸汽轮机15/10（允许孤立4个）。总图五层纵坐标为 `8、28、50、69、88`；企业层和隔离区层横坐标为 `24、50、76`，厂级层为 `14、38、62、86`，单元层为 `12、30、44、59、74、89`，现场层为 `6、18、30、44、59、74、89`。三个旧关键环节过滤视图复用这些坐标，只作为厂区多图能力和历史兼容回归数据；新第三层不得激活或展示它们，其他场景也不得照搬这些业务坐标。

## 一、容器职责

1. 拓扑容器仅在第二层厂区作为当前子应用下半区；沙盘和关键环节模式不为它预留空间。
2. 容器按当前 `topologyId` 渲染一套拓扑，同一时刻只保留一个活动画布。
3. 一个 `sceneId` 可以登记多套 `topologyId`，默认拓扑和允许拓扑由场景清单决定。
4. 拓扑切换只能由联动协调器发起，组件不得自行修改当前场景或向父页面发送原始消息。
5. 切换期间必须与 Unity 场景或动作处于同一个 `transitionId`，禁止提前暴露新拓扑为可操作状态。

## 二、拓扑配置边界

1. 节点、层级、连线、协议文字、方向和坐标必须由拓扑配置提供，不得根据标题、截图、三维模型名称或坐标邻近关系猜测。
2. `topologyId` 全局唯一；每个 `nodeId` 在同一 `resourceKey` 内全局唯一。
3. `nodeId` 是二维、状态和双击的逻辑关联键；平台真实设备编号不进入拓扑壳；三维模型使用 `sceneNodeId`。
4. 同一业务节点出现在多套拓扑时复用同一个 `nodeId`，过滤视图只引用总图节点，不复制定义。
5. 状态、选中、缩放和平移不能修改业务关系、节点坐标和连线方向。
6. 分层展示是可选的纯二维元数据：`layers[]` 定义 `layerId`、标题、纵向位置和颜色；节点以可选 `layerId` 显式归属层级。缺失时按未分层通用拓扑绘制，不得依据坐标或名称补全层级。
7. 边可选携带协议或介质标签及连线证据状态。标签仅用于二维可读性；证据状态仅决定实线、虚线和颜色，不代表运行时通信协议、设备状态或 Unity 路由。
8. 每个系统必须指定一套总拓扑。子层级拓扑必须显式引用该总拓扑，并以稳定节点标识和连线标识声明可见集合；不得复制节点坐标、设备映射、三维映射或连线事实形成第二份数据源。
9. 子层级可见集合默认覆盖该主题从顶层入口到最底层目标的连续已登记链路。只有两端节点均可见且连线标识已列入当前过滤视图时才绘制连线；其余节点、连线、协议标签和状态图元不参与当前视图绘制与命中测试。
10. 业务资料明确要求展示、但总图没有合法连线的节点，允许作为孤立节点保留；必须逐项写入 `allowedOrphanNodeIds`，不得为了消除孤立而补造连线。未声明孤立、声明不可见节点或把实际已连接节点声明为孤立时必须阻止发布。
11. 子层级拓扑不能根据中文标题、节点位置、同名设备或自动最短路径推断相关关系。相关节点和连线由业务资料明确登记；出现未登记断链、跨总图引用或重复事实时阻止发布。
12. 总览图可声明 `focusRegions`（重点区域）用于强调已绑定三维模型的入口节点及其显式子节点。每个区域必须登记稳定 `regionId`、带 `sceneNodeId` 的 `anchorNodeId`（锚点节点）和包含锚点的 `nodeIds` 成员集合；兼容清单中的旧 `label` 只作为元数据保留，画布不得显示区域名称，也不得根据标题、坐标或连线自动归组。
13. 重点区域只属于总览来源图；厂区过滤视图以及保留的历史关键环节过滤视图必须省略并在注册表投影时清空 `focusRegions`。区域框是区域级视觉，不是节点外框，不参与节点命中、选中状态、连线路由或三维联动。

后续拓扑清单至少按以下展示字段建模；业务映射字段仍按正式映射清单单独维护：

| 字段 | 作用 | 制作约束 |
| --- | --- | --- |
| `layers[].layerId/title/y/color` | 分层色带和左侧层级导视色 | 必须由业务资料明确提供；颜色应具有足够对比度。 |
| `nodes[].layerId` | 节点所属展示层级 | 只能引用同一拓扑已经声明的层级。 |
| `edges[].protocolLabel` | 连线旁的协议或介质说明 | 空间不足或发生碰撞时可隐藏标签，不可压住节点文字。 |
| `edges[].evidenceStatus` | 已核验、待确认、概念或未分类的连线视觉 | 未声明时必须使用中性未分类虚线，不能默认为已核验。 |
| `nodes[].sceneNodeId` | 可选三维聚焦目标 | 只有正式登记且 Unity 声明能力时才可使用。 |
| `nodes[].doubleClickBehavior` | 节点双击能力 | 新业务源拓扑的全部节点必须为 `emit-node`，结构清单声明后平台不得修改；说明、分组和层级标题不作为节点。`none` 仅保留为旧协议与防御测试兼容值。 |
| `sourceTopologyId` | 子层级视图引用的总拓扑 | 总拓扑不填写；子层级必须引用同一场景内已登记的唯一总拓扑。 |
| `visibleNodeIds` | 子层级需要显示的节点集合 | 必须显式列出从顶层到底层的完整相关链路，不复制节点定义。 |
| `visibleEdgeIds` | 子层级需要显示的连线集合 | 每条边必须属于总拓扑且两端均在 `visibleNodeIds` 中；未列入的边隐藏。 |
| `allowedOrphanNodeIds` | 资料明确要求保留的孤立节点集合 | 只能逐项引用当前可见且在过滤后实际无边的节点；不得用于放宽普通断链或补造关系。 |
| `nodeLayoutOverrides` | 过滤视图投影后的节点二维坐标 | 默认由注册表或发布构建器按 `nodeId` 从总拓扑坐标生成，子层级不得独立维护另一套拉伸坐标。只有业务资料明确要求节点换位时才允许人工覆盖 `x/y`，且必须覆盖全部可见节点并保留依据；标题、图元、状态、设备和三维映射始终复用总图。 |
| `focusRegions[]` | 总览图重点区域及其成员节点 | 仅总览声明；`regionId` 唯一，`anchorNodeId` 必须存在且绑定 `sceneNodeId`，`nodeIds` 不得重复并必须包含锚点；过滤视图禁止声明。 |

## 三、容器布局

1. 只有第二层厂区使用上下两区等分网格。三维容器和拓扑容器各占可用高度的一半，二者之间仅保留 1 像素分隔；沙盘和关键环节改为单区全屏三维，不为拓扑预留空白。
2. 厂区三维实际视口在上半区内保持 16:9；其宽度与下半区拓扑面板宽度相同并水平居中。0813包按外层部署最小尺寸 `600×600` 判定“容器尺寸不足”；低于部署阈值时由外层显示结构化诊断。
3. 常规态拓扑面板的宽度必须等于 Unity 实际 16:9 视口宽度并水平居中；标题、图例、画布和全屏入口与 Unity 左右边界对齐。超宽屏未使用区域统一采用纯黑壳层背景，不把拓扑青色背景扩展到两侧。
4. 常规态移除节点、连线和设备状态统计摘要。拓扑面板、标题、图例、画布和缩放工具栏必须位于同一容器；画布使用标题、图例和内边距之外的全部剩余高度。空拓扑才显示配置缺失说明。
5. 拓扑全屏必须与三维容器使用相同的浏览器原生全屏接口：由用户手势对当前拓扑面板调用 `requestFullscreen`，并以 `document.fullscreenElement` 和 `fullscreenchange` 事件作为唯一真实状态。全屏态必须解除“与 Unity 同宽”的常规约束，标题、图例和内边距占用自身高度，唯一画布填充其余高度。节点图元、节点标题、层级标题和连线文字必须同步放大至常规态的 2 倍，并使用同倍率的标题、选中、命中和连线避让边界；不得通过修改用户缩放或平移实现。必须提供关闭按钮，并支持浏览器原生 `Esc` 退出。
6. 外层平台及其承载本子应用的每一层内嵌框架必须声明 `allow="fullscreen"` 或等效权限策略；任一层未授权时浏览器可拒绝请求，子应用只能保持常规态并恢复按钮状态，禁止退回只能覆盖平台容器的假全屏。
7. 退出用户主动触发的拓扑原生全屏后恢复同一画布实例以及当前拓扑的缩放、平移和选中状态，并回到厂区双区布局；外层父页面不得因拓扑内容出现滚动条，缩放和平移均在画布内部完成。

## 四、画布视觉与文字基线

1. 画布使用深蓝黑底和低对比网格；分层拓扑在画布内绘制半透明层级色带、虚线分隔线和独立的左侧层级导视区。层级标题、节点、连线和标签不得侵入该导视区。
2. 节点采用图标优先布局：状态图元居中并直接填满图标盒，图标盒只作为布局、连线端点和命中计算边界。未选中节点不绘制层级描边、圆角矩形或其他常驻装饰；选中节点允许在正式图元外叠加独立选中反馈，但不得替换、裁切或改写原始图元。文字完全位于图元下方；空间不足时优先截断常驻小字，而不是压缩图元。设备状态只由四态图元和完整提示表达，画布不再额外绘制遮挡图标的右上角状态圆点；图元自带状态徽标继续保留，其中旧离线图元徽标必须透明填充并使用灰色虚线描边。
3. 已核验连线使用青色实线；待确认和概念连线使用各自的虚线与色彩；未分类连线使用中性虚线。选中路径可以加粗、提亮和增强发光，但不能改变连线证据含义。
4. 协议或介质标签必须扫描路径中的全部可用线段。斜线路径的标签放在线段中点法线方向并保持文字水平；标签与完整节点边界、层级导视区、画布边界和其他标签统一碰撞检测。没有安全位置时隐藏该标签，禁止为了完整显示而压住内容。
5. 常驻文字默认只在图元下方显示一行辅助小字，按实际像素宽度截断并追加省略号；不得在图标右侧保留多行大面积文字区。常规画布节点标题约为 `6.4—7.2` 像素，层级标题约为 `8.8—9.9` 像素，协议文字约为 `7.2—8.1` 像素；低于 `188` 像素的极低画布允许继续按受限高度缩小。节点完整标题、可选设备说明和状态说明通过悬浮提示展示；提示锚点限制在画布安全区，当前实现不承诺对节点或连线执行碰撞绕行。
6. 桌面端鼠标悬浮、键盘聚焦和节点选中都必须能够显示同一份完整提示；触屏设备通过单击选中读取，不能把完整名称做成仅鼠标可见的信息。提示内容只来自当前节点已发布字段，不显示内部标识、Unity 层级路径或未确认映射。
7. 绘制顺序固定为：层级背景、重点区域框、连线和协议标签、节点状态图元与辅助小字、选中反馈、上层提示。重点区域仅使用虚线圆角矩形、轻透明填充和稳定伪随机颜色，不显示区域名称；它不是节点级外框，也不是选中反馈，不能替代正式图元或表达节点状态。
8. 常规画布图标限制为约 `28—40` 像素；高度 `160—239` 像素时图标下限为 `18` 像素，低于 `160` 像素的极低画布下限为 `8` 像素。前两档分别保证常规和紧凑视图，最后一档只用于类似 `500×108` 的受限嵌入画布，并依赖现有缩放查看细节。
9. 路由边界和命中边界必须分开计算：路由安全边界合并图元和下方文字后保留少量避让余量；命中边界覆盖图元和文字并补足至少 `40×40` 像素。两者只服务连线和交互，不得回写为可见节点外框。
10. 响应式比例由画布宽度、高度、最密层数量和相邻层净距共同取受限值：在 `600×240` 到 `1280×720` 间由 `0.8` 连续插值到 `0.9`；画布高度低于 `188` 像素时，在 `108—188` 像素间由 `0.55` 连续插值到 `0.8`。图标常规为 `28—40` 像素，高度 `160—239` 像素时下限为 `18` 像素，低于 `160` 像素时下限为 `8` 像素；节点标题、层标题和协议文字分别以 `8`、`11`、`9` 像素乘响应式比例。左侧导视区使用 `clamp(88px, 13%, 124px)`，右侧安全边距为 `max(14px, 2%)`。
11. 协议标签按文字实测宽度和可用线段自适应计算标签盒，不得使用 Canvas 的 `maxWidth` 横向压缩字体；可用空间不足时按字符追加省略号，无法安全放置时隐藏标签，保证剩余文字可读且不覆盖节点、重点区域或其他标签。

## 五、多拓扑切换

### 5.1 准备与激活

拓扑切换分为两个阶段：

1. `prepare(topologyId, transitionId)`：读取、校验和预计算轻量拓扑数据，但不改变活动画布。
2. `activate(topologyId, transitionId)`：仅在协调器确认场景和动作满足提交条件后替换活动拓扑。

若目标为子层级视图，`prepare` 必须在注册表加载阶段已完成“来源节点/连线索引 → 可见集合 → 总图坐标投影”的一次投影；画布只接收投影结果。没有资料明确的换位要求时，投影坐标必须与总图一致；隐藏节点、隐藏连线、其协议标签和命中区域均不得保留在活动画布或选择索引中。

旧 `transitionId` 的准备结果不得激活。准备失败时必须保留当前拓扑，不得清空活动画布。

### 5.2 画布与缓存

1. 始终复用一个活动画布适配器，不为每套拓扑创建隐藏画布。
2. 可缓存最近使用拓扑的解析结果，但必须设置容量上限并按最近使用策略淘汰。
3. 可按 `topologyId` 保存有限视图状态：缩放、平移、选中节点和选中路径。
4. 图元图片按受控资源地址缓存，同一地址只加载一次；缓存必须有释放策略。
5. 拓扑版本变化时清除对应解析和视图缓存，禁止跨版本复用旧路径。
6. 布局缓存同时保存标题边界、最小命中边界和路由安全边界。路径只在拓扑、画布尺寸或路由规则版本变化时重算；选择、设备状态、缩放和平移重绘不得逐帧执行碰撞搜索。

### 5.3 总拓扑与子层级过滤

1. 总拓扑负责保存该系统全部已确认节点、连线、层级、坐标和映射，是唯一结构事实来源。
2. 子层级只保存总拓扑标识、可见节点标识、可见连线标识和自己的显示标题，不重复保存节点或连线对象。
3. 激活子层级时先从总拓扑的常数时间索引取出可见节点，再按显式连线集合生成过滤结果；禁止每次绘制嵌套扫描全部节点与全部连线。
4. 总拓扑状态、选择和设备映射变化后，当前子层级直接投影最新事实；切回总拓扑时不需要重新加载资源或等待平台重推状态。
5. 隐藏节点不绘制、不参与点击和悬浮命中，但其最新设备状态仍保存在有限权威快照中，重新显示时立即恢复。
6. 子层级默认复用总图的真实层级和坐标，切换时节点不得跳位或被分别拉伸到画布两端；资料明确要求换位时才允许带依据的完整覆盖。

## 六、更新性能

拓扑定义、选择、状态和尺寸必须使用独立更新路径：

| 变化 | 允许执行 | 禁止执行 |
| --- | --- | --- |
| `topologyId` 或拓扑版本变化 | `setTopology`、重建节点索引和路径缓存 | 保留旧版本路径 |
| 选中节点或路径变化 | `setSelection`、局部重绘 | `setTopology`、重新加载图元 |
| 单设备状态变化 | 更新目标节点状态、局部重绘 | 重建全图布局和连线路径 |
| 容器尺寸变化 | 重算画布尺寸和必要路径 | 创建新画布实例 |
| 缩放或平移 | 更新视图变换并重绘 | 修改配置坐标或业务关系 |

连续回调必须合并到下一动画帧。设备像素比建议上限为 `2`，防止高分屏缓冲区无限扩大。

## 七、节点交互

### 7.1 单击

1. 单击命中后立即更新本地 `nodeId` 选择和关联路径。
2. 有 `sceneNodeId` 时，由协调器向 Unity 发送 `focusNode`。
3. 无 `sceneNodeId` 的图元仍保留二维选择，但必须向 Unity 发送 `clearSelection`，清除前一次已绑定图元遗留的三维交互选中效果；不得把未绑定图元误映射到任意模型。
4. 三维不可用、清理失败或聚焦失败时保留二维选择，不伪造成功。
5. 拖拽结束后的浏览器单击事件必须被忽略，避免误选经过节点。

### 7.2 双击

1. 双击不延迟第一次单击，仍保留本地选中结果。
2. 只有 `doubleClickBehavior: 'emit-node'` 的节点允许上报。
3. 双击向协调器发出节点事件，再由外层桥发送仅含 `sceneId + topologyId + nodeId` 的 `topology.node.dblclick`。
4. 双击产生的重复单击通过选择关联标识幂等去重，不重复发送相同三维聚焦命令。
5. 概念分组、层级标题和 `none` 节点不得发送节点双击事件。

### 7.3 缩放、拖拽与可访问性

1. 支持滚轮、工具栏放大缩小、重置和按住左键拖拽。
2. 默认缩放为 `100%`；当前建议范围继续使用 `55%` 至 `225%`。
3. 画布、工具栏按钮和全屏按钮必须具备明确中文无障碍名称。
4. 容器尺寸变化后重新计算可视坐标，不裁切层级文字、节点名称和控件。
5. 节点悬浮提示必须跟随画布缩放和平移后的实际命中区域定位；拖拽期间隐藏提示，结束后重新命中，避免提示抖动和误选。
6. 节点点击范围至少为 `40×40` 像素并同时覆盖图标和下方文字。多个命中范围在紧凑画布中重叠时，选择与点击点距离节点中心最近者，不依赖清单插入顺序。
7. 画布真正空白处不得误选节点；空白单击先提交空的二维节点和关联路径选择，再通过既有协调器请求 Unity 清除三维交互描边。即使当前已经没有二维选择，也仍须发送一次 `clearSelection`，以消除可能残留的三维交互描边；缩放、平移、拖拽结束和工具栏操作不得误触发该行为。

### 7.4 下钻关联覆盖层

1. 下钻只用于展示当前正式节点的说明型关联关系，采用拓扑面板内部的全尺寸覆盖层，不注册为新的 `topologyId`，不参与正式拓扑 `prepare/activate`（准备/激活）事务。
2. 下钻入口必须使用独立的 `drilldown`（下钻）能力声明和按钮；不得把节点单击改成下钻，也不得复用双击节点事件。节点单击仍负责二维选择和已登记的三维聚焦，双击仍按既有 `topology.node.dblclick` 规则上报。
3. 覆盖层挂载在拓扑面板内部的相对定位工作区，使用 `position: absolute`（绝对定位）和 `inset: 0`（四边贴合）覆盖面板内容；必须使用不透明背景，完全遮挡原节点、连线、提示、缩放控件和全屏入口。
4. 覆盖层打开后，原拓扑保留唯一画布实例但进入不可交互状态；通过 `inert`（不可交互）和焦点隔离阻断鼠标、键盘及提示穿透，不得创建第二个拓扑画布或第二个 Unity 内嵌框架。
5. 燃煤、燃气下钻的来源节点、直接子节点和模型节点必须延续总览的“正式图标 + 图标下方标题”布局。节点通过受控 `iconKey`（图元键）解析图标，禁止纯文字、矩形卡片、临时字符和图片路径；模型节点虽不属于正式拓扑，仍必须显示正式图标。
6. 说明图最顶层只能复用一个当前正式入口节点；其余说明节点不属于总拓扑事实，不得声明 `nodeId`、`sceneNodeId`、设备状态、设备绑定或三维映射。说明连线也不得冒充正式拓扑边、协议证据或运行时路由。
7. 说明节点不提供点击动作或三维交互；静态图固定使用受控图标的 `normal`（正常）外观，不接入自身告警、故障、离线图标。鼠标悬浮、键盘聚焦和触屏单击后的提示固定只显示“节点标题”和“状态：状态值”两行，状态沿用触发入口当前正式状态，不显示节点类型、关联说明或内部标识，提示使用覆盖层单实例实现。缩放和平移只更新覆盖层本地状态，不发送 Unity 命令、外层消息、节点双击事件、状态同步或场景动作；关闭覆盖层时恢复原拓扑的缩放、平移、选中、路径和键盘焦点。
8. 场景或拓扑切换进入准备、切换或加载状态时，必须隐藏旧拓扑的下钻按钮；只有新的稳定上下文提交后，才允许显示新拓扑的下钻入口。
9. 覆盖层尺寸始终跟随拓扑面板自身，不读取并保存页面级屏幕坐标；窗口缩放、嵌入区域变化和拓扑原生全屏均自动同步。覆盖层不得覆盖常规态拓扑面板两侧的黑色留白。
10. 下钻内容按 `contentKey + version`（内容键与版本）有限缓存；打开序号、内容键和版本必须参与迟到结果校验。打开、关闭、拓扑切换和组件卸载时清理监听器、动画帧和缓存引用。
11. 下钻说明、空态、原生全屏和关闭按钮必须具备明确中文无障碍名称；覆盖层使用对话框角色但不声明全页模态，因为上方三维区域仍可使用。支持关闭按钮和浏览器退出键，焦点关闭后返回触发按钮，触发按钮不存在时回退到拓扑面板标题。

### 7.5 总览重点区域

1. 重点区域只在未声明 `filter` 的总览拓扑绘制；厂区过滤视图及历史关键环节过滤资源必须没有区域数据，注册表投影也必须显式清空，不能因复用来源节点而继承区域框。第三层关键环节不激活任何过滤资源。
2. 区域边界由成员节点的 `visualBounds`（图标与标题视觉边界）一次计算，包含统一内边距；不使用 `hitBounds`（命中边界）或 `routeBounds`（路由边界），避免区域框放大点击范围或改变连线避让。
3. 绘制只采用轻透明填充和虚线圆角矩形，不绘制名称标签。颜色依据 `regionId` 的确定性哈希从受控调色板选择，视觉上随机但刷新、缩放和视觉回归结果稳定。
4. 区域绘制顺序位于层级背景之后、连线之前；区域框不得遮挡节点图元、标题和协议标签，不参与选择集合、设备状态、三维聚焦、下钻入口或外层消息。
5. 发布校验必须保证 `regionId` 唯一、`anchorNodeId` 存在且带 `sceneNodeId`、`nodeIds` 不重复并包含锚点；未通过校验时整份清单不得进入运行时。

## 八、节点与连线布局

1. 层级标题使用独立左侧导视区，节点、连线和标签不得侵入。
2. 所有边先按稳定 `edgeId` 排序，再从两端图标真实边框交点尝试任意角度的两点直线；不再只对同层或同列关系直连。
3. 候选线路不得穿过第三方完整节点边界。该边界包含图标、下方文字和选中安全区，不只包含图标矩形。
4. 候选线路不得与已经接受的路径共线重叠或发生非端点交叉；共享业务端点时只放行双方端点的单点接触。
5. 直线冲突时依次尝试一个拐点和两个拐点；同一拐点数量内选择总长度最短且坐标顺序稳定的无碰撞候选。全部候选失败时才使用既有独立通道路由作为最终回退。
6. 同一节点同一侧的多条边按对端坐标和稳定边标识分配不同端口；最终通道回退仍禁止公共长主干覆盖多条业务关系。
7. 箭头方向按路径最后一段计算，必须与配置方向一致。
8. 协议或介质文字沿线段法线保留间隔并保持水平，执行完整节点、导视区、画布边界和其他标签碰撞检测。
9. 连线在节点下方绘制，节点图元和标题在上方绘制；选中反馈位于对应节点视觉边界外侧，不能遮挡图标、标题或重点区域框。

### 8.1 节点选中反馈

1. 选中是独立于设备状态的二维交互状态。选中节点仍使用当前 `deviceStatus`（设备状态）对应的正式图元，不得把选中误显示为正常、告警、故障或离线。
2. 默认采用高对比青白色外圈或描边，并配合轻微外发光作为选中反馈；选中反馈只能围绕节点视觉边界绘制，不得重新生成节点卡片、遮挡图元或改变节点标题。具体色值和线宽由画布主题统一控制，常规态应清晰可见，紧凑态按展示倍率同步缩放。
3. 选中关联路径同时提高线宽、亮度或发光强度，但不得改变连线证据状态、方向、协议标签内容和路由坐标。未选中的节点和路径不得因相邻节点被选中而出现选中外圈。
4. 节点单击、键盘确认、触屏选中和 Unity（统一引擎）反向选择必须使用同一套二维选中反馈；清空选择、切换拓扑、关闭下钻和组件销毁后必须移除旧反馈，不能残留在新拓扑或新节点上。
5. 选中反馈与总览重点区域框分层绘制：区域框用于表达模型关联范围，选中反馈用于表达当前交互对象；二者同时存在时必须都可辨识，不能以区域框代替节点选中效果。
6. 选中反馈不得扩大 `hitBounds`（命中边界）、修改 `routeBounds`（路由边界）或触发额外拓扑扫描；选择变化只调用 `setSelection`（设置选择）并合并到下一动画帧重绘。

路径缓存只在拓扑定义、拓扑版本、容器尺寸或路由规则版本变化时重建。常规状态和选择更新必须复用缓存。

## 九、释放规则

拓扑运行时释放时必须：

1. 取消待执行动画帧。
2. 断开尺寸观察器。
3. 移除全局键盘监听器。
4. 释放图元加载回调和画布引用。
5. 清理当前活动拓扑和有限缓存。
6. 阻止旧拓扑异步回调更新新实例。

## 十、验收清单

- [ ] 一个场景可登记并切换多套拓扑。
- [ ] 同一时刻只有一个活动画布。
- [ ] 准备失败时保留当前拓扑。
- [ ] 旧事务准备结果不能激活。
- [ ] 选择变化不重建拓扑和路径缓存。
- [ ] 单设备状态变化只更新目标节点。
- [ ] 单击立即选中并按映射聚焦三维。
- [ ] 双击额外上报正确 `nodeId`，不重复聚焦且消息不包含 `deviceId`。
- [ ] 全屏、缩放、拖拽、重置和退出状态恢复可用。
- [ ] 常规态拓扑与 Unity 视口同宽；全屏态由浏览器登记拓扑面板为原生全屏元素并覆盖整个屏幕，退出后全屏元素清空且不重建画布或 Unity 内嵌框架。
- [ ] 下钻说明覆盖层完全遮挡当前拓扑面板，自动跟随容器尺寸和原生全屏变化，不创建第二个画布或 Unity 实例；说明节点不进入正式拓扑、状态和外层通信链路。
- [ ] 分层色带、连线证据、协议标签和状态图元均由显式配置或受控运行时状态驱动；未选中节点不附加常驻外框，选中节点显示独立可撤销的选中反馈。
- [ ] 选中反馈不覆盖正式图元、不改变设备状态、不替代重点区域框，并且不改变命中边界、路由边界或三维消息语义。
- [ ] 总览重点区域只显示虚线圆角边框和轻透明底色，不显示区域名称；下钻节点悬浮、键盘聚焦和触屏单击后显示完整提示，但不出现节点级业务弹窗。
- [ ] 节点图元是视觉主体，常驻文字最多一行辅助小字；完整名称可通过悬浮、键盘聚焦或选中读取，触屏不依赖悬浮。
- [ ] 拟物化 Cisco 风四态资源与受控源文件一致；离线徽标在白色展示页和深色画布中均为透明底灰色虚线环，不出现白色实心圆。
- [ ] 单击画布空白位置清除当前二维节点和关联路径选择；拖拽结束、滚轮缩放和工具栏操作不得误触发清除。
- [ ] 紧凑视口下层级标题、节点小字、协议标签与缩放控件不重叠；无安全位置的协议标签被隐藏而非覆盖内容，提示锚点始终限制在画布可见安全区。
- [ ] 每个子层级视图都从同一总拓扑过滤，并完整显示当前主题从顶层到底层的已登记链路；无关节点和连线不绘制、不命中。
- [ ] 子层级复用总图层级和坐标，不独立拉伸；不存在复制节点定义、复制设备映射、未登记断链或按名称推导关系。资料明确要求的孤立节点必须显式登记。
- [ ] `600×240`、`770×336`、`942×257`、`1280×720` 和 `3440×1440` 下完整节点边界不与相邻层重叠；真实极低画布另按实际尺寸补测。
- [ ] 无冲突边为两点直线；穿过节点、共线重叠或非端点交叉时使用最少拐点的最短绕行，箭头及斜线标签位置正确。
- [ ] 缩放和平移后图标与文字仍可命中；重叠命中选最近节点，节点间空白不误选，空白单击同时清除二维选择和三维交互描边。
- [ ] 连续切换后观察器、动画帧、图元回调和画布缓存不累积。
