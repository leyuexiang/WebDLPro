# 拓扑下钻关联覆盖层实施计划

**计划状态：** 待实施

**提出日期：** 2026-08-21

**适用范围：** 第二层厂区当前活动拓扑中，需要展示更深层关联关系、但不属于正式业务拓扑事实的说明型下钻内容。

**关联文档：** [拓扑容器与多图切换规范](拓扑容器与多图切换规范.md)、[多拓扑与 Unity 多场景联动规范](多拓扑与Unity多场景联动规范.md)、[测试、性能与发布任务](../07-测试性能与发布.md)、[测试包与正式包输出标准](../测试包与正式包输出标准.md)。

> **2026-08-30 展示边界补充：** 总览中的 `focusRegions`（重点区域）属于第二层厂区拓扑本身的区域级视觉分组，负责框选已绑定三维模型的入口及其子节点；它与本计划的说明型下钻覆盖层相互独立。重点区域仅绘制边框和底色，不显示区域名称，不创建说明节点、不提供下钻交互。第一层沙盘和第三层关键环节均为全屏三维，无拓扑节点和下钻入口；旧关键环节过滤视图只作历史兼容资料。

---

## 一、结论与设计决策

本需求采用“同一拓扑容器内的全尺寸下钻覆盖层”，不采用正式拓扑切换，也不创建新的页面或第二个拓扑画布。

下钻内容的定位是“解释当前节点内部关系”，不是“进入另一套可运行拓扑”。因此：

1. 点击入口节点后，在当前拓扑面板内部显示覆盖层，覆盖层尺寸和位置与点击时的拓扑面板一致。
2. 原拓扑仍保留在组件树和运行时中，但被不透明覆盖层完全遮挡，并通过 `inert`（不可交互）禁止焦点和鼠标操作。
3. 覆盖层复用总览拓扑的“正式图标 + 图标下方标题”视觉语言：来源节点、直接子节点和下方模型节点均必须声明受控 `iconKey`（图元键），由正式图元登记表解析图标；其余节点仍属于说明型逻辑节点，不进入总拓扑清单的节点、状态、三维映射或设备绑定。
4. 下钻节点、连线和说明文字只在覆盖层内本地交互，不调用 Unity，不发送外层消息，不触发 `view.open`、`workflow.trigger`、`topology.node.dblclick` 或状态同步。
5. 关闭覆盖层后恢复原拓扑的缩放、平移、选中节点、选中路径和键盘焦点；不得重新激活拓扑或重新创建画布。

这样可以保留总览上下文，又能避免把不存在于总拓扑的说明节点误认为真实设备。

## 二、需求边界

### 2.1 纳入范围

- 第二层厂区活动拓扑中经业务资料明确标记为“可下钻”的入口节点。
- 入口节点到若干说明型节点之间的静态关联关系。
- 覆盖层内的缩放、平移、关闭和退出键操作。
- 覆盖层与拓扑面板尺寸、全屏状态和容器变化的同步。
- 覆盖层打开、关闭、重复打开、尺寸变化和释放的组件测试与视觉回归。

### 2.2 明确不纳入范围

- 不把说明型节点写入总拓扑 `nodes`，不为其分配平台 `nodeId`，不声明 `sceneNodeId`。
- 不为下钻内容新增正式 `topologyId`，不进入拓扑注册表的场景切换集合。
- 不改变 Unity 场景、流程步骤、镜头、模型显隐、状态材质或三维选中描边。
- 不向父页面发送新消息，不扩展外层协议，不要求平台参与。
- 不接入实时设备状态、告警、故障、离线或设备绑定。
- 不支持从说明节点继续触发业务动作；若未来需要多级业务操作，另立正式需求评审。

## 三、交互方案

### 3.1 入口节点

在节点清单的展示扩展字段中增加下钻能力声明，建议使用独立的 `drilldown`（下钻）对象，不复用 `doubleClickBehavior`：

```json
{
  "nodeId": "仅用于示例的正式入口节点",
  "drilldown": {
    "enabled": true,
    "contentKey": "由业务资料登记的说明内容键",
    "trigger": "button"
  }
}
```

约束如下：

1. `nodeId` 仍只属于总拓扑中的正式入口节点。
2. `trigger: button` 表示通过节点附近的独立下钻按钮进入；不把单击改成下钻，避免破坏现有三维聚焦。
3. 双击仍遵循既有节点事件规则；下钻按钮点击不产生节点双击事件。
4. `contentKey` 只能引用已加载且版本匹配的说明内容；缺失内容时显示固定空态，不根据标题、坐标或节点名称猜测关系。
5. 业务资料未声明 `drilldown` 时，节点不显示下钻入口。

### 3.2 覆盖层布局

覆盖层挂载在拓扑面板内部的相对定位容器中：

```text
拓扑面板（相对定位）
├─ 原拓扑标题、图例和唯一画布
└─ 下钻覆盖层（绝对定位，inset: 0）
   ├─ 说明层标题栏
   ├─ 说明型关联图
   └─ 关闭按钮
```

实现约束：

1. 拓扑面板或其内部工作区设置 `position: relative`（相对定位）。
2. 覆盖层设置 `position: absolute`（绝对定位）、`inset: 0`（四边贴合）和高于画布的层级。
3. 覆盖层使用不透明背景，必须完全遮挡原拓扑的节点、连线、提示、缩放控件和全屏按钮。
4. 不使用页面根节点固定定位，不依赖手工保存屏幕坐标；因此窗口缩放、内嵌区域变化和拓扑原生全屏都能自动同步。
5. 若拓扑面板常规态与三维视口同宽，覆盖层只覆盖拓扑面板本身，不覆盖两侧黑色留白。
6. 打开覆盖层不改变唯一拓扑画布的数量；少量说明节点采用轻量的可缩放矢量图形（SVG）与文档对象模型（DOM）绘制，不复用正式拓扑运行时，也不创建第二个画布。
7. 原拓扑内容与覆盖层必须是同一相对定位工作区内的兄弟节点，只对原拓扑内容设置 `inert`（不可交互）；不得把 `inert` 设置在两者共同父节点，否则覆盖层本身也会失去焦点与交互。
8. 覆盖层使用 `role="dialog"`（对话框角色）并关联标题，但不声明 `aria-modal="true"`（全页模态状态）：它只遮挡拓扑面板，不能向辅助技术谎报上方三维区域也不可用。不得调用原生 `showModal`（显示模态对话框）进入浏览器顶层，避免覆盖范围脱离拓扑面板。

### 3.3 关闭与返回

关闭入口统一放在覆盖层标题栏右侧，使用“关闭下钻”中文无障碍名称；标题栏同时复用当前拓扑面板的原生全屏控制，使说明图可在常规态与原生全屏态之间切换。以下操作均可关闭：

- 点击关闭按钮。
- 按浏览器退出键。
- 未来若进入原生全屏，先按既有全屏规则退出全屏，再按退出键关闭覆盖层；不得把一次按键误解释为两个关闭动作。

关闭时必须：

1. 清理说明图的局部指针和临时动画状态。
2. 恢复打开前保存的原拓扑视图快照。
3. 将键盘焦点返回触发下钻的按钮；若触发按钮已因拓扑切换消失，则回退到拓扑面板标题。
4. 不调用拓扑 `prepare/activate`，不触发 Unity 或外层桥回调。

## 四、数据与渲染模型

### 4.1 说明内容模型

建议把说明内容作为独立、只读、版本化的前端数据块，不混入正式拓扑节点：

```ts
interface TopologyDrilldownContent {
  readonly contentKey: string
  readonly version: string
  readonly title: string
  readonly sourceNodeId: string
  readonly nodes: readonly TopologyDrilldownNode[]
  readonly edges: readonly TopologyDrilldownEdge[]
}

interface TopologyDrilldownNode {
  readonly id: string
  readonly title: string
  readonly kind: 'source' | 'logic' | 'boundary'
  /** 受控正式图元键；只允许引用图元登记表，不保存图片路径或外部网址。 */
  readonly iconKey: TopologyIconKey
  readonly x: number
  readonly y: number
  readonly description?: string
}

interface TopologyDrilldownEdge {
  readonly id: string
  readonly fromId: string
  readonly toId: string
  readonly label?: string
}
```

模型约束：

1. `sourceNodeId` 必须指向当前活动正式拓扑中存在的入口 `nodeId`。
2. 说明节点 `id` 只在当前 `contentKey` 内唯一，不得与正式 `nodeId` 或 `sceneNodeId` 混用。
3. `kind: source` 只能有一个，且必须位于说明图最顶层；它是当前拓扑中的入口节点投影。
4. `kind: logic` 和 `kind: boundary` 只表达关系，不拥有设备状态、平台事件或三维映射；两类节点仍必须按场景映射表登记 `iconKey`。
5. 说明连线只能连接同一说明内容中的节点；不允许跨内容键、跨场景或回写正式拓扑边。
6. 所有文本、坐标、颜色和连线标签必须由说明内容明确提供；禁止从节点标题或坐标自动推断关联关系。

### 4.2 渲染规则

1. 所有节点均直接使用 `iconKey` 解析出的正式拓扑图标，标题统一显示在图标下方；不得用纯文字、矩形卡片、字符或临时圆形代替图标。
2. 来源节点的 `iconKey` 必须与当前正式入口节点一致；直接子节点和下方模型节点按燃煤、燃气场景映射表显式登记，不得根据标题、坐标或模型名称猜测。
3. 说明节点仍不拥有实时设备状态。静态下钻图默认使用登记图标的 `normal`（正常）外观；不得显示说明节点自身的告警、故障或离线状态徽标，也不得把“警告”素材误当作告警。提示中的状态只沿用触发入口当前正式状态；若未来需要为说明节点单独接入动态状态，必须另立正式设备拓扑需求。
4. 说明节点不显示“来源节点”“直接子节点”“模型说明节点”等类型辅助文字；节点层级由布局和连线表达。
5. 说明图不绘制设备状态统计、三维选中描边或平台绑定提示；悬浮、键盘聚焦和触屏单击只显示“节点标题”和“状态：状态值”两行，状态沿用触发入口当前正式状态，不显示节点类型、关联说明或内部标识。
6. 说明连线只表达静态关联，不复用正式拓扑的协议证据、运行时路由或状态语义。
7. 说明图的缩放、平移和命中区采用独立的轻量实现；可复用现有尺寸计算常量、视觉令牌和提示样式，但不得调用正式画布适配器、拓扑运行时或高像素比位图缓冲区。
8. 节点命中区与视觉图元分离，命中区至少保持 `40×40` 像素并同时覆盖图标和下方标题；鼠标悬浮、键盘聚焦和触屏单击后的可读状态均显示完整提示，拖拽期间隐藏，离开节点或失焦后清除。

## 五、状态隔离与生命周期

覆盖层使用独立的短生命周期状态，不写入可视化稳定上下文：

| 状态 | 作用 | 允许影响 | 禁止影响 |
| --- | --- | --- | --- |
| `closed` | 未打开 | 正常拓扑交互 | 场景、拓扑、Unity、外层事件 |
| `opening` | 校验并准备说明内容 | 显示局部等待状态 | 替换正式拓扑或发送业务事务 |
| `open` | 显示说明图 | 说明图缩放、平移和只读完整提示 | 正式节点选择、设备状态、三维聚焦、外层业务弹窗 |
| `error` | 说明内容缺失或版本不匹配 | 显示固定错误和关闭入口 | 猜测内容、清空当前拓扑、触发回滚 |

生命周期要求：

1. 打开前保存一次原拓扑视图快照，禁止每一帧或每次指针移动重复复制。
2. 打开期间暂停原拓扑的鼠标和键盘命中，但保留唯一画布和资源句柄。
3. 关闭、拓扑切换、场景切换或组件卸载时，统一清理覆盖层监听器、动画帧和内容缓存引用。
4. 内容缓存按 `contentKey + version` 建立有限容量索引；版本变化时淘汰旧内容，禁止无界累积。
5. 任何迟到的说明内容加载结果都必须核对当前打开序号和 `contentKey`，不能覆盖新打开的内容或恢复已关闭的覆盖层。

## 六、性能与响应式要求

1. 打开覆盖层只做一次内容校验、一次索引构建和一次必要绘制，不重新解析总拓扑。
2. 说明节点和连线使用静态索引；指针和视图变化不得嵌套扫描全部节点与全部连线。
3. 连续尺寸回调、滚动或全屏变化合并到下一动画帧；尺寸同步只更新覆盖层绘制边界，不创建画布。
4. 说明内容数量建议按“少量关联节点”控制；超过现有拓扑画布可读性或性能预算时，应改为正式页面级信息架构评审，不在覆盖层中无限扩张。
5. 覆盖层打开和关闭前后，浏览器内嵌框架数量、拓扑画布数量、图元资源缓存数量和监听器数量必须保持稳定。
6. 说明层动画只使用合成层属性，默认不加入持续循环动画；退出后立即取消动画帧。

## 七、分阶段实施

### 阶段一：交互与数据契约

- 确认入口节点清单中的下钻声明字段和内容键命名。
- 确认说明节点的 `source / logic / boundary` 三类语义和视觉区分。
- 为缺失内容、版本不匹配、内容为空和入口节点不存在定义固定中文空态。
- 在发布校验中禁止说明节点反向进入正式拓扑、状态和三维映射。

### 阶段二：覆盖层容器

- 在现有拓扑面板内部增加相对定位工作区和全尺寸覆盖层出口。
- 增加打开、关闭、退出键、焦点返回和 `inert` 隔离。
- 接入全屏与容器尺寸变化，验证常规态、紧凑态和原生全屏态均无偏移或露底。

### 阶段三：说明图渲染

- 使用可缩放矢量图形与文档对象模型绘制少量说明节点和连线；说明节点直接渲染正式 `iconKey` 图标和下方标题，不创建第二个画布。
- 复用现有视觉令牌、缩放范围、拖拽阈值、命中区和单实例提示样式，不复用正式拓扑运行时状态，不为每个节点创建独立悬浮层。
- 增加说明型节点和连线样式，明确不绘制实时状态和三维交互描边。
- 增加静态索引、局部重绘、有限缓存和迟到结果隔离。

### 阶段四：回归与发布

- 补充组件、视觉、浏览器和释放回归。
- 验证打开下钻不发送外层消息、不调用 Unity、不改变稳定上下文。
- 验证正式包不包含自测入口、测试按钮或合成说明数据；说明内容必须来自正式版本化资源。
- 发布前复核厂区总览、厂区拓扑用户主动全屏、三维聚焦、空白清除和总览复位能力不回退，并确认第三层关键环节没有拓扑下钻入口。

## 八、验收清单

- [ ] 仅声明下钻能力的正式入口节点显示独立下钻按钮。
- [ ] 下钻按钮与节点单击、双击语义分离，不重复触发三维聚焦或节点双击上报。
- [ ] 覆盖层完全覆盖拓扑面板，原拓扑节点、连线、提示和工具栏不可见且不可交互。
- [ ] 覆盖层宽高自动跟随拓扑容器；窗口缩放、嵌入区域变化、原生全屏往返均不偏移、不露底。
- [ ] 覆盖层打开期间不创建第二个拓扑画布或第二个 Unity 内嵌框架。
- [ ] 燃煤和燃气下钻的来源节点、直接子节点、模型节点均显示受控正式图标，标题位于图标下方；不存在纯文字节点或额外节点外框。
- [ ] 所有节点仅显示正式业务标题，不显示“来源节点”“直接子节点”“模型说明节点”等类型辅助文字。
- [ ] 下钻图标键全部存在于正式图元登记表，静态说明图使用正常图标，不把故障素材映射为告警。
- [ ] 场景或拓扑切换加载期间隐藏所有旧拓扑下钻按钮，只有新的稳定视图提交后才显示入口。
- [ ] 鼠标悬浮、键盘聚焦和触屏单击下钻节点均能显示“节点标题 + 状态：状态值”两行提示；状态沿用触发入口当前正式状态，不显示节点类型、关联说明或内部标识，不创建节点级独立业务弹窗。
- [ ] 说明图最顶层只有一个来源节点，其余节点不进入正式拓扑清单，不拥有 `nodeId`、`sceneNodeId`、状态或设备绑定。
- [ ] 说明节点点击、悬浮、缩放和平移不触发外层消息、Unity 命令、状态同步或拓扑事务。
- [ ] 缺失内容、版本不匹配和迟到结果均有固定中文空态，且不替换当前正式拓扑。
- [ ] 关闭后恢复原拓扑缩放、平移、选中、路径和焦点，不重新初始化画布或 Unity。
- [ ] 退出键、关闭按钮、触屏操作和键盘操作均具备明确中文无障碍名称。
- [ ] 键盘焦点不能进入被遮挡的原拓扑；焦点可以进入覆盖层，也可以继续访问未被遮挡的三维区域，关闭后返回下钻入口或拓扑标题。
- [ ] 连续打开、关闭、尺寸变化和组件卸载后，监听器、动画帧、缓存和资源句柄均被释放。

## 十、实施前资料清单

框架可以先用受控测试夹具开发，但正式内容上线前必须取得：

1. 每个可下钻入口的正式 `sceneId + topologyId + nodeId`。

## 十一、风险与升级条件

以下任一条件成立时，不应继续扩大覆盖层，而应重新评审为正式拓扑或页面级详情：

1. 说明节点需要真实设备状态、告警、故障、离线或平台绑定。
2. 说明节点需要三维聚焦、流程动作、节点双击或外部平台事件。
3. 下钻存在多级历史路径、可分享地址、权限控制或长期编辑状态。
4. 说明内容规模导致覆盖层无法在当前厂区半屏拓扑容器内保持可读性。
5. 业务资料要求说明节点成为总拓扑中的正式结构事实。

出现升级条件后，必须另行设计正式 `topologyId`、事务、状态、权限、回退和平台协议，不能通过继续扩展本覆盖层规避边界。
