# 风电拓扑五个设备系统三维映射约定

## 一、映射范围

风电第二层 JSON 拓扑只为五个设备系统建立二维与三维映射：变桨系统、变流系统、偏航系统、传动系统和刹车系统。五个控制层图元仍按源 JSON 绘制，但暂不登记业务节点编号或 Unity 场景节点编号，因此不会参与三维聚焦、反向选择和设备状态绑定。

| 设备系统 | 默认组合图元编号（`penId`） | 业务节点编号（`nodeId`） | Unity 场景节点编号（`sceneNodeId`） |
| --- | --- | --- | --- |
| 变桨系统 | `87f441c`、`d4ab511` | `asset.wind-pitch-system` | `node.wind-pitch-system` |
| 变流系统 | `4996538`、`5e9d380` | `asset.wind-converter-system` | `node.wind-converter-system` |
| 偏航系统 | `44940c8`、`a89f0ae` | `asset.wind-yaw-system` | `node.wind-yaw-system` |
| 传动系统 | `52b0990b`、`5fbd69f` | `asset.wind-drivetrain-system` | `node.wind-drivetrain-system` |
| 刹车系统 | `9331d40`、`828058d` | `asset.wind-brake-system` | `node.wind-brake-system` |

## 二、各筛选文件的显式图元

每份 JSON 只绑定文件中实际出现且名称为“系统”的图元。其他文件中的“控制”图元不因名称相近而复用系统编号。

| 拓扑文件 | 传动系统 `penId` | 刹车系统 `penId` |
| --- | --- | --- |
| 架构层 `architecture` | `eca11c6` | `3518b49` |
| 网络层 `network` | `6d463462`、`7100f20` | `4e4e4b`、`779c4bd9` |
| 业务层 `business` | 无 | 无 |
| 关键环节层 `key-process` | `6bd3ecb9`、`6ae5e42` | `7241f93e`、`3790242` |
| 网络层+业务层 `network-business` | `ec6a59e`、`5d39b66f` | `4a75cf4`、`17d8b5c` |
| 网络层+关键环节层 `network-key-process` | `4d331569`、`82b105` | `777e94bc`、`40eac465` |
| 业务层+关键环节层 `business-key-process` | `8d7675b`、`17cee71` | `ccca65e`、`7e8936` |
| 网络层+业务层+关键环节层 `network-business-key-process` | `52b0990b`、`5fbd69f` | `9331d40`、`828058d` |

变桨系统、变流系统和偏航系统目前只在默认组合文件中有对应系统图元；其余变体中同类位置显示的是控制层节点，因此不登记映射。业务层文件没有这五项名称，不创建占位图元。

## 三、保留的第三层映射

风机和齿轮箱是既有关键环节状态节点，不属于本次清理的第二层控制映射，继续保留：`node.wind-turbine`、`node.wind-gearbox`。风电场景映射清单因此包含五个设备系统目标和这两个第三层目标。

上述编号是前端与 Unity 场景配置的稳定键。它们不代表离线 Unity 工程已经配置或完成双向交互验证。

## 四、偏航系统第三层

`node.wind-yaw-system` 同时是第二层偏航设备的三维节点和偏航第三层目录的状态节点，因此第三层沿用已有目标，不重复扩展 `sceneNodeIds`。第三层公开动作、JSON 图元与共享资源合同见[风电偏航关键环节与合作方入口](风电偏航关键环节与合作方入口.md)；偏航详情内的子设备没有逐项三维绑定。
