# 新版 JSON 拓扑图复刻制作规范

**文档版本：** 1.0  
**编制日期：** 2026-08-29  
**适用对象：** 后续需要按现有新版燃气拓扑效果复刻其他工艺、网络或站房拓扑的开发、设计、联调和验收人员。

> 本文是“按数据交换格式（JSON）原样复刻组态图显示效果”的专项规范。它服务于当前新版燃气拓扑及其后续替换方案，重点是保留原始数据的坐标、尺寸、文字、图元层级、动态图片和筛选逻辑。它不替换原有燃气拓扑的历史制作规范；旧拓扑仍需保持可访问、可联动和可回退。

> **2026-08-30 三层展示边界：** 本规范生成和接入的拓扑仅在第二层厂区“三维与拓扑并存”模式下展示。第一层沙盘和第三层关键环节均为全屏三维，不展示拓扑；进入这两类视图时只停用并隐藏唯一拓扑画布，不销毁或另建画布，返回厂区后恢复进入前的拓扑上下文。

## 一、核心目标和适用边界

### 1.1 核心目标

新拓扑制作的第一目标是：**使用原始组态数据直接得到与源图一致的视觉结果**。

必须优先保证以下内容一致：

1. 图元的二维坐标、宽度、高度、旋转角度和绘制顺序。
2. 图元文字、换行、字号、颜色、对齐方式和文字位置。
3. 连线的起止点、控制点、锚点、箭头、虚实线、颜色和层级顺序。
4. 动态图片格式（GIF）的画面、尺寸、动画和加载时机。
5. 外层区域、中间分组区域、节点和底部流程矩形的相对位置。
6. 图层筛选后各区域、图元、连线和背景框的显隐关系。
7. 设备图元与状态、二维选择、三维场景交互之间的显式绑定。

### 1.2 与旧拓扑规范的关系

当前新图是旧燃气拓扑的替代候选，不是对旧图的覆盖修改。因此：

- 原燃气拓扑入口和原有实现必须继续保留。
- 新图先通过独立预览地址验证，再接入正式总览。
- 新图的视觉规则以源数据为准，不强行套用旧图的节点排列、颜色、字号、层级高度或业务连线。
- 新图的状态接入、二维选择、三维聚焦和双击事件仍必须遵循项目已有的稳定协议。
- 任何未在源数据或正式映射清单中确认的关系，都不得靠标题、坐标、图片名称或数组顺序推断。

### 1.3 当前实现基线

当前新版燃气拓扑的主要入口和资源如下：

| 内容 | 当前地址或文件 | 说明 |
| --- | --- | --- |
| 独立预览地址 | `/gas-topology-json-preview` | 用于直接核对 JSON 原始显示效果和图层筛选。 |
| 原始拓扑数据 | `power-data-web/public/topology/gas-json-preview/topology.json` | 当前预览实际加载的数据交换文件（JSON）。 |
| 动态图片目录 | `power-data-web/public/topology/gas-json-preview/gifs/` | 当前图纸中使用的本地图像资源。 |
| 数据加载器 | `power-data-web/src/modules/visual/topology-preview/gas-topology-preview-data.ts` | 负责加载数据、替换本地图片地址和应用选择规则。 |
| 图层筛选规则 | `power-data-web/src/modules/visual/topology-preview/gas-topology-layer-filter.ts` | 负责区域、图元、连线的层级绑定和显隐判断。 |
| 选择规则 | `power-data-web/src/modules/visual/topology-preview/gas-topology-selection.ts` | 负责区分可选图元与纯背景图元。 |
| 提示规则 | `power-data-web/src/modules/visual/topology-preview/gas-topology-tooltip.ts` | 只为设备图片生成设备提示。 |

当前基线文件包含 102 个图元，其中 44 条连线、34 个图片设备图元、24 个矩形图元。上述数量只是当前数据的核对基线，后续拓扑不得为了“保持数量一致”而补造或删除业务图元。

## 二、数据源和原样还原规则

### 2.1 数据源唯一性

每套新拓扑必须指定唯一的源数据交换文件（JSON）和版本信息。制作过程必须记录：

- 源文件名称和来源时间。
- 源文件版本或哈希值。
- 组态编辑器导出版本。
- 是否包含动态图像、字体、外部图片地址和特殊图元。
- 本地化资源与源地址的对应关系。

收到多个同名数据文件时，必须先确认哪一份是最新且已确认的版本，再复制到项目资源目录。不得把旧文件、临时导出文件和正式文件混用。

### 2.2 必须保留的原始字段

除非经过明确的兼容性处理，以下字段必须原样保留：

- 图元唯一编号 `id`。
- 图元类型 `name`。
- `x`、`y`、`width`、`height`、`rotate`。
- `text`、文字换行和文字相关样式。
- `image`、图片比例和图片显示参数。
- 连线的锚点、控制点、箭头、虚实线和路径字段。
- 背景色、边框色、线宽、透明度和渐变字段。
- 图元在 `pens` 数组中的顺序。
- 数据文件中的缩放倍率 `scale` 及其他画布视图信息。

特别注意：数据交换格式（JSON）中的 `id` 是图元编号（`penId`），不是业务节点编号（`nodeId`），更不是三维模型编号（`sceneNodeId`）。三者必须分开维护。

### 2.3 禁止改变坐标的操作

以下操作会破坏一比一还原，除非源数据本身已被确认修改，否则禁止执行：

1. 按浏览器宽高重新计算每个图元坐标。
2. 把所有图元平移到从零开始的坐标系。
3. 把数据中的 `scale` 强制改为 `1`。
4. 按节点标题重新排序或自动均分节点。
5. 把多段原始连线合并成一条“看起来更短”的连线。
6. 根据节点距离自动补线、删线或改线。
7. 把背景矩形改造成网页组件，再用网页组件替代原始图元。

当前实现允许在加载后清除顶层固定纸张宽高，以便响应式容器铺满背景，但这不等于修改图元坐标。页面应通过网页二维组态引擎（Meta2D）的 `fitView`（适应画布）统一适配，而不是逐个改写图元。

### 2.4 数据加载顺序

推荐使用以下固定顺序：

1. 加载并校验源数据交换文件（JSON）。
2. 校验 `pens` 数组存在、图元编号唯一、坐标和尺寸为有限数字。
3. 按源图片地址精确替换为本地资源地址。
4. 应用背景与设备选择规则。
5. 构建一次图层绑定索引和显隐规则索引。
6. 按默认筛选状态设置每个图元的 `visible`。
7. 创建唯一的 Meta2D 画布实例并打开数据。
8. 等待动态图片加载完成后，再执行一次适应画布。

禁止在每次筛选、状态变化或鼠标移动时重新解析整份 JSON。

## 三、图元分类规则

源图中的矩形不等于设备，图片图元也不等于已经完成业务绑定。每个图元必须先明确视觉职责，再决定筛选、命中、提示和三维行为。

| 图元类别 | 视觉职责 | 是否允许选中 | 是否显示设备提示 | 是否参与三维设备联动 |
| --- | --- | --- | --- | --- |
| 最外层边界框 | 表示整体架构范围 | 否 | 否 | 否 |
| 区域边界框 | 表示企业办公网、工业非军事区、监控层等层级范围 | 否 | 否 | 否 |
| 中间分组矩形 | 只用于视觉分组和区域背景 | 否 | 否 | 否 |
| 图片设备图元 | 表示设备、工作站、服务器或工艺设备 | 是 | 是，但必须有有效设备文字 | 只有正式登记后才允许 |
| 底部工艺流程小矩形 | 表示工艺流程节点和关系 | 是 | 否；它们是工艺，不是设备 | 否，除非另有正式业务定义 |
| 连线 | 表示拓扑关系或工艺关系 | 否 | 否 | 否 |
| 运行时状态图元 | 表示设备实时状态的叠加效果 | 否 | 否 | 不得单独作为业务节点 |

### 3.1 背景图元的处理

最外层矩形、区域矩形、中间分组矩形和区域文字都属于背景。背景只负责构图和分组：

- 不进入鼠标悬停提示。
- 不进入设备选择。
- 不产生三维聚焦。
- 不产生设备双击事件。
- 不因加锁而改变其原始视觉样式。
- 隐藏时必须连同其承担的区域连线一并隐藏。

### 3.2 底部工艺流程矩形的处理

底部工艺流程中的小矩形是当前规则中的特殊可选图元：

- 允许保留组态引擎的只读选中框。
- 不显示设备悬浮弹窗。
- 不叠加设备状态圆点或设备状态滤镜。
- 不发送设备三维聚焦命令。
- 不发送设备双击事件，除非业务清单另行明确其为正式业务节点。
- 只受业务层控制，并与工艺流程内部虚线同步显隐。

## 四、图层筛选规范（核心）

图层筛选不是装饰性工具栏，而是新拓扑的核心数据模型。区域边框、内部节点、跨区域连线和工艺虚线必须绑定到筛选层，用户取消某一层时，该层负责的全部内容必须同步隐藏。

### 4.1 筛选栏只显示四个顶层复选框

当前界面只显示以下四项，不展开企业办公网、工业非军事区、监控层等子区域复选框：

| 复选框 | 稳定编号 | 当前含义 |
| --- | --- | --- |
| 架构层 | `architecture` | 网络层、物理层、业务层全部选中时的“全选”聚合状态，不是独立内容层。 |
| 网络层 | `network` | 企业办公网、工业非军事区、监控层及现场控制与保护区中的网络相关内容。 |
| 物理层 | `physical` | 现场控制与保护区及现场设备中的物理相关内容。 |
| 业务层 | `business` | 底部工艺流程及工艺流程内部关系。 |

子区域名称可以作为图元文字或内部绑定说明存在，但不得在筛选栏额外生成可勾选项。这样可以保证筛选栏结构固定，也避免后续数据换名导致页面状态协议变化。

### 4.2 架构层的真实语义

架构层必须按以下规则实现：

1. 初始状态：网络层、物理层、业务层全部选中，架构层显示为选中。
2. 点击架构层选中：同时选中网络层、物理层和业务层。
3. 点击架构层取消：同时取消网络层、物理层和业务层。
4. 单独取消任意一个内容层：架构层立即取消选中。
5. 三个内容层重新全部选中：架构层自动恢复选中。
6. 架构层不是独立的业务内容，不能因为它被选中就永久放行一个本应被网络层、物理层或业务层控制的图元。

实现时可以保留 `architecture` 作为快捷状态或兼容标签，但制作人员不得把它当作第四个独立内容层给设备、区域或连线分配业务归属。

### 4.3 区域绑定矩阵

当前新版燃气拓扑采用以下区域归属：

| 区域或背景框 | 绑定层 | 可见条件 |
| --- | --- | --- |
| 企业办公网 | 网络层 | 网络层开启。 |
| 工业非军事区 | 网络层 | 网络层开启。 |
| 监控层 | 网络层 | 网络层开启。 |
| 现场控制与保护区 | 网络层、物理层 | 网络层或物理层任一开启。 |
| 现场设备 | 物理层 | 物理层开启。 |
| 工艺流程 | 业务层 | 业务层开启。 |
| 纯整体装饰边界 | 架构聚合状态 | 三个内容层全选时显示；任一内容层关闭时隐藏。 |

区域边框不能只按文字标题匹配。当前燃气图使用源数据中的固定图元编号登记区域；后续拓扑也必须建立本图专属的编号清单。

### 4.4 连线绑定矩阵

连线必须按业务语义分类，而不能只按几何位置自动判断。当前新版燃气拓扑的规则如下：

| 连线类型 | 绑定层 | 可见条件 |
| --- | --- | --- |
| 监控层上下沿到现场控制与保护区的过渡线 | 仅网络层 | 网络层开启。 |
| 监控设备到现场控制站群的跨区折线路径 | 仅网络层 | 网络层开启。 |
| 现场控制与保护区到现场设备的竖向连接 | 仅物理层 | 物理层开启。 |
| 现场设备到工艺流程的连接 | 物理层、业务层 | 物理层和业务层同时开启。 |
| 工艺流程内部虚线 | 仅业务层 | 业务层开启；物理层关闭不影响它。 |
| 尚未确认归属的连线 | 必须待确认 | 禁止默认为网络层或物理层。 |

这组规则直接对应用户已确认的筛选行为：

- 网络层关闭、物理层和业务层开启时：监控层边框、监控区域节点、监控相关连线全部隐藏；现场控制与保护区、现场设备和工艺流程仍按各自规则显示。
- 物理层关闭、网络层和业务层开启时：工艺流程内部虚线继续显示；现场控制到现场设备的物理连线隐藏；现场设备到工艺流程的连接因缺少物理层而隐藏。
- 网络层和物理层同时关闭、业务层开启时：现场控制与保护区也隐藏，只保留工艺流程和业务层关系。
- 三个内容层全部选中时：架构层恢复选中，整张图显示。

### 4.5 显隐逻辑的实现要求

图层绑定索引必须在数据加载后构建一次，后续显隐判断只读取索引：

- 普通图元：所属层任一开启即可显示，即“或”关系。
- 特殊跨层连线：使用显式必选层集合，即“且”关系。
- 没有任何业务层标签的纯架构装饰：只在架构聚合状态有效时显示。
- 隐藏图元不得参与绘制、悬浮、点击和选中命中。
- 筛选切换不能修改坐标、尺寸、文字、连线路径或业务映射。

推荐保留类似以下的规则表达：

```ts
/**
 * 普通图元使用 tags（所属层）判断“任一层开启即可显示”；
 * 跨层连线使用 requiredFilterIds（必选层）判断“全部层开启才显示”。
 * 这样能明确表达现场设备到工艺流程连接的物理层与业务层双重依赖。
 */
interface VisibilityRule {
  tags: readonly FilterId[]
  requiredFilterIds?: readonly FilterId[]
}
```

### 4.6 相邻区域和浮点坐标

相邻区域的边界通常来自浮点计算，两个看似相邻的区域可能出现极小数值误差。制作时必须：

1. 采用统一的极小容差比较边界。
2. 防止监控层因与现场控制与保护区存在微小重叠而误绑定到物理层。
3. 对跨区域折线建立显式编号覆盖规则，不依赖矩形交集自动推断。
4. 为每个相邻边界和跨区域连线增加回归测试。

当前实现使用 `1e-6` 级别容差，并对跨区线段建立固定编号集合。后续拓扑必须按自身坐标精度重新验证，不能机械复制容差或编号。

## 五、图元选中、悬浮提示和状态显示

### 5.1 选中规则

选中规则与图层筛选规则相互独立：一个图元可以属于某个可见层，但仍然不能被选中。

当前基线只允许以下对象命中：

- 带图片地址的设备图元。
- 工艺流程区域内、尺寸明显小于外层流程框且带业务文字的底部小矩形。

以下对象必须禁用命中：

- 最外层边界框。
- 企业办公网、工业非军事区、监控层、现场控制与保护区、现场设备和工艺流程的区域外框。
- 主控监控、辅控监控、主控控制站群等中间分组框。
- 所有连线。
- 区域标题和纯说明文字。
- 运行时追加的状态图元。

网页二维组态引擎（Meta2D）中，推荐使用“可选对象只读锁定、背景对象完全禁用”的两档锁定策略。禁止用可见的透明矩形覆盖背景来阻止命中，因为透明覆盖仍可能影响连线、悬浮和画布事件。

### 5.2 悬浮提示规则

设备提示必须复用原拓扑的“标题 + 状态”结构：

- 只为设备图片生成提示。
- 工艺流程矩形不显示设备弹窗。
- 背景框、分组框和连线不显示提示。
- 标题只清理用于绘图的换行和重复空格，不擅自改写业务名称。
- 独立预览无实时状态时使用明确的默认展示状态。
- 正式运行时使用平台下发的四态状态：正常、告警、故障、离线。
- 提示层使用单一实例，避免每个图元创建常驻网页节点。
- 提示锚点必须限制在画布安全区域内，不能跑出画布或遮挡关键内容。

### 5.3 状态显示规则

设备状态必须与选中状态分离：

- 状态只允许正常、告警、故障、离线四种互斥值。
- 状态变化只更新对应设备的显示和必要状态叠加，不重建整个拓扑。
- 运行时追加的状态点必须禁用命中，不能变成第二个设备节点。
- 状态点必须继承源设备所属图层；设备被筛选隐藏时，状态点同步隐藏。
- 没有正式状态数据时，不得把所有设备伪造为实时正常。
- 没有正式三维映射时，不得根据设备标题猜测三维对象。

## 六、动态图像和图标资源规范

### 6.1 图片地址必须精确映射

源图中的图片地址可能来自另一套组态服务。当前实现按照“源地址 → 本地资源”的精确映射替换，禁止使用以下方式猜图：

- 根据中文标题猜图标。
- 根据图片文件名中的相似词猜图标。
- 根据图元坐标推断设备类型。
- 用一个通用图标替换所有缺失设备而不记录依据。
- 在渲染时直接依赖不可控的远程资源地址。

### 6.2 资源落地要求

每套拓扑应建立独立资源目录，例如：

```text
public/topology/<拓扑资源键>/
├─ topology.json
└─ gifs/
   ├─ <设备资源一>.gif
   └─ <设备资源二>.gif
```

资源处理规则：

1. 开发阶段可以依据源地址获取用户提供的动态图片。
2. 进入项目后必须落地为本地受控资源，避免运行时依赖外部服务。
3. 数据加载器中必须保留源地址映射表，便于复核和后续替换。
4. 图片地址应经过项目基础路径拼接，保证部署到子目录后仍能加载。
5. 图片请求失败时必须有结构化错误或明确的缺失资源状态，不能静默替换成错误设备图标。
6. 动态图片加载完成后再执行一次适应画布，防止图片尚未参与边界计算导致整图位置或缩放错误。

### 6.3 缺失图元处理

如果本地图标目录中不存在合适资源：

- 优先从用户提供的 GIF 包或当前项目受控图标目录中选择。
- 必须记录选择的源地址、目标资源、适用设备和确认依据。
- 不得为了“看起来像”而使用语义明显错误的图标。
- 如果只能使用临时占位图，必须标记为待替换，不得直接视为正式资源。

## 七、二维与三维交互接入规范

新版拓扑的显示效果可以与源 JSON 完全一致，但交互关联必须通过稳定标识显式完成。

### 7.1 标识职责

| 标识 | 所属层 | 用途 | 禁止做法 |
| --- | --- | --- | --- |
| `penId` | JSON 图元 | 定位源图元和执行显隐 | 不得当作业务节点编号直接发给平台。 |
| `nodeId` | 业务拓扑清单 | 二维选择、状态和双击协议 | 不得根据标题、坐标或图片地址自动生成。 |
| `sceneNodeId` | 三维映射清单 | 三维聚焦、状态同步和反向选择 | 不得使用 Unity 层级路径或模型显示名替代。 |
| `deviceId` | 平台内部 | 平台内部设备绑定 | 不进入我方拓扑 JSON、前端状态和跨窗口消息。 |

新版 JSON 图元与正式业务节点之间必须维护独立的绑定表，例如当前实现的 `gas-topology-runtime-bindings.ts`。一个正式节点可以对应多个视觉图元，但每个绑定都必须逐项确认。

### 7.2 单击

1. 单击设备图片后立即更新二维选中状态。
2. 有正式 `nodeId` 和 `sceneNodeId` 时，向三维场景发送聚焦请求。
3. 没有三维映射时保留二维选择，但必须清除上一个设备遗留的三维选中效果。
4. 点击背景、连线或工艺矩形时，不得伪造设备节点；需要时只执行清除选择。
5. 隐藏图元不得被点击命中。

### 7.3 双击

1. 只有正式绑定的设备图元允许发送节点双击事件。
2. 发送内容使用 `nodeId`，不发送 `penId`、设备名称或三维层级路径。
3. 背景、分组框、连线和工艺流程矩形默认不发送设备双击事件。
4. 双击不能重复发送一次无意义的三维聚焦命令。
5. 未登记的图元双击必须安全忽略，不能按相似标题补发事件。

### 7.4 正式运行与独立预览的区别

| 能力 | 独立 JSON 预览 | 正式运行画布 |
| --- | --- | --- |
| 图纸显示 | 使用当前本地 JSON 和资源 | 使用同一套 JSON 视觉数据。 |
| 图层筛选 | 支持四个顶层复选框 | 支持同一套筛选逻辑。 |
| 设备状态 | 无外部实时状态时使用预览基线 | 使用平台下发的四态状态。 |
| 二维选择 | 用于查看可选图元 | 同步外层选择状态。 |
| 三维聚焦 | 不执行正式三维命令 | 按显式 `nodeId`、`sceneNodeId` 绑定执行。 |
| 原燃气拓扑 | 通过返回入口保留 | 原正式拓扑仍可回退。 |

## 八、组件和运行时实现边界

### 8.1 唯一画布实例

同一时刻只允许保留一份活动画布：

- 图层筛选只更新当前画布图元的显隐。
- 状态更新只更新目标设备和状态叠加图元。
- 缩放和平移只更新画布视图变换。
- 容器大小变化只重设当前画布尺寸并重绘。
- 厂区内切换业务拓扑时复用同一活动画布，并释放上一拓扑专属的图片缓存和事件监听；不得销毁后另建宿主画布。
- 禁止为每个筛选层、每个设备或每个拓扑创建隐藏画布。

### 8.2 Meta2D 显隐更新要求

网页二维组态引擎（Meta2D）修改图元显隐时，必须使用其专用的 `setVisible`（设置显隐）接口，再统一调用一次 `render`（重绘）。不能只直接写入 `pen.visible` 或逐个使用会触发多次重绘的通用更新接口。

原因是专用接口还会同步：

- `calculative.visible` 等内部计算状态。
- 图片画布缓存。
- 子图元显隐状态。
- 当前图元的重绘标记和命中计算状态。

筛选热路径应只处理实际发生变化的图元，避免每次切换都重复初始化全部图片缓存。

### 8.3 事件和资源释放

组件确实销毁或厂区内切换业务拓扑资源时必须：

- 取消数据请求。
- 断开尺寸观察器（`ResizeObserver`）。
- 取消未执行的动画帧回调。
- 移除悬浮、点击和双击事件监听。
- 组件确实销毁时调用画布销毁接口释放多层画布和动态图像对象；仅进入沙盘或关键环节时不得销毁画布，应停用输入、布局和重绘后隐藏。
- 清理当前提示、选中状态和临时状态叠加。

任何筛选切换、状态更新或窗口尺寸变化都不得累积事件监听器或动画帧回调。

## 九、性能规范

在保持视觉和交互完整的前提下，必须满足以下要求：

1. 图层索引、显隐规则索引和运行时绑定索引只构建一次。
2. 显隐判断使用图元编号直接查找，不能在每次鼠标移动时扫描标题。
3. 选择变化不重建 JSON、不重新下载 GIF、不重建画布。
4. 状态变化只更新差异设备，不重建整图布局。
5. 筛选切换只对显隐字段发生变化的图元调用专用显隐接口。
6. 最终只触发一次统一重绘。
7. 尺寸变化合并到下一动画帧执行，避免连续触发多次适配。
8. 图片缓存必须受控，同一资源地址不能重复加载。
9. 禁止使用嵌套全量扫描实现每帧连线碰撞或图层判断。
10. 不得以牺牲图层筛选正确性为代价减少图元数量。

## 十一、后续复刻一套新拓扑的制作流程

### 阶段一：准备数据

1. 获取最新且已确认的源数据交换文件（JSON）。
2. 保存源文件版本、哈希值和导出工具版本。
3. 清点图元、连线、图片、矩形、文字和特殊图元。
4. 逐项确认区域边界和区域业务语义。
5. 逐项确认每条跨区域连线的归属层。

### 阶段二：准备资源

1. 建立该拓扑独立的资源目录。
2. 收集并落地源图使用的 GIF、SVG（可缩放矢量图形）或其他受控图片。
3. 建立源图片地址到本地资源的精确映射表。
4. 检查动画图片在本地开发服务器和生产构建后的地址都可访问。

### 阶段三：建立图层清单

至少提交以下三份清单：

1. 区域框清单：区域图元编号、区域名称、绑定层。
2. 特殊连线清单：连线编号、业务语义、绑定层、是否需要多层同时开启。
3. 设备绑定清单：图片图元编号、`nodeId`、可选 `sceneNodeId`、状态能力和双击能力。

清单必须使用稳定编号，不能只写中文名称。中文名称可作为人工核对字段，但不能作为运行时主键。

### 阶段四：接入画布

1. 复用当前数据加载、图层筛选、选择策略和运行时画布结构。
2. 替换该拓扑专属的数据文件、资源映射、区域编号和特殊连线编号。
3. 不复制旧燃气的业务节点名称、业务映射、坐标和三维模型编号。
4. 在独立预览地址先完成视觉和筛选验收。
5. 再通过正式面板的稳定画布控制器接入状态和三维交互。

### 阶段五：回归和交付

1. 先跑图层筛选专项测试。
2. 再跑选择、提示和运行时绑定测试。
3. 执行类型检查、全量单元测试和生产构建。
4. 浏览器逐项执行筛选矩阵和悬浮命中检查。
5. 保存默认全选、网络层关闭、物理层关闭、业务层关闭四张验收截图。
6. 确认旧燃气拓扑仍可访问、状态和三维联动未被破坏。

## 十三、禁止事项总表

1. 禁止把架构层当成独立的第四个业务层。
2. 禁止在筛选栏额外暴露未确认的子区域复选框。
3. 禁止只隐藏区域框而保留该区域负责的连线。
4. 禁止只按矩形交集推断跨区域连线归属。
5. 禁止用标题、坐标、数组顺序或图片名称猜测业务和三维映射。
6. 禁止把背景框、分组框、连线或工艺矩形当作设备弹窗对象。
7. 禁止直接写 `visible` 后不使用 Meta2D 专用显隐同步接口。
8. 禁止筛选切换时重建画布、重复加载 GIF 或新增常驻监听器。
9. 禁止为了布局好看修改源 JSON 的节点坐标、文字和连线关系。
10. 禁止把远程图片地址作为生产环境唯一资源来源。
11. 禁止把平台内部 `deviceId` 写入我方拓扑数据或跨窗口消息。
12. 禁止用新拓扑替换旧拓扑文件或删除旧拓扑入口。
13. 禁止没有专项筛选测试和浏览器验收就接入正式总览。

**本规范的判断顺序：先确认源数据，再确认图元职责，再建立图层绑定，最后接入状态和三维交互。任何一步未确认，都不得通过猜测补齐。**
