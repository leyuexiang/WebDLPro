# 微电网、配电站与楼宇拓扑接入设计

## 1. 目标与范围

为微电网、配电站、楼宇三个新业务场景接入用户提供的完整拓扑输入文件。每场景含架构、网络、业务、关键环节四个单层文件，以及网络+关键环节、网络+业务、业务+关键环节和默认全层四个组合文件，共 24 份。各文件独立加载，不在运行时合并。

画布、筛选状态机、文件切换、选择提示、画布暂停和视口控制复用现有清单式预览组件。图元图片只能引用 `public/topology/shared/` 下的公共资源，不在场景目录复制图像。

本接入只登记二维图元的本地可选行为。尚无经过确认的 Unity（统一引擎）节点绑定及设备实时状态映射，不生成 `nodeId`、`sceneNodeId` 或虚构状态。

## 2. 数据布局与来源

每个场景使用独立预览数据目录，目录中只包含各变体的 `topology.json`：

```text
power-data-web/public/topology/<scene-id>-json-preview/variants/<combination-key>/topology.json
```

场景键固定为 `microgrid`、`distribution`、`consumption`；组合键固定为 `architecture`、`network`、`business`、`key-process`、`network-key-process`、`network-business`、`business-key-process`、`network-business-key-process`。默认项显式登记为 `network-business-key-process`。

变体清单按文件登记源文件散列（SHA-256）、图元数、运行时图元数、需移除的全画布组合父级及其直接子图元数、关键环节可选图元编号。输入来源的原始散列和图元数由专项契约测试单独校验，避免清单自身出错时失去第二份校验事实。

## 3. 运行时数据流

1. `TopologyPanel.vue` 根据三个正式总览拓扑稳定键解析场景，不使用页面标题或拓扑文字推断。
2. `BusinessSceneTopologyJsonPreview.vue` 持有窄画布接口，转交公共 `ManifestTopologyJsonPreview.vue`。
3. 场景 profile（预览配置）用稳定筛选集合生成组合键，并从预建索引找到唯一完整 JSON 文件。
4. 数据模块按“场景/变体”缓存经净化的不可变原始数据；每次装载都克隆副本，在副本上做坐标展平、公共图片地址解析和选择策略设置。
5. 当前二维画布提交目标文件。新请求使用取消信号；旧文件请求、图片和选择状态不能覆盖最后一次有效选择。

模拟、外部网络和启动脚本入口在缓存前关闭或清空。引擎运行时对象不进入原始缓存。组合索引和清单索引只在模块初始化时构建。

## 4. 全画布组合父级处理

输入文件带有 1 至 4 层铺满整张画布的 `combine` 父级。保留该父级会导致点击命中落在整图容器上，独立设备或工艺项无法被可靠选择。清单显式列出每份文件中确认属于整图容器的父级编号和直接子项数；不依据尺寸、标题或层级自动猜测。

装载副本时从最外层开始逐级换算直接子项矩形：

```text
child.x      = parent.x + child.x * parent.width
child.y      = parent.y + child.y * parent.height
child.width  = child.width * parent.width
child.height = child.height * parent.height
```

处理后移除该层的 `parentId`，递归处理登记的下一层父级，再从运行时列表滤除已展平父级。未登记的局部组合保持父子关系和局部坐标。输入缓存及文件内容不被修改。

专项测试逐个比较所有保留图元变换前后的世界矩形，并检查唯一根父级、登记父级可达性、父级直接子项数量、最终 pen 数及工艺图元编号。

## 5. 公共图片与预览状态

输入引用的图片统一映射到既有公共资源。当前映射按图元编号和已审阅业务语义静态写入各 JSON，不在运行时根据外部 URL、文字或文件名猜测：

| 图元类别 | 公共资源示例 |
| --- | --- |
| 工商业系统与平台 | `assets/enterprise-system.png` |
| 服务器与数据库 | `assets/data-server.png`、`assets/database.png` |
| 操作台、值班员 | `assets/operator.png`、`assets/workstation.png` |
| 控制器和能源设备 | 对应 `icons/normal/` 公共图元 |
| 区域底图和流光 | `background/flow-light-3.png` |

运行时路径仅接受 `assets/`、`background/`、`icons/` 下的相对路径，并通过 `topology-shared-assets.ts` 解析到共享目录；远端 URL 和目录上溯均拒绝。场景 JSON 不携带自有图片文件。

这三个场景当前没有外部设备状态映射，因此公共设备图片作为预览默认图显示，并统一提示“预览默认态”。这不代表真实设备正常态已完成接入，也不生成告警、故障或离线状态图。

## 6. 选择、连线与三维边界

区域背景、组合父级和连线不拦截命中；带公共设备图的图元及清单登记的工艺矩形可单独二维选中。选中只提供预览局部交互，不触发猜测的三维节点聚焦。

输入 JSON 中有 859 项 `connectedLines` 连接引用，其中 119 项在同一输入文件找不到对应连线编号。该比例和编号均来自用户提供的源文件。导入和预览保留原始连接字段，不臆造或跨文件拼接线条；既有公共高亮实现只对当前文件中实际存在的连线编号建立高亮关系。

需要真实二维—三维联动或设备状态时，必须先从 Unity 场景资产及业务映射确认稳定 `nodeId`、`sceneNodeId` 和状态源，再通过显式文件级映射接入。缺少这些证据时维持二维预览能力。

## 7. 验证要求

- 三个场景各 8 个文件均存在，哈希、源图元数、路径、唯一 ID、有限几何数值及引用的公共图片均满足专项契约。
- 所有组合过滤只解析独立文件，默认集合和架构互斥规则正确。
- 每份输入中整图组合父级都按清单安全展平，坐标世界位置保持一致，局部组合不被误拆。
- 公共画布复用；未登记拓扑键不进入新场景预览。
- 本地预览包通过自测页和发布产物门禁后，逐个检查三个场景默认组合及筛选切换、图片请求和控制台。
