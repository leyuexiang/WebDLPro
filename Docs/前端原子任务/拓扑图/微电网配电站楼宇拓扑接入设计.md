# 微电网、配电站与楼宇拓扑接入设计

## 1. 目标与范围

为微电网、配电站、楼宇三个新业务场景接入用户提供的完整拓扑输入文件。每场景含架构、网络、业务、关键环节四个单层文件，以及网络+关键环节、网络+业务、业务+关键环节和默认全层四个组合文件，共 24 份。各文件独立加载，不在运行时合并。

画布、筛选状态机、文件切换、选择提示、画布暂停和视口控制复用现有清单式预览组件。图元图片只能引用 `public/topology/shared/` 下的公共资源，不在场景目录复制图像。

微电网仍只登记二维图元的本地可选行为。配电站按用户最新截图登记保护装置、测控装置、配电变压器、断路器、互感器五组二维—三维稳定编号；楼宇登记暖通空调、门禁、智能照明三组编号。配电站编号是供用户后续统一引擎（Unity）配置的目标约定，不表示离线 Unity 工程中的对象已经创建或验证。三个场景都没有接入设备实时状态源，不生成虚构状态。

## 2. 数据布局与来源

每个场景使用独立预览数据目录，目录中只包含各变体的 `topology.json`：

```text
power-data-web/public/topology/<scene-id>-json-preview/variants/<combination-key>/topology.json
```

场景键固定为 `microgrid`、`distribution`、`consumption`；组合键固定为 `architecture`、`network`、`business`、`key-process`、`network-key-process`、`network-business`、`business-key-process`、`network-business-key-process`。默认项显式登记为 `network-business-key-process`。

变体清单按文件登记源文件散列（SHA-256）、图元数、运行时图元数、需移除的全画布组合父级及其直接子图元数、关键环节可选图元编号。输入来源的原始散列和图元数由专项契约测试单独校验，避免清单自身出错时失去第二份校验事实。

## 3. 运行时数据流

1. `TopologyPanel.vue` 根据三个正式总览拓扑稳定键解析场景，不使用页面标题或拓扑文字推断。
2. `BusinessSceneTopologyJsonPreview.vue` 持有窄画布接口，转交公共 `ManifestTopologyJsonPreview.vue`。
3. 场景 profile（预览配置）用稳定筛选集合生成组合键，并从预建索引找到唯一完整 JSON 文件。
4. 数据模块按“场景/变体”缓存经净化的不可变原始数据；每次装载都克隆副本，在副本上做坐标展平、公共图片地址解析和选择策略设置。
5. 当前二维画布提交目标文件。新请求使用取消信号；旧文件请求、图片和选择状态不能覆盖最后一次有效选择。

模拟、外部网络和启动脚本入口在缓存前关闭或清空。引擎运行时对象不进入原始缓存。组合索引和清单索引只在模块初始化时构建。

## 4. 全画布组合父级处理

大多数输入文件带有铺满整张画布的 `combine` 父级。保留该父级会导致点击命中落在整图容器上，独立设备或工艺项无法被可靠选择。清单显式列出每份文件中确认属于整图容器的父级编号和直接子项数；不依据尺寸、标题或层级自动猜测。最新楼宇默认组合有 48 个平铺图元且没有组合或父级，清单登记零个展平父级后按原坐标加载；其他组合文件继续执行原有的父级校验与坐标换算。

装载副本时从最外层开始逐级换算直接子项矩形：

```text
child.x      = parent.x + child.x * parent.width
child.y      = parent.y + child.y * parent.height
child.width  = child.width * parent.width
child.height = child.height * parent.height
```

处理后移除该层的 `parentId`，递归处理登记的下一层父级，再从运行时列表滤除已展平父级。未登记的局部组合保持父子关系和局部坐标。输入缓存及文件内容不被修改。

专项测试逐个比较所有保留图元变换前后的世界矩形，并检查唯一根父级、登记父级可达性、父级直接子项数量、最终 pen 数及工艺图元编号。

## 5. 公共图片与预览状态

输入引用的图片统一映射到既有公共资源。当前映射按图元编号和已审阅业务语义静态写入各 JSON，不在运行时根据外部 URL、文字或文件名猜测：

| 图元类别 | 公共资源示例 |
| --- | --- |
| 工商业系统与平台 | `icons/normal/desktop.webp` |
| 服务器与数据库 | `icons/normal/server.webp` |
| 操作台、值班员 | `icons/normal/office.webp` |
| 配电站五类目标设备 | `icons/normal/protection-device.webp`、`icons/normal/measurement-device.webp`、`icons/normal/distribution-transformer.webp`、`icons/normal/distribution-breaker.webp`、`icons/normal/instrument-transformer.webp` |
| 控制器和能源设备 | 对应 `icons/normal/*.webp` 公共图元 |
| 区域底图和流光 | 对应 `background/*.webp` 公共底图 |

配电站最新默认组合直接引用 `icons/` 和 `background/` 下的网页图片格式（WebP），其他历史图元键也由 `topology-shared-assets.ts` 解析到共享 WebP；远端 URL 和目录上溯均拒绝。场景 JSON 不携带自有图片文件，公共资源目录不保留历史 PNG。

这三个场景当前没有外部设备状态映射，因此公共设备图片作为预览默认图显示，并统一提示“预览默认态”。这不代表真实设备正常态已完成接入，也不生成告警、故障或离线状态图。

## 6. 选择、连线与三维边界

区域背景、组合父级和连线不拦截命中；带公共设备图的图元及清单登记的工艺矩形可单独二维选中。配电站和楼宇设备图元通过逐文件 `penId → nodeId → sceneNodeId` 映射接入统一选择协调器，二维选中可请求三维聚焦，三维对象选择可反选对应二维图元。配电站默认组合的左右重复设备图元绑定到同一业务编号，编号约定如下：

| 截图节点 | 前端业务节点编号（`nodeId`） | Unity 目标节点编号（`sceneNodeId`） | 默认组合图元编号（`penId`） |
| --- | --- | --- | --- |
| 保护装置 | `asset.distribution-protection` | `node.distribution-protection` | `1406260e`、`1508d7f` |
| 测控装置 | `asset.distribution-measurement` | `node.distribution-measurement` | `175412f5`、`99f85e3` |
| 配电变压器 | `asset.distribution-transformer` | `node.distribution-transformer` | `6db2600f`、`cb0cbf4` |
| 断路器 | `asset.distribution-breaker` | `node.distribution-breaker` | `a1a5b54`、`4f0d6e4a` |
| 互感器 | `asset.distribution-instrument-transformer` | `node.distribution-instrument-transformer` | `c1499f9`、`67b16fb` |

以上 Unity 编号以本次截图节点命名和前端映射规范为依据，供后续离线 Unity 配置；本次不读取或修改 Unity 场景。配置完成后，三维聚焦和反选才会实际命中对象。楼宇编号见[楼宇拓扑三节点三维映射约定](楼宇拓扑三节点三维映射约定.md)。

当前 24 份输入 JSON 共含 845 项 `connectedLines` 连接引用，其中 120 项在同一输入文件找不到对应连线编号。该数量随配电站默认组合替换后重新统计；导入和预览保留原始连接字段，不臆造或跨文件拼接线条；既有公共高亮实现只对当前文件中实际存在的连线编号建立高亮关系。

合作方结构清单生成器同步发布配电站五个及楼宇三个稳定业务编号和三维目标编号；发布门禁会核对节点映射与 `sceneNodeIds` 完全一致。配电站目标编号只约定前端契约，Unity 场景配置由用户后续完成。状态映射仍需后续提供真实状态源后单独接入。

## 7. 验证要求

- 三个场景各 8 个文件均存在，哈希、源图元数、路径、唯一 ID、有限几何数值及引用的公共图片均满足专项契约。
- 所有组合过滤只解析独立文件，默认集合和架构互斥规则正确。
- 每份输入中整图组合父级都按清单安全展平，坐标世界位置保持一致，局部组合不被误拆。
- 配电站最新默认组合为 85 个无全图组合包装的图元，坐标保持源文件值；五类目标设备共十个重复图元分别指向同一组五个业务节点及 Unity 目标编号。
- 配电站默认组合所有图片均直接引用共享 WebP，且联合发布清单的五个目标编号与前端点击绑定一致；该合同不代替后续 Unity 工程配置。
- 楼宇默认组合的 48 个平铺图元保持源坐标；三项设备图元逐文件映射且合作方结构清单登记同一组三维目标编号。
- 公共画布复用；未登记拓扑键不进入新场景预览。
- 本地预览包通过自测页和发布产物门禁后，逐个检查三个场景默认组合及筛选切换、图片请求和控制台。
