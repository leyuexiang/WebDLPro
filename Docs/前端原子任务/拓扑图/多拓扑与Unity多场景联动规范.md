# 多拓扑与 Unity 多场景联动规范

## 一、稳定上下文

运行时只维护一个已提交上下文：场景、视图模式、第二层拓扑或第三层关键环节、结构版本和上下文修订号。任何二维选择、三维事件和状态同步都必须先核对当前上下文。

## 二、二维选择到三维

1. 二维节点立即进入本地选中和连线高亮。
2. 节点存在显式 `sceneNodeId` 且当前场景声明聚焦能力时，发送 `focusNode`。
3. 无映射节点只保持二维选择，不发送三维命令。
4. 三维失败不得伪造成功，二维选择按产品契约保留并输出固定诊断。

## 三、三维反向选择

1. Unity 只上报当前场景已登记的下层 `sceneNodeId`。
2. 前端通过当前场景唯一反向索引解析 `nodeId`。
3. 反选复用二维选择与连线高亮函数，不再回发 `focusNode`，避免循环。
4. 旧场景、旧实例、未知映射和迟到事件全部丢弃。

## 四、清除选择

点击空白、地面或未映射对象时，Unity 发送 `selectionCleared`。前端清除二维节点与连线高亮，不执行场景复位。`resetCamera`、`resetScene` 和清除选择具有不同语义，禁止混用。

## 五、设备状态

外层完整状态快照先提交二维中央缓存，再按当前场景映射生成三维状态命令。三维同步属于尽力执行，不得反向污染二维权威快照。缺失节点执行清除状态，不推断为离线。

## 六、场景与拓扑切换

- 跨场景：加载目标 Unity 场景成功后，再提交目标二维拓扑和稳定上下文。
- 第二层组合切换：保持场景不变，只替换完整拓扑文件和文件级绑定。
- 进入第三层：准备并提交精细三维资源，同时加载 `topologyDataContextId` 对应的唯一完整拓扑，隐藏筛选轨。
- 退出第三层：释放精细资源，恢复第二层场景、进入前组合文件、选择和最新状态。

全过程复用单 Unity 实例和单拓扑画布。

## 七、并发与失败

快速动作、场景加载和拓扑请求均使用单调事务编号。旧事务被取代后，其回执、事件和资源加载结果不得提交。任何失败都保留或恢复最后稳定上下文，不能形成二维/三维错配。

## 八、能力边界

Unity 全局桥接能识别命令，不证明当前业务场景支持。发送前必须同时检查场景目录声明、适配器运行时能力和序列化前置条件。未登记节点、路线、命名镜头或第三层资源不得在运行时猜测或降级伪造。

## 九、验证矩阵

至少覆盖：二维有映射/无映射节点、三维反选、空白清除、完整状态与状态清除、第二层组合切换、第三层进入/直接切换/退出、快速取代、加载失败、超时、迟到事件、场景释放和监听器清理。
