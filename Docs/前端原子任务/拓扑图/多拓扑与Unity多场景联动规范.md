# 多拓扑与 Unity 多场景联动规范

**适用范围：** 九个 Unity 业务场景、全部二维拓扑、外部父页面动作和节点事件。

**依赖规范：** [拓扑容器与多图切换规范](拓扑容器与多图切换规范.md)、[图元与设备状态规范](图元与设备状态规范.md)、[场景拓扑动作映射规范](../场景拓扑动作映射规范.md)。

**视觉边界：** 二维拓扑的深色分层、状态图元、选中描边、协议标签、文字避让、常规态同宽和全屏自适应，统一采用前述容器规范的已确认制作基线；本规范只定义已显式登记的二维选择、三维聚焦和状态同步，不把视觉相似、同名模型或坐标邻近视为映射依据。

**当前联动基线：** `Builds/Releases/燃气发电场景与拓扑图联动包0813`。包内 `gas-power-platform-release-5550-20260813-2015` 是发布识别值；内部验证包和早期端口包只作历史证据。

> **2026-08-14 节点协议修正：** 平台不向我方注入设备编号；双击、状态和三维反向选择统一以 `nodeId` 关联。平台内部自行维护 `nodeId → 真实设备编号`。

---

## 一、联动边界

1. 外部父页面、当前子应用、Unity 和拓扑之间的所有动作必须经过唯一联动协调器。
2. 外部父页面只使用 `sceneId`、`topologyId` 和 `actionId`，不得直接调用 Unity。
3. Unity 只接收当前子应用内部 `power3d-unity` 协议，不接收外层 `power-scene-topology-shell` 消息。
4. 场景、拓扑和动作作为一个 `transitionId` 执行；只有全部满足提交条件后才能更新稳定上下文。
5. `selectedNodeIds` 是交互选择集合，燃气节点单击基线每次只提交一个元素；`deviceStatus` 是运行状态，两者必须独立保存和渲染。

---

## 二、同场景联动

外部点击当前场景子项时：

1. 父页面发送 `workflow.trigger` 和稳定 `actionId`。
2. 协调器解析动作的目标场景、目标拓扑和 Unity 动作。
3. 普通业务事务的目标场景等于当前场景时，不发送 `switchScene`，不重建 Unity 内嵌框架；只有外层命令超时后的补偿事务允许携带 `forceReload=true` 强制重建同名物理场景，Unity 内嵌框架实例仍保持唯一。
4. 多拓扑运行时预解析目标拓扑，但保持当前拓扑可见。
5. Unity 执行流程、聚焦、路径或复位动作。
6. 动作成功后激活目标拓扑。
7. 协调器递增 `contextRevision`，外层桥发送 `command.result` 和 `view.changed`。

动作失败时默认保留当前场景和当前拓扑。只有动作清单显式允许的非关键动作才可提交视图并附带警告。

燃气基线固定四个同场景动作：`action.gas-power.overview`、`action.gas-power.gas-turbine`、`action.gas-power.hrsg`、`action.gas-power.steam-turbine`，失败策略均为 `keep-current-context`（保持当前上下文）。三个关键环节分别进入对应三维流程并提交16/13、13/6、15/10过滤视图；总览动作必须先等待三维 `overview` 成功，再提交23/22来源总图，禁止只取消二维过滤而让三维仍停留在关键环节。

0813包只发布 `overview`、`gas-turbine`、`hrsg`、`steam-turbine` 四个三维流程步骤，三维路径映射数量为0；平台动态设备绑定、真实设备状态和三维反向设备选择不属于该包已验收能力。后续实现这些能力时必须保持本节既有四动作和二维交互不回退。

---

## 三、跨场景联动

外部点击其他场景入口或跨场景子项时：

1. 创建新 `transitionId`，旧事务失去提交权。
2. 校验目标场景、目标拓扑和动作映射。
3. 预解析目标拓扑；失败则不切换场景。
4. 显示统一切换遮罩，禁止操作当前三维和拓扑。
5. 向 Unity 发送包含 `sceneId`、`transitionId`、`sceneMappingVersion` 和 `forceReload=false` 的 `switchScene`。
6. Unity 按场景策略卸载旧场景、加载目标资源并初始化目标场景。
7. 收到匹配原请求、场景和 `transitionId`，且携带新 `sceneActivationId` 的 `sceneChanged` 后执行可选动作。
8. 动作成功后激活目标拓扑。
9. 提交稳定上下文并移除遮罩。

切换期间不得显示可操作的“新拓扑 + 旧场景”或“旧拓扑 + 新场景”。加载进度只用于反馈，不能作为成功提交条件。

---

## 四、快速切换与旧回调

1. 新 `view.open` 或 `workflow.trigger` 到达时，可将执行中的旧事务标记为 `superseded`。
2. 旧事务的场景进度、场景完成、命令结果和拓扑准备回调只能执行资源清理，不能更新稳定状态。
3. 父页面必须收到旧命令的 `command.result.status = 'superseded'`。
4. 当前稳定上下文只由最新仍有效的 `transitionId` 提交。
5. 不自动重试场景切换和流程动作；父页面重试时使用新的 `messageId`。

## 五、二维选择、三维聚焦与回环阻断

### 5.1 拓扑发起

1. 单击二维节点后立即更新 `selectedNodeIds` 单元素集合和该节点全部入边、出边的路径高亮。
2. 节点有 `sceneNodeId` 且 Unity 声明 `focusNode` 能力时发送聚焦命令。
3. 聚焦命令携带新的 `selectionId`，Unity 聚焦并叠加独立描边。
4. 聚焦失败只记录诊断，不撤销二维选择。

5. 点击拓扑空白处时先清除二维节点与关联路径，再发送独立 `clearSelection`（清除选择）命令关闭三维交互描边；即使二维选择集合本来为空，也仍发送一次清除命令。该命令不得调用 `resetScene`，也不得改变流程步骤、模型显隐、镜头或告警描边；三维失败不回滚二维取消。
6. 燃气基线只冻结三条正向映射：二维 `inlet-duct → gas-turbine`、`hrsg → hrsg`、`steam-turbine → steam-turbine`；节点单击高亮自身及全部入边和出边，再以 `isolate: false` 发送聚焦。其他节点没有显式 `sceneNodeId` 时只保留二维选择，不得借用相邻模型或流程名称聚焦。

### 5.2 Unity 发起

1. Unity `objectSelected` 的业务负载必须且只能携带当前 `sceneId`（场景标识）、`sceneNodeId`（三维节点标识）和 `sceneActivationId`（物理场景激活标识）；本次选择的去重关联使用内层信封 `messageId`（消息标识），不得另以二维 `nodeId`（拓扑节点标识）替代三维节点标识，也不得混入对象名称、层级路径或命令默认字段。
2. 协调器按结构清单中的 `sceneNodeId → nodeId` 唯一反向索引定位逻辑节点；清单不得包含 `deviceId`。
3. 更新二维选择、路径和可选外部事件。
4. 来源为 Unity 的同一次选择不得再发送 `focusNode`。

### 5.3 双击节点上报

1. 双击只在单击选择基础上增加外部节点事件。
2. 事件只发送当前 `sceneId + topologyId + nodeId`，不得等待或包含 `deviceId`。
3. 双击不触发场景切换，除非父页面收到事件后另行发送受控动作。
4. 双击产生的重复单击必须幂等，不能向 Unity 产生两条相同聚焦命令。

## 六、节点状态同步

设备状态只允许：正常 `normal`、告警 `alarm`、故障 `fault`、离线 `offline`。

处理顺序：

1. 父页面按 `nodeId` 发送当前 `resourceKey` 全部已上报节点的完整四态快照，单批1至500项；`sourceRevision` 必填但只用于批次观测与诊断，即使服务重启后变小也不得拒绝快照。
2. 状态适配器一次遍历构建新状态表并原子替换旧表，不得跨批次按节点、来源修订或时间戳做增量合并；同批重复节点按最后一项归一。
3. 上一批存在、本批缺失的节点清除动态覆盖并恢复发布基线；只有平台显式发送 `offline` 才显示离线。
4. 清单中不存在的 `nodeId` 直接忽略，不保存、不报错，也不使命令失败。
5. 壳有限保存最新一份完整快照，按 `nodeId` 更新当前拓扑并完成二维局部更新；切换场景或拓扑后从该快照重新投影。载荷合法且二维完整快照成功提交后，立即形成唯一外层成功结果。
6. 壳按结构清单中的 `nodeId → 可选 sceneNodeId` 派生当前三维目标；按动画帧合并后向对应目标发送最新四态。没有三维映射的节点只更新二维，不属于失败。
7. Unity 未就绪、能力缺失、单节点失败、超时、容量拒绝或释放竞争只进入固定容量的脱敏内部诊断；不得回滚二维、延迟或改变外层成功回执，也不得发送会被平台理解为整批失败的外层错误。
8. Unity 恢复或场景重新激活时只重放最新完整快照，禁止重放已经被替换的旧批次；平台不因场景或拓扑切换重新推送。

壳必须为每次已接受的完整快照分配会话内单调递增的本地快照序号，用它隔离三维异步迟到结果；外部 `sourceRevision` 和 `statusUpdatedAt` 只能作为诊断元数据，不能作为拒绝合法快照的因果水位。该内部机制不能改变二维完整替换语义，也不能成为外层回执的等待条件。活动控制器变化或 Unity 整体释放时清空旧场景水位，禁止无界保留历史节点。

状态更新不得移动镜头、改变选择、切换场景、切换拓扑或重置路径高亮。

## 七、三维视觉与选择分层

| 状态 | 二维图元 | 三维模型 | 选中叠加 |
| --- | --- | --- | --- |
| 正常 `normal` | 正常图元 | 默认材质 | 独立选中描边 |
| 告警 `alarm` | 告警图元 | 半透明红黄色调 | 保留状态并叠加描边 |
| 故障 `fault` | 故障图元 | 半透明红色闪烁 | 保留闪烁并叠加描边 |
| 离线 `offline` | 离线图元 | 半透明灰色 | 保留灰色并叠加描边 |

三维状态使用受控材质变体、材质属性块（`MaterialPropertyBlock`）或等效参数；禁止按设备和每次状态更新克隆材质、模型或渲染器。

## 八、失败与恢复

| 阶段 | 失败处理 |
| --- | --- |
| 配置校验 | 不操作 Unity 和拓扑，直接返回错误 |
| 拓扑准备 | 保留当前稳定组合，不切换场景 |
| 场景切换 | 尝试恢复上一稳定场景；恢复前保持遮罩 |
| 目标动作 | 默认保留或恢复上一稳定组合 |
| 拓扑激活 | 不提交新上下文，尝试恢复上一拓扑 |
| 外部结果发送 | 保留本地稳定状态，记录有限重发诊断，不重复执行业务动作 |

外层命令超时的补偿恢复是普通同场景规则的唯一例外：协调器生成新事务，发送 `forceReload=true`，强制卸载并重建上一稳定物理场景。只有取得新的 `sceneActivationId` 且拓扑恢复成功，才恢复原稳定上下文。目标切换失败但 Unity 已自动恢复旧场景时，失败 `commandResult` 必须携带恢复后的激活标识，前端据此替换旧实例标识；否则进入明确错误态。

恢复失败时进入结构化错误态，必须清楚显示当前已加载场景、目标场景、当前拓扑、目标拓扑和错误关联标识。

## 九、可观测性

每次事务至少记录：

- 外部 `messageId`。
- `transitionId`。
- `sceneId`、`topologyId`、`actionId`。
- 上一个和目标 `contextRevision`。
- Unity 命令原请求标识和结果。
- 拓扑准备与激活耗时。
- 场景加载与动作耗时。
- 成功、失败或 `superseded` 状态。
- 恢复结果。

记录必须有容量上限，不保存 Unity 层级路径、完整外部载荷和无界设备状态历史。

## 十、验收清单

- [ ] 普通同场景子项不发送 `switchScene`，只执行动作和拓扑切换；外层超时补偿可发送 `forceReload=true`，但不重建 Unity 内嵌框架实例。
- [ ] 跨场景动作按场景、动作、拓扑顺序完成。
- [ ] 场景和拓扑只一起提交稳定状态。
- [ ] 快速切换只提交最后一个事务。
- [ ] Unity 反向选择不产生聚焦回环。
- [ ] 拓扑双击上报正确 `nodeId` 且不重复聚焦，消息不包含 `deviceId`。
- [ ] 完整四态快照原子替换二维状态；上一批缺失节点恢复基线，未知节点忽略，同批重复取最后一项，较小 `sourceRevision` 仍应用且不影响成功。
- [ ] 场景或拓扑切换后从最新完整快照重新投影；存在三维映射时向全部不同目标尝试同步，三维失败不回滚二维、不延迟或改变外层成功回执，且不改变选择和镜头。
- [ ] 任一阶段失败均有明确恢复或错误态。
- [ ] 释放后旧场景、旧拓扑和旧事务回调均不能更新当前状态。
