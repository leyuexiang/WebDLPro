# 多拓扑与 Unity 多场景联动规范

**适用范围：** 九个 Unity 业务场景、仅在第二层厂区显示的二维拓扑、外部父页面动作和节点事件。

**依赖规范：** [拓扑容器与多图切换规范](拓扑容器与多图切换规范.md)、[图元与设备状态规范](图元与设备状态规范.md)、[场景拓扑动作映射规范](../场景拓扑动作映射规范.md)。

**视觉边界：** 二维拓扑的深色分层、状态图元、选中描边、协议标签、文字避让、常规态同宽和全屏自适应，统一采用前述容器规范的已确认制作基线；本规范只定义已显式登记的二维选择、三维聚焦和状态同步，不把视觉相似、同名模型或坐标邻近视为映射依据。

**二维选中效果补充：** 节点被二维选中时显示独立高对比外圈或轻微光晕，关联路径同步增强；该反馈不替换四态图元、不改变设备状态，不等同于 Unity 三维选中描边，也不改变总览重点区域框的语义。

**重点区域边界：** 厂区总览 `focusRegions` 仅是二维区域级视觉分组，不是三维动作或拓扑切换。锚点与成员关系由清单显式登记；厂区过滤视图及历史关键环节过滤资源不携带区域数据，区域框不产生选择、状态同步、聚焦命令或外层消息。

**当前联动基线：** `Builds/Releases/燃气发电场景与拓扑图联动包0813`。包内 `gas-power-platform-release-5550-20260813-2015` 是发布识别值；内部验证包和早期端口包只作历史证据。

> **2026-08-14 节点协议修正：** 平台不向我方注入设备编号；双击、状态和三维反向选择统一以 `nodeId` 关联。平台内部自行维护 `nodeId → 真实设备编号`。

> **2026-08-30 三层展示规则：** 沙盘和第三层关键环节均为全屏三维且不显示拓扑，只有第二层厂区显示三维与拓扑并存布局。本文二维选择、双击、下钻和多拓扑规则只在厂区模式生效；0813 的三个关键环节过滤视图仅作历史回归数据。

## 一、联动边界

1. 外部父页面、当前子应用、Unity 和拓扑之间的所有动作必须经过唯一联动协调器。
2. 外部父页面只使用 `system.init`、`view.open` 中的受控 `sceneId`、可选业务 `topologyId` 和 `actionId`，不得直接调用 Unity。第二层厂区必须携带 `topologyId`；全局 `overview` 和第三层关键环节稳定状态必须省略 `topologyId`。
3. Unity 只接收当前子应用内部 `power3d-unity` 协议，不接收外层 `power-scene-topology-shell` 消息。
4. 场景、视图模式、可选拓扑和动作作为一个 `transitionId` 执行；厂区激活合法拓扑，沙盘和关键环节停用拓扑，只有全部满足提交条件后才能更新稳定上下文。
5. `selectedNodeIds` 是交互选择集合，燃气节点单击基线每次只提交一个元素；`deviceStatus` 是运行状态，两者必须独立保存和渲染。

### 1.1 说明型下钻不属于联动事务

1. 仅第二层厂区当前拓扑节点可打开说明型下钻覆盖层；第三层关键环节没有可见拓扑节点和下钻入口。覆盖层只解释当前正式节点与若干说明型节点的关系，不改变 `sceneId`、`topologyId`、`actionId` 或 `contextRevision`。
2. 下钻打开和关闭不得创建 `transitionId`，不得调用 `view.open`、`workflow.trigger`、拓扑 `prepare/activate` 或任何 Unity 场景、流程、镜头和显隐命令。
3. 下钻入口必须与节点单击、双击分离：节点单击继续进行二维选中和已登记三维聚焦，双击继续上报 `sceneId + topologyId + nodeId`；下钻按钮不产生节点事件。
4. 覆盖层中的说明节点和连线不参与 `selectedNodeIds`、`deviceStatus`、`sceneNodeId` 反查、设备绑定、实时快照或外层事件。说明节点点击只更新覆盖层本地状态。
5. 覆盖层打开期间只阻断当前拓扑的交互，不显示统一场景切换遮罩；原拓扑仍保留唯一画布，关闭后恢复打开前的缩放、平移、选中、路径和键盘焦点。
6. 说明内容缺失、版本不匹配或加载结果迟到时，只显示固定说明空态并保留当前正式拓扑；不得猜测关系、清空稳定上下文或触发恢复事务。

## 二、同场景联动

外部点击当前场景子项时：

1. 父页面发送 `workflow.trigger` 和稳定 `actionId`。
2. 协调器解析动作的目标场景、目标视图模式、可选目标拓扑、`processDetailId` 和 Unity 动作。
3. 普通业务事务的目标场景等于当前场景时，不发送 `switchScene`，不重建 Unity 内嵌框架；只有外层命令超时后的补偿事务允许携带 `forceReload=true` 强制重建同名物理场景，Unity 内嵌框架实例仍保持唯一。
4. 厂区动作预解析目标拓扑但保持当前拓扑可见；关键环节动作跳过拓扑准备，先加载并隐藏目标三维细节资源。
5. Unity 执行关键环节加载、聚焦、路径或复位动作。
6. 厂区动作成功后激活目标拓扑并保持双区布局；关键环节动作成功后停用拓扑并切换为全屏三维。
7. 协调器递增 `contextRevision`，外层桥发送 `command.result` 和 `view.changed`。

动作失败时默认保留当前场景和当前拓扑。只有动作清单显式允许的非关键动作才可提交视图并附带警告。

0813 历史基线固定四个同场景动作：`action.gas-power.overview`、`action.gas-power.gas-turbine`、`action.gas-power.hrsg`、`action.gas-power.steam-turbine`，失败策略均为 `keep-current-context`（保持当前上下文）。当时三个关键环节分别提交16/13、13/6、15/10过滤视图；新第三层继续复用稳定动作标识时，必须改为加载对应 `processDetailId`、停用拓扑并提交全屏三维。总览动作返回第二层厂区，恢复23/22来源总图和双区布局。

0813包只发布 `overview`、`gas-turbine`、`hrsg`、`steam-turbine` 四个三维流程步骤，三维路径映射数量为0；平台动态设备绑定、真实设备状态和三维反向设备选择不属于该包已验收能力。后续实现应保持厂区拓扑视觉与交互不回退，但不再要求第三层显示历史过滤拓扑。

## 三、跨场景联动

外部点击其他场景入口或跨场景子项时：

1. 创建新 `transitionId`，旧事务失去提交权。
2. 校验目标场景、目标视图模式、可选目标拓扑和动作映射。
3. 厂区目标预解析拓扑；沙盘或关键环节目标跳过拓扑准备。
4. 显示统一切换遮罩，禁止操作当前三维和拓扑。
5. 向 Unity 发送包含 `sceneId`、`transitionId`、`sceneMappingVersion` 和 `forceReload=false` 的 `switchScene`。
6. Unity 按场景策略卸载旧场景、加载目标资源并初始化目标场景。
7. 收到匹配原请求、场景和 `transitionId`，且携带新 `sceneActivationId` 的 `sceneChanged` 后执行可选动作。
8. 厂区动作成功后激活目标拓扑；沙盘或关键环节成功后停用拓扑并显示全屏三维。
9. 提交稳定上下文并移除遮罩。

切换期间不得显示可操作的“新拓扑 + 旧场景”“旧拓扑 + 新场景”或“沙盘/关键环节三维 + 厂区旧拓扑”。加载进度只用于反馈，不能作为成功提交条件。

### 3.1 业务场景返回全局沙盘

全局沙盘只有三维场景，没有对应的全局拓扑图。平台通过 `system.init` 或 `view.open({ sceneId: "overview" })` 触发返回；子应用必须通过统一原子事务向 Unity 下发内层 `switchScene("overview")`，收到匹配新 `sceneActivationId` 后停用并隐藏网页拓扑区域、清空业务拓扑选择。总览稳定上下文和上行事件均不提交 `topologyId`，也不允许只切 Unity 场景而遗留旧拓扑。Unity 启动后不会默认进入沙盘，也不会因本地点击自行返回。

返回事务固定遵守：

1. 校验平台返回命令的来源、权限、请求标识和当前稳定上下文。
2. 创建新的 `transitionId`，使当前业务场景事务和旧业务拓扑失去提交权。
3. 保留旧稳定视图并用事务遮罩阻断交互，避免在 Unity 成功前丢失可恢复的业务选择。
4. 向 Unity 请求进入 `Overview`，收到匹配的新 `sceneActivationId` 后停用唯一拓扑 Canvas 并清空业务选择。
5. 只有 `Overview` 场景就绪且拓扑进入空闲态后，才提交全局沙盘稳定状态并发送成功回执；返回状态不包含全局 `topologyId`。
6. 返回成功后网页只保留全局三维沙盘，业务拓扑、业务节点选择、流程动作和业务拓扑交互全部隐藏或清空；Canvas 保持挂载，供下一次业务场景复用。

切换失败、超时、快速重复返回、旧回调和释放竞态沿用现有事务取代与恢复规则。全局沙盘没有拓扑图，因此不得伪造全局拓扑、复用默认业务拓扑或扩展九项业务 `SceneId` 闭集。Bootstrap 只初始化常驻服务并等待平台命令；沙盘建筑点击也只上报选择意图，不得在 Unity 内部创建无平台请求标识的场景事务。

## 四、快速切换与旧回调

1. 新 `view.open` 或 `workflow.trigger` 到达时，可将执行中的旧事务标记为 `superseded`。
2. 旧事务的场景进度、场景完成、命令结果和拓扑准备回调只能执行资源清理，不能更新稳定状态。
3. 父页面必须收到旧命令的 `command.result.status = 'superseded'`。
4. 当前稳定上下文只由最新仍有效的 `transitionId` 提交。
5. 不自动重试场景切换和流程动作；父页面重试时使用新的 `messageId`。

## 五、二维选择、三维聚焦与回环阻断

### 5.1 拓扑发起

1. 单击二维节点后立即更新 `selectedNodeIds` 单元素集合和该节点全部入边、出边的路径高亮。
2. 节点有 `sceneNodeId` 且 Unity 声明 `focusNode` 能力时发送聚焦命令。
3. 聚焦命令携带新的 `selectionId`，Unity 聚焦并叠加独立描边。
4. 聚焦失败只记录诊断，不撤销二维选择。

5. 点击拓扑空白处时先清除二维节点与关联路径，再发送独立 `clearSelection`（清除选择）命令关闭三维交互描边；即使二维选择集合本来为空，也仍发送一次清除命令。该命令不得调用 `resetScene`，也不得改变流程步骤、模型显隐、镜头或告警描边；三维失败不回滚二维取消。
6. 燃气基线只冻结三条正向映射：二维 `inlet-duct → gas-turbine`、`hrsg → hrsg`、`steam-turbine → steam-turbine`；节点单击高亮自身及全部入边和出边，再以 `isolate: false` 发送聚焦。其他节点没有显式 `sceneNodeId` 时只保留二维选择，不得借用相邻模型或流程名称聚焦。

### 5.2 Unity 发起

1. Unity `objectSelected` 的业务负载必须且只能携带当前 `sceneId`（场景标识）、`sceneNodeId`（三维节点标识）和 `sceneActivationId`（物理场景激活标识）；本次选择的去重关联使用内层信封 `messageId`（消息标识），不得另以二维 `nodeId`（拓扑节点标识）替代三维节点标识，也不得混入对象名称、层级路径或命令默认字段。
2. 协调器按结构清单中的 `sceneNodeId → nodeId` 唯一反向索引定位逻辑节点；清单不得包含 `deviceId`。
3. 更新二维选择、路径和可选外部事件。
4. 来源为 Unity 的同一次选择不得再发送 `focusNode`。
5. Unity 鼠标命中已登记场景节点时更新三维交互描边，并发送 `objectSelected`；前端按静态 `sceneNodeId → nodeId` 映射同步当前二维拓扑选择，不回发 `focusNode`。
6. Unity 鼠标点击真正空白、地面或未映射对象时，仅在存在交互选择时清除交互描边并发送 `selectionCleared(sceneId, sceneActivationId)`。
7. 前端收到当前场景实例的 `selectionCleared` 后清除二维节点和关联路径，不回发 `clearSelection`；流程描边、告警描边、场景显隐和已到达镜头位置不变。
8. 旧场景实例、无激活标识或已释放实例产生的 `objectSelected` / `selectionCleared` 必须丢弃。

### 5.3 双击节点上报

1. 双击只在单击选择基础上增加外部节点事件。
2. 事件只发送当前 `sceneId + topologyId + nodeId`，不得等待或包含 `deviceId`。
3. 双击不触发场景切换，除非父页面收到事件后另行发送受控动作。
4. 双击产生的重复单击必须幂等，不能向 Unity 产生两条相同聚焦命令。

## 六、节点状态同步

设备状态只允许：正常 `normal`、告警 `alarm`、故障 `fault`、离线 `offline`。

处理顺序：

1. 父页面按 `nodeId` 发送当前 `resourceKey` 全部已上报节点的完整四态快照，单批1至500项；`sourceRevision` 必填但只用于批次观测与诊断，即使服务重启后变小也不得拒绝快照。
2. 状态适配器一次遍历构建新状态表并原子替换旧表，不得跨批次按节点、来源修订或时间戳做增量合并；同批重复节点按最后一项归一。
3. 上一批存在、本批缺失的节点清除动态覆盖并恢复发布基线；只有平台显式发送 `offline` 才显示离线。
4. 清单中不存在的 `nodeId` 直接忽略，不保存、不报错，也不使命令失败。
5. 壳有限保存最新一份完整快照，按 `nodeId` 更新当前拓扑并完成二维局部更新；切换场景或拓扑后从该快照重新投影。载荷合法且二维完整快照成功提交后，立即形成唯一外层成功结果。
6. 壳按结构清单中的 `nodeId → 可选 sceneNodeId` 派生当前三维目标；按动画帧合并后向对应目标发送最新四态。没有三维映射的节点只更新二维，不属于失败。
7. Unity 未就绪、能力缺失、单节点失败、超时、容量拒绝或释放竞争只进入固定容量的脱敏内部诊断；不得回滚二维、延迟或改变外层成功回执，也不得发送会被平台理解为整批失败的外层错误。
8. Unity 恢复或场景重新激活时只重放最新完整快照，禁止重放已经被替换的旧批次；平台不因场景或拓扑切换重新推送。

壳必须为每次已接受的完整快照分配会话内单调递增的本地快照序号，用它隔离三维异步迟到结果；外部 `sourceRevision` 和 `statusUpdatedAt` 只能作为诊断元数据，不能作为拒绝合法快照的因果水位。该内部机制不能改变二维完整替换语义，也不能成为外层回执的等待条件。活动控制器变化或 Unity 整体释放时清空旧场景水位，禁止无界保留历史节点。

状态更新不得移动镜头、改变选择、切换场景、切换拓扑或重置路径高亮。

## 七、三维视觉与选择分层

| 状态 | 二维图元 | 三维模型 | 选中叠加 |
| --- | --- | --- | --- |
| 正常 `normal` | 正常图元 | 默认材质 | 独立选中描边 |
| 告警 `alarm` | 告警图元 | 半透明红黄色调 | 保留状态并叠加描边 |
| 故障 `fault` | 故障图元 | 半透明红色闪烁 | 保留闪烁并叠加描边 |
| 离线 `offline` | 离线图元 | 半透明灰色 | 保留灰色并叠加描边 |

三维状态使用受控材质变体、材质属性块（`MaterialPropertyBlock`）或等效参数；禁止按设备和每次状态更新克隆材质、模型或渲染器。

## 八、失败与恢复

| 阶段 | 失败处理 |
| --- | --- |
| 配置校验 | 不操作 Unity 和拓扑，直接返回错误 |
| 拓扑准备 | 保留当前稳定组合，不切换场景 |
| 场景切换 | 尝试恢复上一稳定场景；恢复前保持遮罩 |
| 目标动作 | 默认保留或恢复上一稳定组合 |
| 拓扑激活 | 不提交新上下文，尝试恢复上一拓扑 |
| 外部结果发送 | 保留本地稳定状态，记录有限重发诊断，不重复执行业务动作 |

外层命令超时的补偿恢复是普通同场景规则的唯一例外：协调器生成新事务，发送 `forceReload=true`，强制卸载并重建上一稳定物理场景。只有取得新的 `sceneActivationId` 且拓扑恢复成功，才恢复原稳定上下文。目标切换失败但 Unity 已自动恢复旧场景时，失败 `commandResult` 必须携带恢复后的激活标识，前端据此替换旧实例标识；否则进入明确错误态。

恢复失败时进入结构化错误态，必须清楚显示当前已加载场景、目标场景、当前拓扑、目标拓扑和错误关联标识。

## 九、可观测性

每次事务至少记录：

- 外部 `messageId`。
- `transitionId`。
- `sceneId`、视图模式、可选 `topologyId`、可选 `processDetailId`、`actionId`。
- 上一个和目标 `contextRevision`。
- Unity 命令原请求标识和结果。
- 拓扑准备、停用、恢复与激活耗时。
- 场景加载与动作耗时。
- 成功、失败或 `superseded` 状态。
- 恢复结果。

记录必须有容量上限，不保存 Unity 层级路径、完整外部载荷和无界设备状态历史。

## 十、验收清单

- [ ] 普通同场景子项不发送 `switchScene`；厂区动作切换拓扑，关键环节动作停用拓扑并切换全屏三维。外层超时补偿可发送 `forceReload=true`，但不重建 Unity 内嵌框架实例。
- [ ] 跨场景动作按场景、视图模式、动作和可选拓扑顺序完成。
- [ ] 场景、视图模式、可选拓扑和三维目标只一起提交稳定状态。
- [ ] 快速切换只提交最后一个事务。
- [ ] Unity 反向选择不产生聚焦回环。
- [ ] 拓扑双击上报正确 `nodeId` 且不重复聚焦，消息不包含 `deviceId`。
- [ ] 节点单击、键盘、触屏和 Unity 反向选择均显示统一二维选中反馈；清除选择和拓扑切换后反馈无残留，且不改变四态状态、重点区域或命中/路由边界。
- [ ] 下钻覆盖层只在厂区拓扑中可用，不创建联动事务、不调用 Unity、不发送外层消息；第三层关键环节无拓扑下钻入口。
- [ ] 总览重点区域只按显式 `focusRegions` 绘制；锚点带 `sceneNodeId`、成员集合闭环且颜色稳定；关键环节无区域框，区域框不改变命中、路由和三维联动。
- [ ] 完整四态快照原子替换二维状态；上一批缺失节点恢复基线，未知节点忽略，同批重复取最后一项，较小 `sourceRevision` 仍应用且不影响成功。
- [ ] 场景或拓扑切换后从最新完整快照重新投影；存在三维映射时向全部不同目标尝试同步，三维失败不回滚二维、不延迟或改变外层成功回执，且不改变选择和镜头。
- [ ] 任一阶段失败均有明确恢复或错误态。
- [ ] 释放后旧场景、旧拓扑和旧事务回调均不能更新当前状态。
- [ ] 沙盘和关键环节模式下拓扑输入、布局和重绘停用；返回厂区时恢复原拓扑与选择，不重建唯一画布。
