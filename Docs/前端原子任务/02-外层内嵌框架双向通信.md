# 外层内嵌框架双向通信任务

> **2026-08-15 协议纠偏：** 本组实现已统一使用 `nodeId` 作为双击、状态和三维反选关联键。平台不向我方注入 `deviceId`、设备映射或绑定计数；任务-056已完成本地迁移。

## 任务-007：外层协议类型与载荷校验

**前置：** 任务-004、005。

**需求：** 按[外层内嵌框架双向通信协议](外层内嵌框架双向通信协议.md)实现通用信封、命令、事件、错误码和逐类型运行时校验；设备状态按当前 `resourceKey` 的完整快照校验。

**交付：** `host-protocol.ts`、类型守卫和测试。

**验收：** 通道、版本、实例、会话、消息标识、响应关联和时间戳完整；状态项 `nodeId` 必须符合结构清单规则，`statusUpdatedAt` 必须带时区，`sourceRevision` 必填但只作诊断；500项通过，501项整体拒绝，未知类型、超长字符串、设备编号字段和无效载荷被拒绝。

**实施状态：** 已完成（100%），详见[任务-007实施状态](02-任务-007-外层协议类型与载荷校验-实施状态.md)。

## 任务-008：统一窗口消息路由器

**前置：** 任务-007、现有 Unity 内层协议。

**需求：** 在全局消息入口先按通道分流外层父页面消息和内层 Unity 消息，避免两个连接器重复监听和误记拒绝日志。

**交付：** `message-router.ts` 和订阅接口。

**验收：** `power-scene-topology-shell` 只进入外层桥，`power3d-unity` 只进入 Unity 连接器；未知通道被安静拒绝并写入有限诊断日志。

## 任务-009：父来源、父窗口与会话隔离

**前置：** 任务-006—008。

**需求：** 校验精确父来源、`window.parent`、部署白名单、实例标识和每次加载生成的 `sessionId`；出站使用精确目标来源。

**交付：** `host-bridge.ts` 安全边界。

**验收：** 错误来源、同源其他窗口、错误实例、旧会话和通配目标来源均不能进入业务逻辑；查询参数不能绕过部署白名单。

## 任务-010：就绪、初始化与能力握手

**前置：** 任务-009。

**需求：** 壳在就绪前从随包文件或受控地址读取并校验我方不可变结构清单，实现 `system.ready → system.init → system.ack`，返回场景目录、清单版本、命令能力和事件能力；初始化失败同时发送失败确认和结构化错误。

**交付：** 外层握手状态机、页面加载后 15 秒就绪期限和父页面初始化等待状态。

**验收：** 父页面先监听再加载时稳定完成握手；子应用在加载后15秒内完成结构清单校验并发送 `system.ready`；清单无设备字段仍正常启动，随包或受控地址缺失时稳定失败；`nodeId` 全局唯一且节点到三维映射闭环；清单版本不匹配时发送失败确认和关联错误；未初始化前业务命令不能执行。

## 任务-011：命令确认、去重、超时与容量控制

**前置：** 任务-007、010。

**需求：** 建立有限待确认表、最近消息去重缓存、`replyTo` 关联、10 秒默认超时和释放清理；重复 `messageId` 直接丢弃，不重复执行或发送第二份业务回执。

**交付：** 外层命令生命周期管理器。

**验收：** 重复 `messageId` 被静默丢弃且不回放第二份结果，平台重试必须生成新标识；响应只能按 `replyTo` 关联；同一会话最多一条状态命令在途，旧会话、卸载和释放会停止旧重试；待确认表达到64条时拒绝新命令，近期去重窗口固定保存最近256个标识并淘汰最早项；卸载后无定时器和闭包残留。

## 任务-012：外部命令入口

**前置：** 任务-010、011、031。

**需求：** 接入 `view.open`、`workflow.trigger`、`device.states.update`、`state.get` 和 `system.dispose`，只向协调器提交已经校验的领域命令；设备状态必须作为完整快照原样提交，分派器不维护设备绑定。

**交付：** 命令分派器和能力白名单。

**验收：** 外层桥不直接调用 Unity、画布或状态仓库；未声明能力、旧上下文版本和已释放状态均返回结构化结果；未知设备被忽略且不使命令失败；二维快照提交决定外层结果，三维同步失败不改变该结果。

## 任务-013：外部事件上报

**前置：** 任务-009、011、027、037。

**需求：** 上报 `view.changed`、`topology.node.dblclick`、可选 `scene.object.selected`、`state.snapshot`、`command.result` 和 `system.error`；节点事件只使用结构清单中的 `nodeId`，不得等待或携带平台真实设备编号。

**交付：** 事件发送器和载荷转换器。

**验收：** 拓扑双击事件只含 `sceneId + topologyId + nodeId`；所有响应带正确 `replyTo`；节点状态的三维同步失败只进入有限内部诊断，不发送失败结果或外层错误；日志和错误不包含真实设备编号、Unity 层级路径、敏感凭据或完整不可信载荷。

## 任务-014：三层本地联调环境

**前置：** 任务-007—013、任务-018。

**需求：** 将现有本地内嵌框架回归夹具升级为“外部宿主页 → 当前可视化子应用 → Unity 模拟页”，覆盖结构清单读取、无设备字段启动、握手、切换、流程、节点双击、完整节点快照、重试、错误和释放。

**交付：** 可重复启动的双端口或三端口联调夹具、自动回归按钮和中文说明。

**验收：** 正向通信与错误来源、旧会话、重复消息、旧事务、超时和释放均可一键验证；结构清单成功与缺失可复现；`emit-node` 双击只上报 `nodeId`，三维通过静态映射派生；连续完整快照跨场景保存，较小来源修订仍应用，同批重复 `nodeId` 取最后一项，501项整体拒绝；同一会话最多一条状态命令在途；三维成功时状态到达模型，三维失败时外层仍只有一次二维成功；监听器必须早于内嵌框架地址设置。
