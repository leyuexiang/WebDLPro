# 任务-027：拓扑节点双击设备事件实施状态

**状态：** 已完成（100%）
**更新时间：** 2026-08-06

## 已实施

- `TopologyCanvas` 在复用既有命中缓存的前提下增加双击节点意图；该层只返回二维节点标识，不访问 Unity、状态仓库或跨窗口通信。
- `TopologyPanel` 仅转发双击节点意图；正式运行时从当前已激活拓扑中检查 `doubleClickBehavior`、`deviceId` 和可选 `sceneNodeId`。
- 只有明确声明 `emit-device` 且存在 `deviceId` 的节点会生成设备双击意图；概念节点、等待态、未知节点和未声明上报节点均不发送。
- 清单校验新增“设备映射闭环”规则：即使同一 `deviceId` 已存在映射表，每个二维设备节点仍须被该映射的 `topologyNodeRefs`（拓扑节点引用）逐项引用；空映射或错图引用不能放行双击上报。
- 单击仍即时处理，并经唯一协调器提交选择；双击不会再次写选择，也不会在本任务中下发 Unity 聚焦命令，因此不会造成双击重复聚焦。
- 正式清单到旧画布端口会回写选择快照，避免拓扑切换或全屏重渲染把运行时恢复的选择清空。
- 嵌入壳已将正式双击意图交给唯一外层通信组合根；组合根仅在握手成功、稳定上下文就绪且事件场景/拓扑与当前提交值一致时发送 `topology.node.dblclick`，并由受控发送器补齐上下文版本、关联标识、实例与会话。

## 验证

- 设备双击解析测试覆盖：已登记设备节点返回 `sceneId`、`topologyId`、`nodeId`、`deviceId` 与可选 `sceneNodeId`；概念节点和未知节点不产生意图。
- 清单校验测试覆盖：双击上报节点缺失设备标识会拒绝发布；设备映射存在但未显式引用该二维节点时以 `device-mapping.node-unmapped`（设备映射节点未闭环）拒绝发布。
- 组合根测试覆盖：初始化前不接纳业务命令；初始化后的设备双击必须匹配当前稳定场景/拓扑，错配意图静默拒绝。
- 2026-08-06 使用内部浏览器重新执行真实 Canvas（画布）双击：外层宿主页仅记录 1 条 `topology.node.dblclick`，设备为测试清单显式登记的 `device.gas-turbine`；浏览器双击派生的两次单击最终只向三维模拟运行时发送 1 次 `focusNode`，计数属性为 `1`。
- 当前前端全量回归：36 个测试文件、168 项通过；类型检查和生产构建通过，`git diff --check` 未发现空白错误。验证结束后已停止 5174、5510、5511 临时服务，用户保留的 5528 测试服务未受影响。

## 性能与释放

- 双击命中复用画布适配器已有节点命中缓存，不重建节点索引、路径缓存或图元资源。
- 双击处理不创建计时器，不延迟单击，不保存无界历史；外层关联标识由现有有限协议发送器生成。
- 画布、尺寸观察器和拓扑运行时继续沿既有幂等释放路径清理，本任务没有新增窗口监听器、动画帧或资源句柄。

## 范围边界与后续事项

1. 任务-027按原始需求、交付和验收口径已经闭环。正式九场景 `deviceId`、`sceneNodeId` 和二维节点对应关系属于任务-039—047，不应反向阻塞双击框架关闭；本地夹具数据只作为协议与浏览器回归证据，不进入生产清单。
2. 当前燃气最小正式联调包因尚未取得正式设备主数据，明确将节点双击声明为 `none`；该诚实降级不代表框架缺失。收到正式设备映射后，应由对应场景配置任务启用 `emit-device` 并执行逐设备验收。
3. 三维聚焦属于任务-028。任务-027只要求双击产生额外外层设备事件，并验证双击派生单击不会重复聚焦；不得在双击处理器内另行调用 Unity。
