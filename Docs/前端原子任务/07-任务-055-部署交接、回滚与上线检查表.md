# 任务-055：部署交接、回滚与上线检查表

**适用范围：** 结构版本4燃气联调包及后续使用相同发布门禁的场景包。  
**使用边界：** 本文是上线前交接材料，不填写生产域名、证书、账号、设备数据或合作方内部网络信息。当前受控内网阶段不以固定平台来源、证书或精确嵌入祖先为前置条件；仍未关闭的真实节点状态联调、回滚演练、九场景验收和目标硬件验证完成前，不得将任务-055标为待验收或已完成。

包类型、文件结构和自动失败条件以[测试包与正式包输出标准](测试包与正式包输出标准.md)为准；本表只记录每次实际发布是否逐项满足。

## 一、发布责任边界

1. 发布目录必须是唯一版本目录，禁止覆盖已有目录；平台交付目录不得携带 `self-test.html`（自测页）。
2. 我方负责发布目录完整性、前端与 Unity 协议门禁、不可变结构清单、外层通信协议和本地接入参考。
3. 平台负责读取结构清单、在平台内部维护 `nodeId → 真实设备编号`、内网访问边界、访问日志、上线窗口和版本指针回滚；平台绑定不注入我方产物。固定来源、反向代理和证书仅在后续外网部署或安全加固时由双方另行启用。
4. Unity 场景负责人负责同一发布标识下的网页图形构建、协议能力文件、场景资源、内存基线与可回滚历史目录。
5. 不得把本地地址、合成设备、内部自测入口或本地浏览器结果作为生产验收结论。

## 三、发布前文件和安全门禁

- [ ] 目标目录和暂存目录均不存在；构建成功后才整体切换到目标目录。
- [ ] `release-manifest.json`（发布摘要）的包类型、部署模式、禁止产物补丁、发布标识、Unity发布标识、清单版本、结构版本和 `selfTestIncluded`（是否包含自测页）与目录内容一致。
- [ ] 平台交付目录中无 `self-test.html`，根入口无流程测试按钮、测试标题和测试诊断。
- [ ] 交付包根入口的 `entryMode`（入口模式）为 `platform-direct-shell-redirect`；根页不嵌套第二层我方宿主、不自动发送 `system.init`，完整保留平台传入的三个协议查询参数。
- [ ] 每张业务源拓扑的全部节点均为 `emit-node`；结构清单不含 `deviceId`（设备标识）、`platformBindingCount`（平台绑定数量）或 `deviceMappings`（设备映射）。
- [ ] 合作方联调包和正式包中只携带我方不可变结构清单；平台只读取 `nodeId`，在平台内部维护真实设备绑定，不能改写双击行为、三维节点、动作、连线或版本。
- [ ] `includedCapabilities`（已含能力）包含 `node-events`、`node-states` 和 `node-scene-mapping`；`excludedCapabilities`（排除能力）按实际排除三维路径和未交付场景。
- [ ] 服务监听地址和端口已填写，启动日志已列出可实际访问的局域网 IPv4 地址；运行时同源模式由当前页面自动派生嵌入壳、Unity和结构清单来源，不要求预填固定平台父源。结构清单固定为 `<当前服务来源>/scene-topology-manifest.json`，不得指向平台接口。交付文本无 `127.0.0.1`、`localhost` 或作为浏览器地址的 `0.0.0.0`。
- [ ] `artifact-integrity.json`（产物完整性清单）覆盖除自身外全部文件；部署前后文件集合、字节数和安全哈希算法摘要一致。
- [ ] Unity 目录含 `webgl-protocol-capabilities.json`（网页图形协议能力声明），发布标识、结构版本4、12项下行命令能力和节点状态字段门禁全部通过。
- [ ] 结构清单读取固定在十秒时限内完成；超时、网络失败、主动取消、非法内容、错误缓存策略和两类404均只显示稳定脱敏错误码，不显示接口地址或服务端正文。
- [ ] HTML、JSON 与错误响应使用 `Cache-Control: no-cache, max-age=0, must-revalidate`（每次使用前重新验证）；版本化脚本、样式、图元和 Unity 资源使用长期不可变缓存。
- [ ] Unity 压缩资源保留正确的压缩编码和网页程序集媒体类型；反向代理不得改写为下载附件或通用二进制类型。
- [ ] 所有成功与错误响应都有类型防嗅探、来源信息限制、同源资源策略与受限浏览器能力响应头。
- [ ] 当前内网运行时同源模式的内容安全策略可使用部署环境的放宽嵌入策略，或通过 `POWER_ALLOWED_FRAME_ANCESTORS`（允许嵌入祖先来源）收紧；不得因此要求构建前提供固定平台父源。外网或安全加固阶段必须改为精确嵌入祖先，且不得使用 `*`（任意来源）。
- [ ] Unity 和结构清单保持当前服务同源，不依赖浏览器Cookie；只有后续固定来源跨域部署时，才额外配置精确跨域来源。
- [ ] Unity `webGLDataCaching`（网页图形离线数据缓存）保持 `0`；构建入口日志确认构建前强制关闭。当前内存基线为初始256MB、单次增长上限64MB、最大768MB。
- [ ] 合作方联调包和正式包的 Unity 构建入口在 `BuildPipeline.BuildPlayer` 前临时设置 `PlayerSettings.insecureHttpOption = InsecureHttpOption.AlwaysAllowed`，使局域网 HTTP 场景资源可下载；构建完成、失败或异常退出后恢复编辑器原值，项目设置不得被永久改写。
- [ ] 使用启动日志列出的实际局域网 IPv4 地址打开包，燃气模型、23/22 总拓扑和 `SceneBundles` 均加载成功；控制台不得出现 `Insecure connection not allowed` 或 `Non-secure network connections disabled`。

## 四、父页面接入核对

完整字段、类型白名单与错误码以[外层内嵌框架双向通信协议](外层内嵌框架双向通信协议.md)为唯一依据。以下只规定上线顺序：

1. 注册消息监听器早于创建或设置内嵌框架地址。
2. 从当前 iframe 地址解析嵌入壳实际目标来源；发送消息时不得使用任意来源通配符。内网阶段无需把该来源预先写入构建配置。
3. 嵌入并通信时，根地址查询参数必须包含经编码的 `parentOrigin`、平台生成的 `instanceId` 和固定 `protocolVersion=1`；根页同窗口进入协议壳后，平台仍是该壳的直接父窗口。直接访问服务根地址时可省略这三个参数，页面仍须独立显示。
4. 只接受 `event.source === iframe.contentWindow`（事件来源等于当前内嵌框架窗口）的消息，并校验来源、通道、版本、实例、会话和消息标识。
5. 收到 `system.ready`（系统就绪）后保存当前会话，才发送 `system.init`（系统初始化）；内嵌壳重载时清空旧会话、待确认表和状态重试。
6. 用 `replyTo`（请求关联标识）匹配命令结果，不能使用响应自身消息标识匹配请求。
7. 状态发送每五秒检查一次，同一会话最多一条状态命令在途，等待上限十秒。超时或网络异常后重新读取最新完整快照并生成新消息标识；显式不可恢复失败、会话变化或释放后不得重发相同状态内容。
8. 没有节点状态时不发送状态命令和空数组；平台未绑定真实设备时的提示与处理由平台内部负责，不向我方发送绑定事实。
9. 页面卸载、版本切换或收到 `system.dispose`（系统释放）结果时，停止计时器、清空待确认表并移除监听器。

## 五、上线执行顺序

1. 复核第二节中的服务地址、端口、内网边界、回滚目标和负责人；当前内网阶段缺少固定平台来源或证书不阻断启动和独立访问。
2. 在目标环境复制新的唯一目录，校验发布摘要、结构清单、网页图形能力声明和目录中无自测页。
3. 配置内网访问边界、缓存与安全响应头；运行时同源包不预填固定来源。若后续启用反向代理、外网或安全加固，再配置精确来源和内容安全策略。分别以读取请求和仅读响应头请求核对入口、清单、脚本与 Unity 资源。
4. 启动平台父页面后，按“监听器先于内嵌框架地址”的顺序加载带三个协议查询参数的根入口；根页同窗口进入 `shell/embed`，平台不直接加载 `unity/index.html`。
5. 验证系统就绪与初始化确认、燃气场景和23节点/22连线总图、单一三维实例、单一拓扑画布、拓扑单击聚焦、空白清除描边和双容器全屏。
6. 平台读取真实结构清单后，验证内部节点绑定、两类404、完整节点快照、超过500项消息容量失败、跨场景重投影和三维失败不改变二维成功回执。
7. 记录发布标识、来源、资源标识、检查人、时间、请求摘要与失败截图；记录中不得写入设备状态完整载荷或敏感配置。

## 六、回滚方案

### 6.1 前置条件

- [ ] 当前发布标识和上一个已验收发布标识均已填写，对应目录与发布摘要可读取。
- [ ] 平台具备原子版本指针或等价的不可中断切换机制；禁止逐文件覆盖当前目录。
- [ ] 父页面能在切换前发送释放并在切换后创建新内嵌框架会话。
- [ ] 父页面、嵌入壳、Unity 资源和清单均按同一回滚发布标识切换；不得只回滚其中一层。

### 6.2 步骤

1. 停止新版本入口继续接收会产生副作用的操作，并发送当前会话释放命令。
2. 记录当前发布标识、失败时间、资源标识和已观察到的稳定错误码。
3. 以平台原子版本指针，将父页面入口、嵌入壳、Unity 资源和清单发布目标一起切回上一个已验收版本。
4. 新建内嵌框架实例，不复用旧会话、旧待确认表或旧状态重试。
5. 重复第五节中的初始化、来源校验、单实例和根入口验证，核对发布摘要与实际响应版本一致。
6. 仅在回滚验证通过后恢复业务入口；失败目录保留只读证据，禁止原位修补后冒充同一版本。

## 八、当前结论

本清单补齐了可由当前工程确定的部署交接、父页面接入、回滚和上线核对规则。当前受控内网阶段采用运行时同源模式，固定生产来源和证书不是前置条件；平台真实节点状态、回滚演练、九场景和目标硬件实际验收尚未提供，因此它仍是上线前置材料，不是上线批准或平台验收结论。

## 十、2026-08-15 内网来源策略决定

合作方联调包和正式包都作为独立内网服务运行。服务启动后只要知道实际局域网访问地址即可独立打开；平台以 iframe 嵌入时才追加 `parentOrigin`、`instanceId` 和 `protocolVersion` 建立跨窗口消息会话。当前不要求提供、登记或固化平台实际来源，不因缺少固定来源、证书或精确嵌入祖先限制阻断打包和启动。此决定不移除消息建立后的 `event.origin`、`event.source`、实例和会话校验；它们是确保消息只在当前 iframe 会话内收发的功能正确性要求。后续进入外网或安全加固阶段，再切换固定来源、HTTPS 和精确嵌入祖先策略。
