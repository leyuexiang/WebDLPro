# 任务-038：设备状态批量协调与可观测性实施状态

**状态：** 进行中（80%）
**更新时间：** 2026-08-05

## 已实施

- 新增 `DeviceStatesUpdateCoordinator`（设备状态批量协调器）。外层已校验的 `device.states.update`（设备状态批量更新）先交给任务-029的 `TopologyRuntime`（拓扑运行时）合并、去重与时间戳丢弃，再只读取当前活动场景已有的显式三维节点状态快照。
- 协调器以最多八路的有限工作池向 Unity 下发单节点四态命令；上限固定不超过内层连接器的 64 条待确认容量，避免单个最多 500 项的批次耗尽连接器。
- 二维与三维独立结算：二维状态已提交时，Unity 未协商能力、回执失败或单项异常均不会回滚二维；外层命令则明确返回失败，不能把部分成功伪装成全链路成功。
- 单项 Unity 异常被隔离为该节点失败，剩余节点继续处理；异常对象、原始外层消息、设备标识和三维节点标识均不进入诊断队列。
- 诊断仅保存关联标识、处理时间、耗时、接受/过期/无映射/无效时间计数、Unity 目标/成功/失败计数及能力不可用标记。队列固定为 64 条先进先出记录，组合根释放时清空。
- `HostRuntimeComposition`（宿主运行时组合根）仅在协调器实际注入时才声明 `device.states.update` 能力，并将该命令接入既有十秒超时、去重和受控回包生命周期；释放时同步清空协调器诊断。
- `EmbeddedVisualizationShell`（嵌入式可视化外壳）已组装唯一拓扑运行时、Unity 状态端口和批量协调器。Unity 端口只在内层就绪且协商到 `setNodeVisualState`（设置节点可视状态）能力时发送。

## 验证

- 专项单元测试覆盖二维先更新、Unity 回执失败、能力未协商、单项异常隔离、诊断容量与释放清空。
- 组合根测试覆盖能力按注入声明、外层命令分派、受控回包及释放清理。
- 前端完整回归：32 个测试文件、141 项测试通过；类型检查与生产构建通过。
- 内置浏览器三层本地夹具已验证：父页面发送合成的燃气设备状态后，宿主收到完成回包，二维状态由正常变为告警，Unity 模拟运行时确认 `setNodeVisualState`（设置节点可视状态）。该夹具严格使用已存在的测试映射，不代表正式业务映射。
