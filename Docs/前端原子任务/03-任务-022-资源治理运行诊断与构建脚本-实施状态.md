# 任务-022：资源治理、运行诊断与构建脚本实施状态

## 完成结论

任务-022原始范围已关闭：业务场景具备统一资源治理工具，燃气场景在卸载前主动释放自有运行时资源，协调器在整体释放时清空资源包句柄与事件订阅；运行诊断记录加载耗时、首帧、峰值内存、失败阶段和当前场景；开发与正式网页图形构建入口严格分离，正式包默认不启用开发构建。

其余八场景的正式资源所有者映射、目标硬件长时间内存和显存数据分别属于任务-039、041—047与054，不再倒置为本原子任务的关闭条件。

## 已交付

### 1. 场景级资源治理工具

- 新增 `Assets/Scripts/Visualization/Scenes/BusinessSceneResourceScope.cs`，统一登记事件退订动作、精确协程、动画器、旧版动画、独占渲染纹理、临时渲染纹理、可释放句柄和运行时创建对象。
- 资源按登记逆序释放，重复登记按对象身份拒绝，重复释放幂等；单项异常只增加有限失败计数，不阻断其余清理。
- 作用域释放后不允许重新打开；异步迟到资源会立即尝试清理，列表与身份集合随后清空，不继续持有资源强引用。
- 生产路径没有 `Update`、层级扫描、`Resources.UnloadUnusedAssets` 或 `GC.Collect`，高成本全局回收不会进入每帧或每次普通切换路径。

### 2. 燃气场景主动释放

- `GasPowerBusinessSceneControllerAdapter` 将控制器自有释放动作登记到资源作用域，`ReleaseScene` 在场景卸载前立即执行并返回结构化结果。
- `PowerPlantProcessController.ReleaseOwnedRuntimeResources` 幂等停止镜头动画，关闭流程与告警高亮，还原原始共享材质，销毁运行时半透明材质并清空节点、选择与渲染器引用。
- `OnDestroy` 继续作为直接销毁场景对象时的幂等兜底，不再是正常切换唯一释放点。
- 全量半透明材质还原改为单次字典遍历后统一清空，避免复制键列表和逐项移除产生的额外分配。

### 3. 协调器、资源包与事件封口

- `MultiSceneCoordinator.DisposeRuntime` 在活动控制器释放和场景卸载启动后，统一释放场景租约、共享依赖包、目录索引与资源包句柄。
- 最终 `disposed` 状态、诊断和活动控制器清空事件发出后，协调器清空五类事件委托，避免常驻发布者继续持有网页桥接器或测试闭包。
- 加载中的协程不被粗暴停止；它仍负责等待 Unity 异步加载收尾并卸载迟到场景，事务门和释放标记保证其不能重新提交活动状态。

### 4. 运行诊断与构建分离

- `SceneRuntimeDiagnostics` 只保存当前事务一份受限快照，覆盖目标场景、当前场景、阶段、失败阶段、错误码、加载耗时、首帧延迟、当前分配内存和峰值分配内存。
- 诊断只在事务开始、阶段变化、场景提交、首帧、完成、失败和释放时采样；相同阶段与当前场景不重复采样或发布，旧事务与迟到首帧不能回写。
- `PowerPlantWebGlBuild.BuildDevelopmentWebGl` 是唯一显式附加开发构建标记的入口；`BuildProductionWebGl` 只使用严格模式、不可覆盖正式目录，并将主播放器与场景资源目录绑定到同一发布标识。
- 燃气最小联调包在初始化失败时仅显示协议白名单内的稳定错误码和阶段，不显示自由文本、资源地址或异常对象，便于区分场景切换与拓扑激活失败。
