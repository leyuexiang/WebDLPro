## 统一正式资料门槛

每个场景必须随同一个原子发布版本提供以下内容：

1. 可用 Unity 场景、稳定 `unitySceneKey`、资源版本、预算、加载策略、失败与降级规则，以及经过场景负责人确认的 `sceneNodeId` 清单。
2. 默认拓扑和所有可切换拓扑的正式 `topologyId`、节点、连线、二维布局、图元键、状态基线与拓扑版本。
3. 显式 `nodeId → deviceId → sceneNodeId` 映射；概念节点必须声明为不可双击，不能因为标题看起来像设备而推断 `deviceId`。
4. 外部 `actionId`、目标场景、目标拓扑、流程步骤、聚焦节点、路径、参数白名单与失败策略。
5. 版本一致的场景、拓扑、动作、设备与 Unity 映射清单，以及单元、Unity 编辑器、三层联调和资源释放的验收结果。

## 模板复用与禁止事项

燃气模板可复用的仅是：原子清单结构、版本校验、单画布拓扑、发布门禁、三层通信、受控失败与回归方式。不得复制燃气的 24 个节点、23 条连线、六条三维聚焦映射、七项流程步骤、设备状态或任何模型对象关系。

在正式资料到位前，七个场景应继续保持 `scene-content-unavailable`。这是防止场景切换误提交的保护性行为，不能作为任务-041至047的业务验收。
