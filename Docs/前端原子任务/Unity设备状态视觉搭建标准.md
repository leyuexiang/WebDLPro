# Unity 设备状态视觉搭建标准

**状态：** 当前基线  
**适用范围：** `Assets/Scenes/Business/GasPower.unity`、`Assets/Scenes/Business/CoalPower.unity` 及后续采用 `PowerPlantProcessController` 的业务场景。  
**目的：** 统一设备正常、告警、故障、离线状态的三维表现、资源生命周期和场景绑定方式，供后续场景搭建、材质配置与验收复用。

## 一、状态表现标准

| 状态 | 模型本体 | 描边 | 填充闪烁 | 插件透视 | 说明 |
| --- | --- | --- | --- | --- | --- |
| 正常 `normal` | 恢复登记时的原始材质数组 | 无状态描边 | 无 | 关闭 | 正常状态和清除动态状态均不得保留运行时状态材质。 |
| 告警 `alarm` | 告警黄色纯色半透明材质 | 告警同色描边，稳定显示 | 慢闪 | 关闭 | 填充透明度周期变化，描边不闪，保证设备持续可识别。 |
| 故障 `fault` | 故障红色纯色半透明材质 | 故障同色描边，稳定显示 | 快闪 | 关闭 | 填充闪烁频率高于告警；存在任一故障时，已登记的流动管线停止。 |
| 离线 `offline` | 不替换模型材质 | 仅在离线显示开关开启时显示灰色覆盖和描边 | 无 | 关闭 | 当前共用配置默认关闭离线三维显示；不得把节点缺失或状态清除推断为离线。 |

告警、故障的填充效果必须由模型本体的透明材质实现，不能只依赖 Highlight Plus（高亮插件）的覆盖色。插件覆盖只用于描边；否则原模型材质仍会可见，无法满足纯色半透明状态要求。

## 二、当前视觉参数

共用配置资产：`Assets/Configuration/PowerPlantVisualStateConfig.asset`。

| 配置字段 | 当前值 | 用途 |
| --- | ---: | --- |
| `_alarmColor` | `#FFB000` | 告警纯色、描边颜色。 |
| `_faultColor` | `#FF0008` | 故障纯色、描边颜色。 |
| `_offlineColor` | `#9AA4B2` | 离线覆盖和描边颜色。 |
| `_overlayOpacity` | `0.32` | 告警、故障纯色材质的最大透明度。 |
| `_fillPulseMinimumOpacity` | `0.08` | 告警、故障闪烁时的最低透明度。 |
| `_alarmFillPulseFrequency` | `0.6` 次/秒 | 告警填充慢闪频率。 |
| `_faultFillPulseFrequency` | `1.5` 次/秒 | 故障填充快闪频率。 |
| `_outlineWidth` | `0.3` | 状态同色描边宽度。 |
| `_showOfflineState` | `false` | 是否显示离线状态的三维覆盖与描边。 |

闪烁只改变填充材质的 `_Opacity`。透明度在最低值与最大值之间采用正弦曲线循环，避免突变；告警和故障各持有一份共享状态材质，因此每帧只写入两次材质属性，不遍历场景渲染器。

## 三、材质和高亮实现

### 1. 纯色半透明状态材质

状态逻辑位于 `Assets/Scripts/PowerPlant/PowerPlantProcessController.cs`。

1. 告警和故障各创建一份共享运行时材质，名称分别以 `Runtime State Alarm`、`Runtime State Fault` 结尾。
2. 状态材质复制 `PowerPlant_ContextFade` 的透明着色器，并将 `_BaseColor` 写为状态色、`_Opacity` 写为当前闪烁透明度。
3. 状态材质不复制设备原始贴图、金属度或基础颜色，确保模型本体呈现单一状态纯色。
4. 同一状态的所有已登记材质槽引用同一份共享状态材质；禁止对每个设备、每次状态更新创建新材质。
5. 正常状态或 `clearNodeVisualState` 必须恢复该渲染器登记时保存的原始材质数组。

透明材质模板：`Assets/Shaders/PowerPlant_ContextFade.mat`。其着色器必须使用透明队列、`Blend SrcAlpha OneMinusSrcAlpha` 和关闭深度写入，保证状态填充可透视背景而不会写入不透明深度。

### 2. Highlight Plus 描边

状态描边由运行时创建的 `HighlightEffect` 组件负责。告警、故障状态采用同色描边；模型本体已经由状态材质填充，状态效果的 `overlay` 必须为 `0`，避免插件覆盖色与材质纯色叠加造成颜色失真。

当前状态效果必须关闭插件透视：

```csharp
effect.seeThrough = SeeThroughMode.Never;
effect.seeThroughIntensity = 0f;
```

关闭原因：透视通道会对被遮挡区域做独立颜色处理，容易与模型本体的状态纯色不一致。后续若重新启用透视，必须先验证可见区域、遮挡区域和描边颜色一致，并记录验收截图后才能改为 `WhenHighlighted`（高亮时透视）。

流程聚焦描边、普通告警入口和状态描边是三套独立效果。修改设备状态视觉时不得改变流程聚焦的青色描边、选择清除语义或相机视角。

## 四、状态与上下文半透明的层级

设备可能同时被流程显隐逻辑要求显示为上下文半透明，又被平台状态标记为告警或故障。状态材质优先级高于上下文材质：

1. 状态开始时，先撤销该渲染器已有的上下文运行时材质，恢复原材质数组。
2. 再替换为告警或故障共享状态材质。
3. 状态期间收到新的上下文半透明请求时，只记录延迟恢复，不覆盖状态材质。
4. 状态清除时先恢复原材质；若存在延迟上下文请求，再创建上下文半透明材质。
5. 场景释放时直接恢复所有原材质并销毁运行时材质，不创建新的延迟上下文材质。

该规则保证状态色不会被流程显隐覆盖，也避免状态材质引用已经销毁的上下文材质。

## 五、场景搭建要求

1. 只有明确需要接收状态的真实模型可以写入 `_visualStateBindings`；每项必须包含稳定 `sceneNodeId` 和属性面板显式绑定的目标对象。
2. 不得根据对象名称、层级路径、二维拓扑节点或模型颜色自动推断状态目标。
3. 单个 `Renderer` 只能归属一个状态节点，防止两个业务状态交替覆盖同一模型。
4. 每个已绑定渲染器的每个材质槽必须存在控制器配置的颜色属性候选，例如 `_BaseColor` 或 `_BASE_COLOR`，否则整套状态能力应判定不可用。
5. 黑色系统、无独立模型的逻辑设备、资料未确认的对象不得加入状态绑定。
6. 状态更新不得移动相机、改变流程步骤、改变拓扑选择、重置场景或修改管线显隐；故障导致的管线停流是唯一已定义的状态联动。

燃煤场景当前允许四态的显式绑定：

| sceneNodeId | 绑定模型 |
| --- | --- |
| `node.coal-boiler` | 燃煤锅炉、汽包、下降管。 |
| `node.coal-steam-turbine` | 低中高压汽轮机。 |
| `node.coal-generator` | 发电机、励磁机。 |

燃气场景当前允许四态的显式绑定：

| sceneNodeId | 绑定模型 |
| --- | --- |
| `gas-turbine` | 燃气轮机。 |
| `hrsg` | 余热锅炉。 |
| `steam-turbine` | 蒸汽轮机。 |

## 六、总览与关键流程场景搭建标准

本节记录当前燃气、燃煤场景已验证的视觉基线。后续使用 `PowerPlantProcessController`（电厂流程控制器）搭建新场景时，必须优先通过属性面板显式配置对象集合，不得根据对象名称在运行时猜测。

### 1. 总览显示层级

总览必须显示场景模型，但通过材质层级突出核心设备：

1. `_groundObjects`（地面对象）始终激活，并在总览和复位时保持原始不透明材质。
2. 流动管道和电线由流动 Shader（着色器）自动识别，在总览保持原始材质和流动效果。
3. `_overviewOpaqueObjects`（总览不透明对象）用于登记不使用流动 Shader、但总览仍需保持正常显示的辅助设备、支撑或普通材质管道。
4. `plant.overview` 的可见节点目标保持原始材质，作为总览核心设备集合。
5. `_overviewContextObjects`（总览上下文对象）用于登记场景根节点之外的建筑、外壳等背景模型；这些对象总览时显示但使用上下文半透明材质。
6. 其他已激活模型总览时显示为上下文半透明，不隐藏模型，不移动相机。

总览配置优先级为：地面、流动管道、`_overviewOpaqueObjects`、`plant.overview` 核心目标保持不透明；`_overviewContextObjects` 和其他非核心模型使用上下文半透明。

### 2. 关键流程显示层级

关键流程进入 `isolate=true`（隔离模式）时：

1. 当前流程核心设备按步骤绑定正常显示，非核心设备使用上下文半透明。
2. 全部流动管道保持显示并使用上下文半透明，以保留工艺流向；故障停流由设备状态逻辑单独控制。
3. 地面保持激活，但使用上下文半透明，降低对关键设备的干扰。
4. `isolate=false` 时恢复初始显隐和材质；不应把关键流程的半透明规则误用于复位或总览。

### 3. 当前燃气场景参考配置

场景：`Assets/Scenes/Business/GasPower.unity`。

- 总览核心设备：燃气轮机、余热锅炉、低中高压汽轮机、发电机、变压站+电网。
- 总览额外不透明对象：管道2、取水泵站、增压站+变压器、支撑结构1、凝汽器、台阶、屋顶蓬、烟囱。
- 总览半透明外壳：完整场景外壳遮罩1。
- 地面：场景/地面；总览不透明，关键流程隔离模式半透明。
- 流动对象：由 `自定义/URP/管道流动` Shader 自动识别，不能因未填写 `_persistentFlowObjects` 而遗漏。

### 4. 当前燃煤场景参考配置

场景：`Assets/Scenes/Business/CoalPower.unity`。

- 总览不透明对象按本轮场景选中清单登记：组件支撑、低中高压汽轮机、储油罐、冷却塔、凝汽器、加热器、励磁机、发电机、取水泵站、变压站+电网、增压站+变压器、所有外壳遮罩以外的其余选中设备、烟囱、燃煤锅炉2、连续排污扩容器、闭式冷却塔2+循环水泵、除尘器、除氧器、送油管道1、电线、汽包、水管、水泵、下降管1。
- 总览半透明外壳：所有外壳遮罩。
- 总览其他上下文：建筑群、水池群。
- 地面：SceneRoot/Environment/地面；总览不透明，关键流程隔离模式半透明。
- 燃煤当前主要流动管道使用流动 Shader；后续新增普通材质管道必须显式加入 `_overviewOpaqueObjects`。

### 5. 新场景验收清单

1. 总览进入后：核心设备、管道、地面和明确登记的不透明对象无 `Runtime Context`（运行时上下文）材质。
2. 总览进入后：外壳和未登记辅助模型使用上下文半透明，模型仍保持激活。
3. 关键流程隔离模式进入后：地面和非核心模型出现 `Runtime Context` 材质，核心设备仍清晰可辨。
4. 总览、复位、关键流程连续切换后，原始材质数组可恢复，运行时材质无残留。
5. 不得通过名称模糊匹配自动补充对象；对象必须由场景序列化字段显式引用。

## 八、资源与性能要求

1. 禁止在 `Update`、状态更新或流程切换中遍历整个场景寻找状态模型。
2. 状态节点的渲染器必须在初始化阶段缓存，状态更新只按 `sceneNodeId` 查询缓存。
3. 告警、故障各只允许一份共享状态材质；状态切换不得访问 `Renderer.material`，只能使用 `sharedMaterials`。
4. 闪烁路径每帧仅更新已创建的告警、故障两份材质的 `_Opacity`，不创建数组、材质、列表或属性块。
5. 清除状态、切换场景和 `ReleaseOwnedRuntimeResources` 必须恢复原始材质数组，并销毁控制器拥有的运行时材质。
6. 运行时材质名称必须包含固定 `Runtime State` 或 `Runtime Context` 后缀，便于自动化测试检查资源是否泄漏。

## 九、验收清单

新增或调整场景状态视觉时，至少验证以下项目：

1. 告警后，真实目标模型使用 `Runtime State Alarm` 材质，颜色为告警色，透明度在 `0.08–0.32` 范围慢闪，描边稳定。
2. 故障后，真实目标模型使用 `Runtime State Fault` 材质，颜色为故障色，透明度在 `0.08–0.32` 范围快闪，描边稳定，管线停止。
3. 正常状态和 `clearNodeVisualState` 后，模型恢复到状态更新前的原始材质数组。
4. 流程上下文半透明与告警/故障同时存在时，状态纯色优先；状态清除后按当前流程恢复应有的上下文半透明。
5. 场景卸载、重置和连续场景切换后，运行时状态材质和上下文材质不会残留。
6. 离线显示开关关闭时，离线状态不应替换模型材质或显示三维描边。
7. Unity 控制台无错误、无警告；编辑器测试和播放模式回归均应通过。若测试运行器因编辑器状态异常无法启动，必须记录原因，并补充实际播放模式的材质名称、颜色、透明度和恢复验证。

## 十、当前验证记录

本标准对应的近期人工与运行时验证结果：

- 告警模型实际使用 `PowerPlant_ContextFade (Runtime State Alarm)`，状态色为 `#FFB000`，透明度基线为 `0.32`。
- 故障模型实际使用 `PowerPlant_ContextFade (Runtime State Fault)`，状态色为 `#FF0008`，透明度基线为 `0.32`；清除后恢复原始材质。
- 燃煤场景跨五次采样确认告警、故障透明度持续变化，且故障变化速度高于告警。
- 插件透视已经关闭，防止遮挡区域和模型本体出现颜色不一致。
- 本轮编辑器模式回归曾通过 `24/24`，运行时材质验证期间 Unity 控制台无错误、无警告。播放模式测试运行器曾因在播放模式启动导致的测试框架残留“取消中”状态无法重新启动；该工具问题不改变上述直接运行时验证结论，后续应在干净编辑器会话重新执行完整播放模式回归。
