# 十三场景当前配置基线

本文记录开发时需要快速核对的当前边界。数量和标识来自现行生成器、Unity 配置与测试；发生变更时应重新生成并整体更新，不保留旧版本流水账。

`overview`（全局沙盘总览）已在联合清单 `scenes` 数组中登记独立场景条目：`sceneId` 与 `unitySceneKey` 均为 `overview`，不携带任何业务拓扑字段，`supportedActionIds` 双向收录 `action.scene.overview`、六个区域高亮动作和两个轮询开关动作；平台按当前场景解析动作时与业务场景同构。它仍不属于十三项业务场景闭集（前端 `SCENE_IDS` 与 Unity `BusinessSceneCatalog` 均不变），Unity 侧由独立 `OverviewSceneCatalog` 提供同名目录与场景包。四个站类总览均已登记显式 `sceneNodeId`；前三个场景各发布三项保护拓扑上下文和进入动作，开关站发布母线保护和线路保护。正式 Unity 包仍必须由 `ProcessDetailCatalog.asset` 中同名包装预制体和资源包构建结果证明，不能只凭前端目录判定完成。

楼宇六项映射是当前前端—Unity 编号契约，Unity 场景对象仍待按[楼宇六节点三维映射约定](拓扑图/楼宇拓扑六节点三维映射约定.md)配置；登记数不代表 Unity 对象已完成绑定。

微电网六项映射仅覆盖默认网络层+业务层+关键环节层组合，六个节点均按设备层登记：前端使用 `asset.*`，Unity 场景节点使用 `node.*`；编号见[微电网拓扑六节点三维映射约定](拓扑图/微电网拓扑六节点三维映射约定.md)。其他拓扑变体保持未绑定。

风电当前登记七个三维场景节点：第二层仅映射变桨系统、变流系统、偏航系统、传动系统、刹车系统五个设备节点；控制层图元不登记跨端映射。风机、齿轮箱和偏航系统三个第三层目标均使用既有目录编号；偏航的 `node.wind-yaw-system` 与第二层偏航设备共用同一场景节点，不重复增加场景映射。逐文件编号见[风电拓扑五系统三维映射约定](拓扑图/风电拓扑五系统三维映射约定.md)和[风电偏航关键环节与合作方入口](拓扑图/风电偏航关键环节与合作方入口.md)。Unity 场景资产仍需按相同 `sceneNodeId` 核对后联调。

## 二、燃气与燃煤参考边界

- 两个场景均有 6 个第二层命名镜头按钮；前端只发送稳定 `cameraPoseId`，Unity 负责镜头和临时视觉效果。
- 两个场景均登记 8 对二维/三维节点映射。上层控制节点只接受拓扑聚焦，下层现场设备负责反向选择和四态。
- 燃气第三层使用 `process-detail.gas-power.gas-turbine`；燃煤第三层使用 `process-detail.coal-power.steam-turbine`。
- 两个场景的第二层拓扑均以 `network+business+key-process` 为显式默认组合，并复用公共画布、资源、选择、高亮、重置与状态快照。
- 升压站、降压站和换流站按燃气/燃煤的第二层场景引用基线配置：显式 Scene Root 与交互相机，开启选中聚焦，关闭启动总览上下文半透明，复用 `PowerPlant_ContextFade`，并显式登记地面与总览不透明对象；没有正式内部入口资料时不绑定 Priority Pointer Consumer。
- 开关站沿用同一配置原则，已完成正式浏览场景、目录条目、构建登记、总览入口和 4 个语义节点绑定：保护装置、测控装置、断路器、互感器；断路器和互感器同步登记四态视觉目标。由于拓扑资料未提供逐图元三维关系，前端映射仍需后续显式补充。
- 全局桥接能识别路径流命令，不代表燃气、燃煤业务场景支持动态路径流；未被适配器和序列化配置共同证明的能力不得发布。

第三层不使用第二层的 `layerIds` 或 `combinationKey`，不显示或接受筛选事件。上下文切换只替换完整拓扑数据和文件级绑定，公共画布与中央状态快照保持复用。齿轮箱详情包含主控制器、散热风扇、润滑油装置、太阳能、行星齿轮、圆柱齿轮和高速轴七个可选设备图元；“太阳能”按来源文件原文保留。齿轮箱七项及偏航详情的主控制器和五个设备图元只支持二维选中，不假定其拥有独立三维目标。

风机详情按最新完整输入展示“控制层”“设备层”“工艺流程”和“主控制器”。十一台设备与三个工艺矩形分别开放二维选择和关联线高亮；只有设备图元显示正常默认态提示，工艺矩形不生成设备提示。该文件没有显式三维图元绑定，不能将第二层五系统映射或整机状态节点直接套到第三层控制和设备图元上。

风电五个第三层合作方状态节点通过 `processDetails[].topologyNodes` 发布，并与对应 `penId → nodeId` 绑定逐项一致：风机图中的“偏航系统”=`asset.wind-turbine-yaw-system`、“传动系统”=`asset.wind-turbine-drivetrain-system`；齿轮箱图中的“散热风扇”=`asset.wind-gearbox-cooling-fan`、“润滑油装置”=`asset.wind-gearbox-lubrication-unit`；偏航图中的“角度传感器”=`asset.wind-yaw-angle-sensor`。这些编号仅用于第三层二维状态，均不声明 `sceneNodeId`，也不进入 Unity 映射；状态只绘制在当前匹配的第三层文件中。

## 五、更新要求

1. 场景、动作、第三层或映射变化时，同步更新 Unity 配置、前端清单、最终门禁、正负向测试和本文。
2. 本文不保存构建目录、完成比例、旧包编号和已完成任务列表。
3. 无正式资料的场景保持空映射或受控导航能力，不复制燃气、燃煤业务语义。
4. 若检查脚本与当前清单结构不兼容，应先修复检查脚本，不能回退清单结构或用旧文档数量替代事实源。
