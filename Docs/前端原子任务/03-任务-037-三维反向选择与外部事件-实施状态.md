# 任务-037：三维反向选择与外部事件实施状态

**状态：** 进行中（80%）
**更新时间：** 2026-08-09

## 已实施

- `TopologyRegistry`（拓扑注册表）仅从已发布的 `deviceMappings`（设备映射）建立“场景标识 + 三维节点标识”常数时间索引。不根据 Unity 对象名称、层级、坐标、截图或字符串相同推导设备。
- `UnityObjectSelectionCoordinator`（Unity 对象选择协调器）只接受 `sceneId`（场景标识）、`sceneNodeId`（三维节点标识）和 `sceneActivationId`（物理场景激活标识）。它依次核对稳定上下文、唯一活动拓扑、场景、物理实例和显式设备映射，才同步二维节点与相邻连线。
- 物理场景激活标识由 `MultiSceneCoordinator`（多场景协调器）在每次真实场景提交或物理恢复提交时递增生成；同场景拓扑切换不改变它。该规则解决“燃气实例一 → 其他场景 → 燃气实例二”后，实例一迟到选择可能被实例二误接收的问题。
- Unity `objectSelected`（对象选择）与 `sceneChanged`（场景切换完成）都必须携带物理场景激活标识。内层协议仅允许对象选择载荷的三个字段，拒绝对象名称、场景状态、层级、路径、旧二维 `nodeId`（拓扑节点标识）和任意扩展字段。
- `view.open`（原子打开视图）端口只接受已验证的场景激活标识；跨场景成功提交时记录新实例，同场景拓扑切换沿用旧实例，物理回退成功时才替换为恢复后的实例。
- 场景切换失败但 Unity 已自动恢复旧稳定场景时，失败 `commandResult`（命令结果）携带恢复后的新物理场景激活标识；前端恢复旧上下文时同步替换该标识，避免真实恢复后的新实例被当作旧实例。
- 同一内层消息标识通过固定 64 条先进先出队列在基础校验后立即登记。无映射、场景失配和实例失配事件同样只诊断一次，避免重复回放造成诊断洪泛或在后续稳定状态中被重试。
- 三维选择只提交来源为 `unity`（三维）的二维选择，绝不调用 `focusNode`（聚焦节点），因此不会形成 Unity → 二维 → Unity 的选择回环。
- `HostRuntimeComposition`（宿主运行时组合根）在发送 `scene.object.selected`（三维对象选择）前再次核对握手、稳定场景、拓扑、上下文版本、设备标识和非空二维节点，阻断绕过映射协调器的直接调用。
- 本地三层 Unity 模拟页同步升级为生成并回传物理场景激活标识；该夹具仅验证协议机制，绝不代表正式燃气设备资料。
