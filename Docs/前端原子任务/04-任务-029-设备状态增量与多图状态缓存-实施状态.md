# 任务-029：设备状态增量与多图状态缓存实施状态

**状态：** 已完成（100%）
**更新时间：** 2026-08-07

## 已实施

- 新增 `TopologyDeviceStateCache`（拓扑设备状态缓存）。它按显式 `deviceId`（设备标识）合并批量更新，并只通过原子清单中的 `DeviceMappingDefinition`（设备映射定义）投影到二维 `nodeId`（节点标识）和可选三维 `sceneNodeId`（三维节点标识）。
- 同一批次同一设备优先保留最新时间，时间相同保留最后一项；跨批次较旧时间戳被丢弃。相同时间戳只接受更高的来源修订号，缺少修订号的重复时间按幂等重放处理。
- 设备状态只允许正常、告警、故障、离线四态；状态缺失或非法时在状态适配器内归一为离线。外层协议仍会在更早的安全边界拒绝非法公开载荷，适配器的离线归一用于受控内部数据源和未来批量协调器。
- 最近设备状态容量固定为 500；二维拓扑和三维场景状态快照均为固定容量 8 的最近最少使用缓存。当前活动场景与活动拓扑在淘汰时受保护；被淘汰的非活动图再次激活时只从有限设备状态缓存按需恢复。
- 状态覆盖只保存偏离拓扑发布基线的二维节点。正常回到基线时自动删除覆盖，画布自然回退清单状态，不创建全节点冗余副本。
- `TopologyRuntime`（拓扑运行时）新增批量状态接口。它只增量交给唯一画布的节点状态通道，不重建拓扑定义、路径、选择、缩放或平移；同时返回当前场景显式三维节点状态快照，供任务-038按能力协商后向 Unity 发送。
- 画布端口通过组件属性同步状态快照，避免运行时端口与 Vue（渐进式网页框架）观察器对同一批状态重复遍历和重复调度绘制。现有画布适配器继续使用单帧合并重绘与像素比上限。
- 注册表新增设备映射和拓扑节点的常数时间索引；发布校验新增“同一场景三维节点不能映射多个设备状态源”约束，避免批量状态按到达顺序相互覆盖。
- 运行时释放时清空设备时间、二维快照、三维快照和活动上下文，不保留状态消息、画布、Unity 对象或无界缓存。
- 基线状态也保留受容量限制的空二维、三维快照标记。这样设备状态回到拓扑发布基线后，活动拓扑的后续读取不会重复扫描最多 500 条设备映射；空快照仍与非空快照共用容量 8 的最近最少使用淘汰，不增加无界内存。
- 快照淘汰改为直接遍历 `Map`（映射）迭代器，不再为最多八项的最近最少使用淘汰创建临时键数组。状态缓存只负责批次合并和有限快照；同一动画帧的画布绘制继续由已有 `CanvasTopologyAdapter`（画布拓扑适配器）统一压缩，避免重复帧调度器。

## 验证

- 专项测试覆盖：同批设备合并、过期状态丢弃、同时间戳修订号比较、四态逐项覆盖、非法状态离线化、无映射与无效时间拒绝、设备容量淘汰同步清除二维/三维旧覆盖、有限快照按需恢复、释放清空活动上下文，以及状态更新不改写拓扑、选择、缩放和平移。
- 清单校验测试覆盖：多个设备映射同一场景三维节点会被发布校验拒绝。
- 本轮专项回归：3 个测试文件、16 项测试通过；前端全量回归为 36 个测试文件、172 项测试通过，类型检查和生产构建通过。

## 后续任务边界

1. 任务-029按原始交付与验收口径关闭：状态适配器、时间戳比较、批量接口、同批去重、有限多图快照、四态降级、视图不变和释放均已有直接证据。画布层在同一动画帧内只绘制最终覆盖值。
2. 多条外层状态命令跨批次按动画帧合并后再向 Unity 下发，以及将 `statusUpdatedAt`（状态更新时间）继续传入内层 `setNodeVisualState`（设置节点视觉状态）载荷，属于任务-038的三维协调与协议补强，不在本任务缓存职责内。
3. 状态“超过实时协议有效期后自动离线”需要外部状态字段、发送频率、最大批量和超时阈值。架构资料明确仍缺这些输入，本任务未猜测固定超时时间；收到正式契约后由任务-038和任务-054补充定时降级与性能验收。
4. 正式九场景设备、二维节点与三维节点映射归任务-039—047；当前测试清单只证明框架机制，不代表正式业务设备状态。
