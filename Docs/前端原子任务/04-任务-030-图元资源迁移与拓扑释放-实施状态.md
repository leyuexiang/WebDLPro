# 任务-030：图元资源迁移与拓扑释放验收实施状态

**状态：** 已完成。
**最后更新：** 2026-08-21。

## 一、完成结果

1. 将生产登记表实际引用的 52 个 SVG 图元迁入 `power-data-web/src/assets/topology-icons`。
   - 图元范围为 13 个受控图元键，每个键完整包含正常、告警、故障、离线四态。
   - 历史设计资料目录保留，不删除、不移动，避免影响文档参考与用户未提交改动。
   - 对每一个迁入文件执行 SHA-256（安全散列算法）比对，52 个目标文件均可在历史来源中找到相同内容。
2. 更新 `power-data-web/src/services/topology/topology-icon-registry.ts`。
   - 生产资源地址统一使用前端资产目录的 Vite（前端构建工具）静态地址转换。
   - 导出冻结的正式图元键目录和 `13 × 4 = 52` 的图片缓存理论上限。
   - 中性 `generic` 图元与未知键均不产生 SVG 地址，不能根据外部输入请求资源。
3. 更新 `power-data-web/src/services/topology/canvas-topology-adapter.ts`。
   - 图片缓存达到受控图元键与四态组合的上限后不再创建图片对象。
   - 释放时取消动画帧、断开每个图片的加载与失败回调、清空缓存，并将画布像素缓冲和样式尺寸归零。
   - 归零可在 Vue（渐进式网页框架）移除画布前释放高分屏内部位图，避免拓扑切换或路由退出后保留大尺寸缓冲区。

## 四、边界与后续事项

1. 本任务迁移的是当前登记表实际引用资源，不主张未登记的 540 个以上历史图元已成为正式生产资产。
2. 九个业务场景的正式图元选择、设备映射和拓扑清单仍由任务-039—047逐项交付；不得借本次图元迁移推断其业务含义。
3. 真实目标硬件上的长时间内存、显存与帧率数据属于任务-054；本任务证明的是缓存容量、回调和画布缓冲的代码级释放边界。
4. 历史文档目录可在后续资料治理任务中单独评估是否归档；本任务未删除任何历史资源。

## 五、2026-08-21 新图标首批增量

1. 根据 `Docs/拓扑图图标` 的三份中文名称对照表，首批迁入核心交换机、塔式服务器和工作站三类图元的正常、故障、停止/离线资源，共9个透明便携式网络图形（PNG）。源文件与正式资产逐一执行安全散列算法（SHA-256）比对，结果全部一致。
2. 状态语义按需求确认：素材“警告”实际用于 `fault`（故障），`alarm`（告警）暂时没有新素材并继续使用原可缩放矢量图形（SVG）；素材“停止”作为当前 `offline`（离线）的停止视觉，不修改既有四态协议。
3. 登记表仍保持13个图元键、每键4态和52个运行时资源上限。首批三类图元各使用3个新PNG和1个旧告警SVG，其余10类图元继续使用原四态SVG；未被登记表引用的旧文件保留，便于素材不匹配时回退。
4. 防火墙暂不替换：正常与停止表的“防火墙 / 安全网关”在故障表中没有同名项，不能把“防火墙（砖墙）”等相似名称视为同一设备。其余未能与现有图元键精确对应的素材也继续待补，禁止按图层编号或图片外观推断。
5. 新素材只从文档目录迁入前端正式资产目录；生产源码和构建产物不引用 `Docs`。后续素材补充仍须经过名称、状态语义、透明背景、尺寸、登记表完整性和视觉回归检查。
