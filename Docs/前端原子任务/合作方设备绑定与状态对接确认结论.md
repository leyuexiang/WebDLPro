# 合作方节点绑定与状态对接确认结论

**最新确认日期：** 2026-08-14  
**文档状态：** 当前正式对接依据  
**历史依据：** 《合作方设备绑定与状态对接待确认问题-回复1》《合作方设备绑定与状态对接二次确认问题-回复》及2026-08-14双方会议结论

本文件中的2026-08-14会议结论优先级最高。此前“平台向我方注入 `deviceId`、`deviceMappings` 和 `platformBindingCount`”的理解已确认是沟通偏差，相关设计、代码、测试和联调包只作为历史实现证据，不再作为新协议依据。

## 一、最新正式结论

1. 我方提供稳定拓扑节点编号 `nodeId`，平台读取该编号并在平台内部维护 `nodeId → 真实设备编号`。
2. 平台不向我方清单、页面、消息或状态缓存注入 `deviceId`，也不提供 `deviceMappings`、`platformBindingCount` 或绑定修订。
3. 我方结构清单直接作为壳运行事实源，不等待平台生成绑定后的运行时清单。
4. 双击拓扑节点时继续发送 `topology.node.dblclick`，载荷只含 `sceneId`、`topologyId`、`nodeId`。
5. 状态命令继续使用已约定的 `device.states.update` 消息类型，但每个状态项以 `nodeId` 为关联键。
6. 我方二维与三维只通过静态 `nodeId → 可选 sceneNodeId` 映射关联；平台真实设备编号不参与三维目标派生。
7. 三维失败、超时或部分失败不得影响、延迟、撤销或补发外层成功回执。

## 二、双方责任边界

### 2.1 我方负责

- 发布不可变结构清单，提供 `resourceKey`、场景、拓扑、动作、`nodeId`、可选 `sceneNodeId` 和节点双击能力。
- 保证 `nodeId` 在单个 `resourceKey` 内全局唯一。
- 关键流程过滤视图复用总图同一 `nodeId`，不复制逻辑节点定义。
- 校验 `nodeId → 可选 sceneNodeId` 和 `sceneNodeId → nodeId` 唯一闭环。
- 按 `nodeId` 处理双击、完整状态快照、二维投影和可选三维同步。
- 保留来源、会话、消息去重、超时、容量、释放和三维失败隔离。

### 2.2 平台负责

- 读取我方结构清单中的 `nodeId`。
- 在平台内部建立和维护 `nodeId → 真实设备编号`，绑定数据不回写我方清单。
- 双击事件到达后，使用收到的 `nodeId` 查询平台内部绑定并执行平台业务。
- 发送状态时，将平台内部设备状态转换为以 `nodeId` 为主键的完整四态快照。
- 保证同一业务状态快照中使用的 `nodeId` 与当前我方结构清单版本一致。

## 三、结构清单约束

1. 清单不得出现 `deviceId`、`deviceMappings`、`platformBindingCount` 或绑定修订字段。
2. `nodeId` 在单个 `resourceKey` 内全局唯一，不能只保证单张拓扑内唯一。
3. 同一逻辑节点在总图和过滤视图中复用同一 `nodeId`。
4. 不同业务场景不得复用同一个逻辑节点编号；新节点采用场景业务前缀或等效全局可区分命名。
5. 每个 `nodeId` 最多登记一个 `sceneNodeId`；同一场景内每个 `sceneNodeId` 最多反向对应一个 `nodeId`。
6. 不得根据标题、坐标、图标、模型名称、对象层级或数组顺序推断映射。

如果未来允许同一 `resourceKey` 内重复 `nodeId`，状态载荷必须增加 `sceneId` 或 `topologyId` 形成复合键；在当前只有 `nodeId` 的协议下禁止重复。

## 四、双击节点事件

```json
{
  "type": "topology.node.dblclick",
  "payload": {
    "sceneId": "gas-power",
    "topologyId": "topology.gas-power.overview",
    "nodeId": "asset.gas-turbine.1"
  }
}
```

规则：

1. 载荷不得包含或等待 `deviceId`。
2. `nodeId` 必须来自当前活动结构清单。
3. 双击保留单击产生的二维选中和可选三维聚焦，但不得重复发送相同聚焦命令。
4. 平台收到事件后自行查询内部设备绑定；未绑定时的业务提示由平台处理，不由我方伪造设备编号。

## 五、节点状态完整快照

消息类型仍为 `device.states.update`，只修改状态项关联键：

```json
{
  "type": "device.states.update",
  "payload": {
    "sourceRevision": 1024,
    "items": [
      {
        "nodeId": "asset.gas-turbine.1",
        "deviceStatus": "alarm",
        "statusUpdatedAt": "2026-08-14T10:00:00.000+08:00"
      }
    ]
  }
}
```

处理规则：

1. `items` 是当前 `resourceKey` 的完整节点状态快照，不是跨批增量补丁。
2. 每份合法快照按到达顺序原子替换上一份；`sourceRevision` 和 `statusUpdatedAt` 只用于诊断，不用于拒绝较小修订。
3. 同批重复 `nodeId` 时最后一项生效；未知 `nodeId` 忽略且不影响整批成功。
4. 新快照缺失的旧节点清除动态覆盖并恢复发布基线；缺失不等于离线。
5. 只有平台明确发送 `offline` 才显示离线。
6. 壳为每份已接受快照生成会话内本地 `snapshotSequence`，只用于隔离三维异步迟到结果。
7. 当前协议容量继续保持单批1至500项；超过容量时整批拒绝，不静默截断。该容量是消息保护，不再对应平台设备绑定数量门禁。

## 六、三维同步与回执

1. 二维完整快照成功提交后立即返回唯一成功回执。
2. 有 `sceneNodeId` 的节点异步尝试同步三维四态；无映射节点只更新二维，不属于失败。
3. Unity未就绪、能力缺失、节点拒绝、部分失败、全部失败、超时或释放竞争只记录固定容量脱敏诊断。
4. 上述三维问题不得回滚二维，不得延迟、修改、撤销或重复外层成功回执，也不得触发平台重发已成功提交的快照。
5. Unity恢复或场景重新激活后，只从当前最新完整快照重投影，不重放已被替换的旧批次。

## 七、已废止的旧口径

以下内容自2026-08-14起全部废止：

- 平台向节点注入 `deviceId`。
- 平台生成 `deviceMappings.topologyNodeRefs`。
- 壳等待或读取平台绑定后的运行时清单才能启动。
- `platformBindingCount` 和第五百零一台绑定保存门禁作为我方发布或启动条件。
- `doubleClickBehavior: 'emit-device'` 和“未绑定节点不发送双击事件”。
- 按 `deviceId` 建立二维状态、三维状态或反向选择索引。
- 双击事件回传 `deviceId`，三维反向选择回传设备编号。

旧口径对应的代码、测试和包不得直接删除，必须按[任务-056：节点标识关联协议偏离调整](08-任务-056-节点标识关联协议偏离调整.md)建立保护性基线后迁移和验证。

## 八、仍需联调确认的事项

1. 平台读取我方结构清单的正式地址、部署来源和刷新时机。
2. 平台内部绑定页面如何展示 `resourceKey + nodeId + 真实设备编号`，以及未绑定节点的提示方式。
3. 平台发送的首份 `nodeId` 状态样例和真实四态数据。
4. 双击节点后平台是否能按 `nodeId` 正确找到内部设备并打开对应业务。
5. 正式环境父页面来源、我方壳来源、Unity子页来源、安全负责人和回滚验收记录。
