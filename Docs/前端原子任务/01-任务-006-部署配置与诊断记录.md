# 任务-006：部署配置与基础诊断记录

## 已交付

- 新增 `power-data-web/src/config/deployment/deployment-config.ts`：读取并校验父页面精确来源、Unity 子页入口、清单地址和最小容器尺寸。
- 新增 `power-data-web/.env.example`：只提供示例变量名和示例域名；开发和生产都必须由 `.env.local` 或部署流水线显式注入，源码不再回退到本机端口。
- 运行时登记表改为只接收已验证的部署配置；配置缺失时不创建 Unity 内嵌框架登记。
- 新增嵌入壳诊断模型，覆盖 `runtime.initializing`、`container.too-small`、`deployment.invalid`、`unity.runtime-failed`、`topology.invalid` 和 `runtime.disposed`。
- 嵌入壳通过 `ResizeObserver`（尺寸观察器）按部署配置检测可用尺寸；卸载时释放观察器。
- 状态组件展示稳定错误代码和当前壳关联标识，但不显示环境变量、完整外部消息或 Unity 原始异常载荷。

## 验证证据

- `npm run typecheck`：通过。
- `npm run test:unit`：8 个测试文件、28 项测试通过。
- 注入模拟正式地址后执行 `npm run build`：通过。
- 对生产 `dist`（构建产物）检索 `localhost:5173` 与 `localhost:8081`：无匹配项。

## 未关闭的外部依赖

- 父页面、当前子应用、Unity 子页和正式清单的真实部署来源尚未提供，因此 `.env.example` 只能使用示例域名。
- 1280 × 720 来自架构设计的推荐可用区域；最终最小尺寸由部署变量控制，需由父页面负责人确认。
- 远程清单下载及其版本发布将在后续场景拓扑运行时接入；当前任务仅建立受控地址读取和错误边界。
