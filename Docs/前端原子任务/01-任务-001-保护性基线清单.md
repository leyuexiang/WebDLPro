## 一、基线结论

1. 当前前端仍是“门户 + 后台 + 可视化工作台”应用，不是单一可嵌入可视化子应用；路由、导航、权限、34 个工艺页模型、专题、详情、请求、实时与图表职责均在生产构建中。
2. 现有三维能力可复用：唯一内嵌框架宿主、精确来源校验、内部通信协议、命令确认、超时、释放、尺寸观察和单实例约束均已有实现。
3. 现有拓扑能力可复用：单一画布、动画帧合并、像素比上限、命中缓存、缩放、平移、全屏、状态图元与释放逻辑均已有实现。
4. 当前实现不能直接满足新架构：没有外层父页面通信桥，没有九场景单实例切换，没有多拓扑登记与双击设备上报，且旧配置以 34 个页面而非 9 个 `sceneId` 为中心。
5. 本机燃气运行时登记、燃气三维全屏和动作载荷刚有用户未提交修改；它们是后续迁移输入，不得在任务-003前直接删除或覆盖。

2. **用户改动重叠：** `ProcessScenePanel.vue` 的全屏、16:9视口和加载提示调整，以及协调器的 `isolate` 布尔载荷，均应在新壳中迁移保留并回归验证。
3. **协议口径：** 当前 Unity 桥接回传白名单为 `ready`、`ack`、`commandResult`、`sceneLoadProgress`、`sceneChanged`、`objectSelected`、`selectionCleared`、`disposed`。`object-click` 和 `test-result` 仅属于旧测试事件，不得进入生产协议；`selectionCleared` 只允许携带 `sceneId` 与 `sceneActivationId`。
4. **单场景限制：** 当前 Unity 构建设置仅启用 `SampleScene`，现有控制器只支持燃气流程；没有九场景加载、卸载、进度、恢复或资源版本能力。
5. **拓扑性能缺口：** `TopologyCanvas.vue` 将拓扑定义和选择放入同一监听，选择变化会再次调用 `setTopology` 并使路径缓存失效；任务-023至任务-030前不得把它当成已完成的多拓扑实现。
6. **资源位置风险：** 图元登记直接引用 `Docs` 目录；在资源迁移完成前，删除或整理文档都会破坏拓扑构建资源。
7. **正式结构与部署资料仍不齐全：** 旧资料曾记录固定清单接口、运行时设备编号注入和二维引用派生三维；该口径已被最新会议废止。当前仍缺九场景内容、默认拓扑、动作、`doubleClickBehavior`、`nodeId`、`sceneNodeId`、正式来源、性能基线、资源策略及合作方三项改造证据。任何按标题、模型名、截图或坐标补全的映射均不允许。
8. **历史文档失效：** `power-data-web/docs/实施记录-第一阶段.md` 的旧任务编号和“完成”状态不适用于新原子任务，不可据此跳过新验收。
