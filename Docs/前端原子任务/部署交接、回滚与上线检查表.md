# 部署交接、回滚与上线检查表

## 一、交接资料

- [ ] 不可变发布标识、包类型和资源摘要已登记。
- [ ] `scene-topology-manifest.json`、`release-manifest.json` 和 Unity 能力元数据来自同一次构建。
- [ ] 部署地址、监听端口、父页面来源和 Unity 子页来源符合目标环境。
- [ ] 平台未修改压缩产物、清单或摘要脚本。
- [ ] 未交付能力已明确标记为不支持或待确认。

## 二、上线前验证

- [ ] 最终产物门禁结果为 `valid`，问题数为零。
- [ ] 平台能读取同源结构清单并生成全部公开动作入口。
- [ ] 场景进入、默认拓扑、第三层进入/退出和全局总览可用。
- [ ] 节点双击只上报 `nodeId`，平台内部绑定不回写我方清单。
- [ ] 完整状态快照在二维与已映射三维节点间一致。
- [ ] 快速切换、命令超时、资源失败和迟到事件不会破坏稳定上下文。
- [ ] 全屏、窗口缩放、拓扑重置和长时间运行无明显泄漏。

## 三、部署检查

- [ ] 浏览器公开地址不使用 `0.0.0.0`。
- [ ] 正式环境未暴露自测页、测试夹具和调试控制器。
- [ ] Unity 主资源、场景资源包和关键环节资源包使用当前缓存策略。
- [ ] 内嵌网页框架来源限制、消息来源校验和协议版本与环境一致。
- [ ] 服务重启后仍能读取同一不可变发布目录。

## 四、回滚

1. 停止向新发布目录导流。
2. 恢复上一份已通过门禁的完整目录，不混用新旧前端、Unity 或清单文件。
3. 清理浏览器和代理层中与失败发布标识相关的缓存。
4. 重新执行场景进入、状态、第三层和协议握手验证。
5. 记录失败发布标识、根因和后续修复，不修改失败产物伪装成新版本。

## 五、完成条件

工程侧测试通过不等于平台验收完成。只有最终产物门禁、部署检查、合作方真实消息联调、节点绑定、状态同步、二维/三维联动和回滚演练全部通过，才可标记正式上线。
