# 任务-019：桥接管理器跨场景生命周期实施状态

## 结论

任务-019已完成。`UnityIframeBridgeManager` 现在在整个 Unity 子应用生命周期内保持唯一：浏览器桥接只初始化一次；正式 Bootstrap 在兜底桥接器已存在的情况下也会在场景加载时完成协调器重绑；业务场景切换仅更新当前统一业务场景控制器，不重复注册协调器或浏览器回调。

用户确认的原 `SampleScene` 已作为燃气发电场景，正式映射路径为 `Assets/Scenes/Business/GasPower.unity`；本任务没有修改其业务内容。

## 交付内容

- `Assets/Scripts/UnityIframeBridgeManager.cs`
  - 新增浏览器桥接初始化计数与协调器订阅计数的只读诊断属性。
  - 以幂等保护确保一个常驻实例只调用一次浏览器桥接初始化。
  - 保存实际订阅的协调器引用，重绑或销毁时精确解除三个事件，避免旧委托持有桥接器。
  - 订阅 Unity 场景加载事件；Bootstrap 在兜底桥接器之后加载时能够重绑协调器，不使用逐帧轮询。
  - 释放时先停止场景加载监听、释放协调器、解除订阅并清空请求关联；重复 `dispose` 只返回幂等回执。
- `Assets/Tests/PlayMode/MultiSceneCoordinatorPlayModeTests.cs`
  - 通过真实 Bootstrap 和真实默认程序集桥接器，依次请求正式九场景目录。
  - 燃气发电成功切换；八个尚未交付内容的空场景结构化失败并恢复燃气基线。
  - 每次请求均验证桥接实例数、浏览器初始化次数和协调器订阅数恒为一，且活动控制器引用与协调器保持一致。
  - 验证首次释放、重复释放和释放后的对象选择回调阻断。
