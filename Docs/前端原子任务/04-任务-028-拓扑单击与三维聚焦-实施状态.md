# 任务-028：拓扑单击与三维聚焦实施状态

**状态：** 进行中（85%）
**更新时间：** 2026-08-05

## 已实施

- 新增 `TopologySelectionFocusCoordinator`（拓扑选择聚焦协调器）。它只接收来源、关联标识和清单显式声明的 `sceneNodeId`（三维节点标识），不接触画布、iframe（内嵌框架）、窗口对象、模型名或坐标。
- 拓扑单击先经唯一协调器提交二维节点与关联路径选择，再异步发送 `focusNode`（聚焦节点）。三维聚焦失败不会撤销已提交的二维描边、路径或选择状态。
- 仅当来源为 `topology`（二维拓扑）、节点存在显式 `sceneNodeId` 且 Unity 已在握手中声明 `focusNode` 能力时才发送命令。无映射、未协商能力、非拓扑来源一律无副作用，不根据节点标题、图元、坐标或资源名称推断三维对象。
- 同一关联标识只会发送一次聚焦；最近关联标识使用固定容量 64 的映射表，达到容量后淘汰最早项，不保存无界历史或未结算 Promise（承诺）。
- `unity`（Unity 运行时）来源被协调器直接阻断，避免未来三维反向选择回写时形成二维→三维→二维的聚焦环。Unity→二维的正式订阅与外层事件归属任务-037。
- 双击解析改为复用当前活动拓扑内已经命中的 `nodeId`（节点标识），不再将画布字符串转换成新的标识，避免过期画布回调或伪造标识越过当前拓扑边界。
- 清单校验新增三维节点登记闭环：拓扑节点与设备映射中的 `sceneNodeId` 必须存在于所属 Unity 场景映射的 `sceneNodeIds`（已登记三维节点）中；仅有格式正确的标识但 Unity 未登记时会在发布前拒绝加载。
- 本地 Unity 模拟页新增仅用于回归的 `data-focus-node-count`（聚焦次数）属性；它不记录节点、场景或业务载荷，不会进入跨窗口协议或正式 WebGL 页面。

## 验证

- 聚焦协调器专项单元测试 3 项通过：拓扑来源且显式映射只聚焦一次；Unity 来源、无映射和无能力不回写；聚焦失败后重放相同关联不会再次发送。
- 清单校验新增回归：二维节点与设备映射共同引用所属 Unity 场景未登记的三维节点时，分别以 `topology.scene-node-unregistered` 和 `device-mapping.scene-node-unregistered` 阻断发布。
- 当前前端全量回归：31 个测试文件、134 项测试通过。
- 类型检查和生产构建通过。
- 内部浏览器三层夹具验证：燃气测试节点具有显式且已登记的 `scene-node.gas-turbine` 映射；首次实际 Canvas（画布）点击收到 Unity `focusNode` 成功回执；本地计数从 `0 → 1 → 1`，重复点击未重复下发；控制台无错误。
- 真实燃气网页图形验证：用户在发布目录 `Builds/Releases/燃气发电场景与拓扑图联动包` 中人工点击拓扑节点，已确认 Unity 三维模型实际聚焦并显示描边。该证据覆盖当前已显式登记的燃气映射链路；其余未登记节点保持纯二维选择，不据此推断三维目标。
- 本次本地服务已停止，端口 `5510`、`5511`、`5174` 均已释放。
