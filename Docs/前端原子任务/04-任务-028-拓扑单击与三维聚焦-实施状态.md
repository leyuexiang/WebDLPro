# 任务-028：拓扑单击与三维聚焦实施状态

**状态：** 已完成（100%）
**更新时间：** 2026-08-07

## 完成结论

任务-028已按原始验收口径关闭：二维拓扑单击立即提交本地节点与关联路径选择；仅在当前稳定场景、当前活动拓扑、显式 `sceneNodeId`（三维节点标识）映射和已协商 `focusNode`（聚焦节点）能力同时满足时，异步请求 Unity 聚焦。三维失败不撤销二维选择，同一 `selectionId`（选择标识）在前端和 Unity 两端均只执行一次，Unity 来源不会反向触发聚焦回写。

## 已实施

1. `TopologySelectionFocusCoordinator`（拓扑选择聚焦协调器）只接收选择来源、品牌化 `selectionId` 和清单显式声明的 `sceneNodeId`，不接触画布、内嵌框架、窗口对象、模型名称、层级路径或坐标。
2. 拓扑单击先经唯一可视化协调器提交二维节点与关联路径，再同步活动画布；只有提交成功后才异步请求三维聚焦。聚焦失败只返回失败结果，不回滚已经提交的二维描边、路径或选择状态。
3. 当前运行时不是就绪态、画布回调不属于当前稳定场景/拓扑、选择未变化、节点无显式三维映射或 Unity 未声明聚焦能力时均无副作用，不根据标题、图元、坐标、文件名或资源名称猜测三维对象。
4. 新增独立 `SelectionId`（选择标识）品牌类型及工厂。每次已接受的拓扑选择生成一个不超过128字符的稳定选择标识，并随 `focusNode` 载荷发送；`view.open`（视图打开）中的聚焦动作则把其唯一事务标识显式转换为选择标识，禁止类型层隐式混用。
5. 网页图形协议将聚焦载荷固定为 `sceneNodeId + selectionId + isolate`（三维节点、选择标识、隔离开关）。前端连接器、Unity 桥接器、本地 Unity 模拟页和开发测试面板均拒绝缺少选择标识的旧载荷。
6. 前端协调器使用固定容量64的选择标识映射表，在调用三维端口前登记；聚焦失败后重放同一选择也不会再次发送。组件销毁时显式清空去重表。
7. Unity 桥接器使用固定容量64的队列与哈希集合进行常数时间查重。同一选择即使换用新的消息标识重发，也只返回幂等成功结果，不再次触发相机补间、模型描边或控制器调用；释放与销毁时同步清空两个集合。
8. `unity`（Unity 运行时）来源被拓扑聚焦协调器直接阻断。三维反向选择只同步二维选择与受控外层事件，不会形成二维→三维→二维循环。
9. 双击继续复用当前活动拓扑内已命中的 `nodeId`（二维节点标识）；双击自身不重复提交选择或发送聚焦，派生的重复单击由当前选择和选择标识幂等边界共同阻断。
