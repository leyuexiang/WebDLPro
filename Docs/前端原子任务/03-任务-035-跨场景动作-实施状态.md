# 任务-035：跨场景动作实施状态

## 当前状态

- 状态：已完成（100%）
- 已完成：跨场景流程动作范围识别、目标场景与拓扑的原子清单校验、跨场景“预解析 → 切换 Unity → 等待场景最终就绪 → 执行动作 → 激活拓扑 → 单次提交”事务、阶段化加载反馈、遮罩交互阻断、动作失败策略、取代和物理回退复用。
- 关闭依据：任务-035交付跨场景动作机制和加载反馈，不负责猜测正式业务动作、参数或九场景资源。当前真实燃气联调清单没有流程动作，已通过能力门禁不向父页面虚报 `workflow.trigger`（流程触发）能力；正式映射与真实发布联调继续由任务-039—047、049 和 052收口。

## 实现规则

1. 流程触发路由器只比较“清单动作目标场景”与“当前稳定场景”；相等进入任务-034同场景路径，不等才进入本任务路径。
2. 跨场景处理器把动作投影为唯一 `view.open`（原子打开视图）事务，严格执行“预解析目标拓扑 → 切换三维场景 → 等待目标场景最终确认 → 执行动作 → 激活拓扑 → 提交稳定上下文”。
3. 协调器快照同时保留上一个稳定上下文、目标场景、目标拓扑、Unity 子系统状态、拓扑子系统状态及单条当前加载阶段反馈；尚未提交的目标不会作为稳定视图对外发布。
4. 运行时宿主只转交连接器已经按来源、原请求、场景、事务、阶段和数值范围校验的加载反馈。协调器再次拒绝旧事务、错目标场景和进度回退；提交、失败、取代或释放都会清空这条瞬态数据。
5. 遮罩只显示脱敏阶段与百分比：卸载当前场景、加载目标场景、初始化目标场景或恢复上一稳定场景。它不显示目标标识、事务标识、资源地址或 Unity 原始信息，并以 `inert`（非活动）阻断两个容器。
6. 目标动作未完成前不激活目标拓扑。仅清单显式声明 `commit-view-with-warning`（带警告提交视图）的非关键动作，可在失败终态保留诊断后提交目标视图；默认 `keep-current-context`（保持当前上下文）继续恢复或物理回退。
