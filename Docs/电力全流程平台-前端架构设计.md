# 电力全流程平台前端架构设计

## 一、结论

系统采用“平台父页面 + 前端可视化壳 + 单 Unity 播放器”的三层结构。第一层是全局沙盘，第二层是业务场景与厂区拓扑，第三层是关键环节精细场景与独立拓扑。所有切换由版本化结构清单和受控动作驱动，不按标题、路径、坐标或模型名称猜测关系。

## 二、职责边界

| 层级 | 主要职责 | 禁止事项 |
| --- | --- | --- |
| 平台父页面 | 菜单、用户身份、平台内部设备绑定、发送公开命令 | 注入 Unity 方法、资源路径或我方结构清单 |
| 前端可视化壳 | 协议校验、稳定上下文、二维拓扑、动作事务、状态快照 | 保存平台真实设备编号、拼装任意 Unity 调用 |
| Unity 播放器 | 单实例多场景、镜头、模型选择、四态、第三层资源 | 根据中文名或层级扫描补映射 |

## 三、页面结构

- 第一层：全屏 Unity 沙盘，不显示业务拓扑。
- 第二层：上部 Unity 业务场景，下部公共拓扑面板；命名镜头按钮属于 Unity 视口覆盖层。
- 第三层：关键环节三维与独立二维拓扑双区；拓扑只加载当前 `topologyDataContextId` 登记的完整文件，不显示筛选轨。
- 单 Unity 内嵌网页框架和单拓扑画布在上下文切换时复用，避免重复初始化、事件监听和图片缓存。

## 四、稳定标识

| 标识 | 责任 |
| --- | --- |
| `sceneId` | 业务场景 |
| `topologyId` | 第二层拓扑入口 |
| `nodeId` | 二维业务节点、平台内部绑定键、状态快照主键 |
| `sceneNodeId` | Unity 三维节点 |
| `actionId` | 平台公开动作 |
| `processDetailId` | 第三层关键环节 |
| `topologyDataContextId` | 第三层独立拓扑上下文 |
| `penId` | 单份数据交换格式拓扑文件内的图元 |

`nodeId`、`sceneNodeId`、`penId` 和平台内部 `deviceId` 不可混用。全部跨域关系必须通过显式清单登记。

## 五、配置模型

结构清单必须同时包含场景、拓扑、动作、第三层目录和 Unity 场景映射。每次发布还必须对齐：

- 清单版本；
- Unity 构建标识和协议版本；
- 场景映射版本；
- 拓扑与动作配置版本；
- 场景资源版本和资源摘要。

场景或动作发生变化时，源生成器、运行时校验器、最终产物门禁和文档必须原子更新。当前目录与能力见[十一场景当前配置基线](前端原子任务/06-十一场景当前配置基线.md)。

## 六、运行事务

1. 外层命令通过来源、协议版本、实例、会话、消息编号和载荷校验。
2. 可视化壳解析目标动作并建立单调事务编号。
3. 需要切场景时先让 Unity 完成受控加载，再提交二维拓扑和稳定上下文。
4. 快速连续请求只允许最后一个有效事务提交；迟到回执不得覆盖新状态。
5. 任一步失败都保留或恢复最后稳定上下文，不提交二维/三维错配状态。
6. 释放时取消在途请求、解绑监听、销毁临时材质并释放场景资源。

## 七、拓扑运行时

- 第二层筛选只把选中集合规范化为 `combinationKey`，再常数时间查找并加载对应完整文件。
- 架构层独立且与网络层、业务层、关键环节层互斥；未登记组合保持当前画布并提示缺少输入。
- 不按标签或坐标执行逐图元显隐，不合并多份数据交换格式文件。
- 图元索引、连线索引和 `penId → nodeId` 绑定在文件加载时构建一次。
- 设备状态以 `nodeId` 为中央快照主键；切换文件后在首次正式重绘前批量重放，并只重绘一次。
- 图片、动态图、图元注册、画布、提示、选择、高亮和重置能力均走公共实现。

## 八、Unity 运行时

- `Bootstrap` 常驻，业务场景按目录键加载和释放；构建顺序及闭集由生成器和测试锁定。
- 场景目录声明能力必须与适配器运行时能力、场景序列化前置条件一致。
- 命名镜头只接收稳定 `cameraPoseId`；镜头高亮和淡化是运行时临时效果，复位或切场景后必须完整恢复。
- 上层控制节点可聚合模型但只接受拓扑聚焦；下层现场设备负责三维反选和四态。
- 第三层资源通过准备、提交、退出事务切换，不用第二层拓扑标识替代关键环节标识。

## 九、性能要求

- 查询使用预构建映射，避免在点击、状态刷新和筛选时扫描全部图元或场景对象。
- 同一状态批次只更新变化图元并统一重绘。
- 异步拓扑加载和场景切换使用递增请求编号或中止控制器隔离竞态。
- 公共图片缓存跨拓扑文件保留；组件卸载或资源版本失效时统一释放。
- 事件监听、尺寸观察器、计时器和临时材质必须有明确生命周期，禁止重复注册和泄漏。

## 十、安全与发布

- 平台通过内嵌网页框架进入我方根入口，不直连 Unity。
- 外层消息只接受精确父来源和受控命令；查询参数不能传入任意资源地址。
- 发布目录不可变，变更必须生成新发布标识和摘要。
- 普通前端构建不是交付包；最终目录必须通过结构清单校验和产物门禁。
- 发布流程见[测试包与正式包输出标准](前端原子任务/测试包与正式包输出标准.md)。
