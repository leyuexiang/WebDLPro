# 燃气发电场景模型与流程映射表

**状态：** 基于 Unity 编辑器真实场景的初步映射，待业务确认后作为 `ProcessSceneConfig` 的录入依据。  
**读取对象：** `Assets/Scenes/SampleScene.unity`，Unity Editor 中加载的 `SampleScene`。  
**读取方式：** 检查场景层级、实例路径、Transform、`MeshFilter`、`MeshRenderer` 的世界包围盒与材质引用；不是仅依据 FBX 文件名推断。

> 置信度说明：**高**表示两个对象的包围盒相接或重叠，且设备名称与工艺关系一致；**中**表示空间位于同一工艺走廊、名称支持该判断，但中间连接细节未拆分；**待确认**表示模型中没有足够的几何或命名证据。所有“待确认”项不应直接固化为生产流程配置。

## 1. 场景扫描结论

- 根节点“场景”下共有 **55 个**模型实例，所有核心对象均为其一级子对象。
- 核心设备、管道和辅助建筑大多是一个 `MeshFilter + MeshRenderer` 的单网格实例，当前**没有 Collider**；对象点击需要增加代理 Collider 或交互热点。
- 现有管道为 **8 段**：`管道1`、`管道2`、`管道3`、`管道4`、`管道5`、`管道6`、`管道7`、`管道9`。**不存在 `管道8`。**
- 管道 1–4 当前使用 `Assets/Art/Materials/17 - Default.mat`；管道 5–7、9 使用 `Assets/Art/Materials/10 - Default.mat`。任何流动材质替换均需先保留并可还原这两套原材质。
- 两套余热锅炉都是单一 MeshRenderer；“炉体 / 汽包 / 烟囱”不能直接作为三个独立模型显隐或单独换材质。需要将它们拆分为独立资产，或以热点 + 相机下钻的方式表达细分步骤。
- 场景内没有名称或几何能直接确认的“燃气管网”模型，也没有明确连接发电机与升压站的独立电缆/电力管段。它们应先作为拓扑端点和视觉高亮处理，不能虚构为已有的流动管段。

- 燃气管网 → 进气/燃机；场景中没有明确的上游燃气管网模型。
- 余热锅炉 → 汽轮机；两个模型空间紧邻/相交，但没有单独命名的外接蒸汽管段。
- 燃机发电机 / 汽轮发电机 → 升压站 / 电网；场景中没有可确认的直连电力管段。`电网电线`位于公共电网区域，不是两台发电机到升压站的可识别连线。

## 6. 需要业务确认的最小清单

1. `管道5/7` 是否为“进气/入口烟道”，还是为“燃气管”；确认后决定使用空气或燃气流动材质。
2. `管道2/4` 的流程方向及介质：汽机排汽至冷凝器、凝结水回流，还是含双向/不同工况切换。
3. 是否将 `管道1/3` 视为机械联轴器；若确认，应从所有 `PipelineFlowController` 路由中排除。
4. 炉体、汽包、烟囱是否必须分别点击、分别下钻或分别隐藏。若必须，需要提供拆分模型或确认三个热点位置。
5. 上游燃气管网以及发电机至升压站的可视化要求：补充模型、使用 2D 拓扑叠加，或仅使用高亮/能量脉冲。
6. 平台一次指令是控制 1/2 号机组之一，还是默认两套机组同步演示；这会决定 `enterProcessStep` 是否增加 `unitId` 参数。

## 7. 可直接开始的开发范围

在未确认第 6 节之前，以下内容可以安全开始且不会返工：

- 依据本表为所有核心模型建立稳定 ID、机组组和周边组。
- 实现总览、按机组隔离、相机下钻、复位、显隐恢复和对象选中回传。
- 为 `管道6` 与 `管道9` 接入燃气排烟流动效果，并在 Unity 中逐段校正 UV 方向。
- 为 `管道1/3`排除流体材质路径；为 `管道2/4/5/7`预留可配置材质档案和方向参数。
- 扩展 iframe 协议为 `enterProcessStep(processId, stepId, unitId?)`，但在未确认的路由上返回“未配置/待确认”而不是错误播放效果。
