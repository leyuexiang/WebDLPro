## 🎯 核心保护机制

### 时间锁定流程

```
用户启动应用
    ↓
初始化安全管理器
    ↓
读取当前系统时间
    ↓
┌─────────────────────┐
│ 是否超过过期日期？   │
└─────────────────────┘
    ↓ 是              ↓ 否
拒绝运行          检查时间回拨
    ↓                  ↓
显示过期提示      是否回拨？
    ↓                  ↓ 是
阻止所有通信      拒绝运行
                      ↓ 否
                  检查警告期
                      ↓
                  正常运行
```

### 消息加密流程（可选）

```
前端发送消息
    ↓
检查是否需要加密
    ↓ 是
序列化 payload
    ↓
AES-256-CBC 加密
    ↓
Base64 编码
    ↓
添加 "ENC:" 前缀
    ↓
发送到 Unity
    ↓
Unity 检测前缀
    ↓
Base64 解码
    ↓
AES-256-CBC 解密
    ↓
反序列化 payload
    ↓
正常处理
```

## 🔧 使用步骤

### 第一步：配置过期日期

```bash
cd power-data-web/src/host-bridge
node configure-security.js --days 90
```

### 第二步：集成到前端

在 `App.vue` 中添加：

```typescript
import { useSecurityInit } from '@/host-bridge/security-example';

const { isExpired, initializeSecurity } = useSecurityInit();

onMounted(async () => {
  await initializeSecurity();
});
```

### 第三步：重新编译

```bash
# 前端
cd power-data-web
npm run build

# Unity
# 在编辑器中等待脚本编译完成
# Build WebGL 项目
```

### 第四步：测试验证

1. 修改系统时间到过期日期之后
2. 启动应用，应该看到过期提示
3. 恢复系统时间
4. 修改系统时间到过期前7天内
5. 启动应用，应该看到警告横幅

## 🛡️ 安全等级

### 当前实现（基础防护）

| 保护类型 | 实现状态 | 防护等级 |
|---------|---------|---------|
| 时间锁定 | ✅ 已实现 | ⭐⭐⭐ |

### 可抵御的攻击

✅ **随意使用** - 普通用户无法绕过时间限制  
✅ **简单逆向** - 密钥混淆增加了静态分析难度  
✅ **时间调整** - 防时间回拨机制可以检测  
✅ **无意拖欠** - 明确的过期提示和技术限制  

### 无法防御的攻击

❌ **专业破解** - 有经验的逆向工程师可以破解  
❌ **内存修改** - 运行时可以修改内存中的变量  
❌ **代码修改** - 可以修改编译后的代码移除检查  
❌ **密钥提取** - 可以从内存或代码中提取密钥

## 🎓 技术亮点

1. **密钥派生**
   - 使用 PBKDF2 而非硬编码
   - 10,000 次迭代增加破解难度
   - XOR 混淆增加静态分析难度

2. **双端一致**
   - C# 和 TypeScript 使用相同算法
   - 确保加密消息可互操作
   - 配置工具自动同步

3. **多层检查**
   - 启动时检查
   - 接收消息时检查
   - 发送消息时检查
   - 可选的定期检查

4. **用户体验**
   - 7天内开始警告
   - 清晰的过期提示
   - 联系信息可配置
