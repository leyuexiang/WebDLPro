# 通信加密与时间限制保护方案

## 概述

本方案为 Unity WebGL 与前端通信层提供双重保护：

1. **时间锁定**：设置试用期限，超期后系统拒绝运行
2. **消息加密**：对敏感通信内容进行 AES-256 加密

⚠️ **重要提示**：此方案仅增加破解难度，无法完全防止逆向工程。建议配合商业合同、分阶段付款等商业手段使用。

---

## 核心功能

### 1. 时间锁定

- **过期检查**：启动时检查当前日期是否超过设定的过期日期
- **防时间回拨**：记录上次运行时间，检测系统时间是否被人为调整
- **过期警告**：距离过期7天内会显示警告提示
- **硬编码过期**：过期后完全拒绝运行和通信

### 2. 消息加密

- **AES-256-CBC 加密**：使用业界标准的对称加密算法
- **密钥混淆**：密钥通过多步计算生成，增加静态分析难度
- **双端一致**：Unity C# 和前端 TypeScript 使用相同的密钥和算法
- **可选启用**：可以选择性地对敏感命令进行加密

## 使用方法

### Unity 端（已自动集成）

安全检查已集成到 `UnityIframeBridgeManager.cs` 中：

```csharp
// 启动时自动检查
private void Awake()
{
    if (CommunicationSecurityManager.Instance.IsExpired())
    {
        Debug.LogError("系统试用期已过期，无法启动。");
        return; // 阻止后续初始化
    }
}

// 接收消息时自动检查
public void ReceiveFromParent(string messageJson)
{
    if (CommunicationSecurityManager.Instance.IsExpired())
    {
        return; // 拒绝处理消息
    }
    // ... 正常处理
}

// 发送消息时自动检查
private static void SendSerializedMessage(string messageJson)
{
    if (CommunicationSecurityManager.Instance.IsExpired())
    {
        return; // 拒绝发送消息
    }
    // ... 正常发送
}
```

### 前端使用示例

#### 1. 初始化（在应用启动时）

```typescript
import { securityManager } from '@/host-bridge/communication-security';

// 在应用入口初始化
async function initializeApp() {
  try {
    // 初始化加密管理器
    await securityManager.initialize();
    
    // 检查是否过期
    if (securityManager.checkExpired()) {
      alert('系统试用期已过期，请联系开发商续期。');
      return;
    }
    
    // 显示过期警告（如果临近过期）
    const warning = securityManager.showExpirationWarning();
    if (warning.show) {
      console.warn(warning.message);
      // 可以在UI上显示提示
    }
    
    // 继续正常初始化...
  } catch (error) {
    console.error('初始化失败:', error);
  }
}
```

#### 2. 发送加密消息（可选功能）

```typescript
import { securityManager } from '@/host-bridge/communication-security';

// 对敏感命令的payload进行加密
async function sendSecureCommand(payload: any) {
  try {
    // 将 payload 序列化
    const plainJson = JSON.stringify(payload);
    
    // 加密
    const encrypted = await securityManager.encryptPayload(plainJson);
    
    // 发送时使用特殊标记
    const message = {
      channel: 'power-3d-unity-bridge',
      version: 1,
      type: 'someCommand',
      payload: {
        text: 'ENC:' + encrypted  // Unity端会检测 "ENC:" 前缀并解密
      }
    };
    
    // 发送到Unity
    iframe.contentWindow.postMessage(message, targetOrigin);
  } catch (error) {
    console.error('发送加密消息失败:', error);
  }
}
```

#### 3. 接收加密消息（如果Unity返回加密内容）

```typescript
// Unity端可以类似地加密返回消息
window.addEventListener('message', async (event) => {
  const message = event.data;
  
  // 检查是否为加密消息
  if (message.payload?.text?.startsWith('ENC:')) {
    try {
      const encrypted = message.payload.text.substring(4);
      const decrypted = await securityManager.decryptPayload(encrypted);
      const payload = JSON.parse(decrypted);
      // 使用解密后的payload
    } catch (error) {
      console.error('解密消息失败:', error);
    }
  }
});
```

## 配置修改

### 修改过期日期

#### Unity 端：

编辑 `Assets/Scripts/Security/CommunicationSecurityManager.cs`：

```csharp
private DateTime CalculateExpirationDate()
{
    DateTime baseDate = new DateTime(2024, 1, 1);
    
    // 修改这里设置试用期天数
    int obfuscatedDays = 90;  // 例如：90天试用期
    
    return baseDate.AddDays(obfuscatedDays);
}
```

#### 前端：

编辑 `power-data-web/src/host-bridge/communication-security.ts`：

```typescript
private constructor() {
  const baseDate = new Date('2024-01-01T00:00:00Z');
  
  // 修改这里设置试用期天数（必须与Unity端一致）
  const obfuscatedDays = 90;  // 例如：90天试用期
  
  this.expirationDate = new Date(baseDate.getTime() + obfuscatedDays * 24 * 60 * 60 * 1000);
}
```

### 修改加密密钥

如果需要更换密钥（增强安全性），需要同时修改 Unity 和前端的密钥生成逻辑。

⚠️ **注意**：密钥生成代码中的魔数（如 `0x12345678`）应该同步修改，确保两端生成相同的密钥。

## 保护等级

### 当前实现的保护

✅ **时间锁定**
- 硬编码过期日期
- 防止时间回拨
- 启动和运行时多次检查

✅ **消息加密**
- AES-256-CBC 加密
- 密钥混淆（静态分析难度增加）
- PBKDF2 密钥派生

✅ **集成到通信层**
- 自动检查过期状态
- 支持可选的消息加密
- Unity 和前端双端保护

### 仍可被破解的方式

❌ **内存修改**：运行时可以通过内存编辑器修改变量
❌ **时间服务器**：可以通过拦截网络请求伪造时间
❌ **代码反编译**：Unity IL2CPP 和前端代码都可以被反编译
❌ **密钥提取**：内存中的密钥可以被 dump 出来

## 常见问题

### Q1：客户可以通过修改系统时间绕过吗？

A：部分可以。本方案记录了上次运行时间，如果检测到时间大幅回拨会拒绝运行。但如果一直保持未来时间，仍可绕过。更严格的方案需要联网验证 NTP 时间服务器。

### Q2：加密会影响性能吗？

A：影响很小。AES-256 加密非常快速，对于正常的消息通信（每秒几次）几乎无感知。但如果大量高频消息（如每帧通信），建议选择性加密敏感命令。

### Q3：过期后能恢复吗？

A：可以。修改源码中的过期日期重新编译即可。或者实现许可证激活系统（代码中已有 `ValidateLicenseKey` 方法框架）。

### Q4：这个保护够安全吗？

A：**不够**。任何客户端保护都可以被破解。此方案主要作用是：
- 增加破解难度（需要一定技术能力）
- 提供法律证据（明确标注试用期）
- 防止"无意拖欠"（善意客户不会刻意破解）

真正的保护需要依赖商业合同和信任关系。

## 后续增强建议

如果需要更强的保护，可以考虑：

1. **联网验证**：每次启动联网检查许可证服务器
2. **硬件绑定**：绑定到特定机器，防止拷贝
3. **关键逻辑服务端化**：把核心算法移到服务器
4. **定期心跳**：运行时定期验证，而非仅启动检查
5. **代码混淆增强**：使用商业级混淆器（如 Obfuscator）
