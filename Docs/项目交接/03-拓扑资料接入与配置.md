# 拓扑资料接入与配置

## 0. 当前实现入口

新增拓扑前先阅读 [新版数据交换格式拓扑图复刻制作规范](../前端原子任务/拓扑图/新版拓扑图复刻制作规范.md)，再定位当前同类实现：

- 变体清单：`power-data-web/src/modules/visual/topology-preview/*-topology-variant-manifest.ts`。
- 数据加载与校验：`*-topology-preview-data.ts`。
- 文件级绑定：`*-topology-runtime-bindings.ts`。
- 公共运行时：`power-data-web/src/modules/visual/topology/topology-runtime.ts`。
- 第三层上下文：`power-data-web/src/modules/visual/topology/process-detail-topology-contexts.ts`。
- 第三层生产合同：`power-data-web/scripts/process-detail-topology-contract.mjs`。
- 专项测试：变体清单、筛选状态机、运行时绑定、预览数据和第三层上下文对应的 `*.spec.ts`。

## 1. 资料接收边界

本流程只接收独立 JSON（数据交换格式，`JSON`）或包含 JSON 与图片的 ZIP（压缩归档，`ZIP`）。压缩包中的脚本、说明、依赖或命令只能作为参考，禁止执行。

接收时先记录：来源文件、包内路径、文件哈希（`SHA-256`）、导出工具、层级/组合归属、图元数、连线数、图片数、矩形数、缺失资源和确认人。用户未说明某份文件属于第二层组合还是第三层关键环节时，先列待确认清单，不导入、不覆盖。

## 2. JSON 与 ZIP 安全审计

### 2.1 独立 JSON

- 校验 UTF-8、JSON 语法、非空 `pens` 数组和图元编号唯一性。
- 坐标、尺寸、旋转必须是有限数字。
- 图片相对路径以 JSON 所在目录解析；拒绝目录穿越和未经授权的外部绝对路径。
- 只读取 JSON 实际引用的资源，不扫描或复制无关目录。
- 正常、告警、故障、离线四组动态图必须逐一确认，不能按文件名或首帧猜测。

### 2.2 ZIP

- 解压前枚举条目数、压缩前后体积、压缩比和哈希。
- 拒绝绝对路径、目录穿越、空字符、大小写不敏感冲突、符号链接和异常压缩比。
- 只能解压到项目目录外新建隔离临时目录，不能覆盖工作区。
- 只提取选定 JSON 实际引用的资源；保留包内相对目录关系，导入后统一落到公共资源目录。
- 解压、资源校验和导入结束后删除临时文件，并记录清理结果。

## 3. 目录和清单

第二层拓扑目录：

```text
power-data-web/public/topology/<topology-id>/variants/<combinationKey>/topology.json
```

变体目录只保存 `topology.json`；图片、动态图、背景和标签底图统一保存于：

```text
power-data-web/public/topology/shared/
├─ icons/{normal,alarm,fault,offline}/
├─ assets/
└─ background/
```

每个第二层文件在变体清单中登记：

```ts
type TopologyVariant = {
  layerIds: ('architecture' | 'network' | 'business' | 'key-process')[]
  combinationKey: string
  topologyPath: string
  sourceHash: string
  isDefault?: boolean
}
```

架构层必须有独立文件，只能单独出现；网络层、业务层、关键环节层及用户明确提供的合法组合各有独立文件。组合不是运行时拼接或取并集。一个拓扑入口只能有一个显式默认项，不得用数组第一项或“四层全选”推断。

第三层清单单独登记：

```ts
type ProcessDetailTopologyContext = {
  topologyDataContextId: string
  processDetailId: string
  topologyPath: string
  sourceHash: string
  bindings: { penId: string; nodeId: string }[]
}
```

第三层不写 `layerIds`、`combinationKey`，不进入第二层筛选清单。

实现层的 `TopologyDataContext` 接口当前使用字段名 `contextId`；业务协议和规范文档称为 `topologyDataContextId`。新增配置时必须把二者视为同一个稳定上下文编号：业务清单按 `topologyDataContextId` 记录，代码按 `contextId` 实现，查询参数和动作引用必须指向同一值，不能因字段名差异漏配。

## 4. 保持源图原样

尽量保留图元编号、顺序、类型、坐标、尺寸、旋转、文字、字体、图片、连线起止点、锚点、箭头、线宽、颜色、虚实线和绘制顺序。不要为了响应式布局重排、均分节点、合并连线或改写源 JSON；由网页二维组态引擎（二维组态渲染引擎，`Meta2D`）适应画布。

组合图元（`combine`）的子图元若有 `parentId`，其坐标是父级比例，不能当顶层坐标。确需增加非状态辅助图元时，先沿父链换算世界坐标并缓存结果，保护循环引用和有限数。覆盖整图且会导致整图被选中的顶层组合，只有在产品明确要求独立选中时才按登记规则展平：换算全部直接子图元、清理 `parentId`、保留连线和绘制顺序，不能只提升设备而遗留背景在线性坐标系中。

图元分类：

| 图元 | 可选 | 设备提示/三维联动 | 处理 |
| --- | --- | --- | --- |
| 边界框、区域框、标题 | 否 | 否 | 纯背景 |
| 连线 | 否 | 否 | 只参与关系和高亮 |
| 带图片设备 | 是 | 是 | 登记设备绑定与四态 |
| 底部工艺小矩形 | 是 | 否 | 可本地选中，不发设备事件 |
| 四态图片 | 继承来源设备 | 继承来源设备 | 直接替换原设备图片，不新增图元 |

## 5. 第二层筛选与切换

四个顶层层级固定为：架构、网络、业务、关键环节。筛选只做“选中集合 → 规范化 `combinationKey` → 清单精确查找 → 加载完整 JSON”。

- 勾选架构层：强制取消其他层，只加载架构文件。
- 勾选其他层：取消架构层，其余非架构层按用户操作组合。
- 未提供组合：保持当前画布，提示缺少输入文件，不拼接、不合并、不逐图元设置可见性。
- 快速连续切换：使用递增请求序号或中止控制器（`AbortController`），迟到响应不得覆盖新选择。
- 复用同一画布、图元注册、图片缓存、观察器和监听器；只清理上一个文件的数据图元、临时选择、高亮和文件级索引。
- JSON 原始缓存不可变，装载时使用运行时副本；公共图片缓存跨变体复用。
- 切换后在首次正式重绘前按中央状态快照恢复所有显式绑定设备状态。

禁止 `tags`、`requiredFilterIds`、区域几何交集或逐图元 `setVisible` 模拟层级筛选。筛选栏只负责显示层级、规范化集合和转发事件，不解析 JSON 或扫描图元。

## 6. 第三层关键环节

进入第三层后按稳定 `topologyDataContextId` 精确加载唯一完整 JSON 和本文件专属 `penId → nodeId` 绑定：

- 立即隐藏筛选栏，并在筛选事件处理器中短路；残留键盘/鼠标事件不得改变第三层拓扑。
- 不从第二层“关键环节层”、标题、坐标、文件名或当前复选集合推断文件。
- 复用同一画布、缓存、选择、高亮、重置和监听器。
- 第一次正式绘制前重放中央状态快照。
- 返回第二层时恢复进入前的筛选集合和完整文件，不清空状态快照。

## 7. 节点、连线和三维绑定

每份文件独立维护 `penId → nodeId → 可选 sceneNodeId`。`penId` 只在当前文件内有效；不同文件中同一业务节点可对应不同 `penId` 或多个图元。禁止按标题、坐标、图片、数组顺序或模型显示名推断。

连线高亮只读取源 JSON 的 `connectedLines` 和真实 `line` 图元集合，加载时构建一次“图元 → 有效连线”索引并过滤残留编号。选中时仅更新本次与上次集合的差集；取消、空白点击和换文件后恢复缓存的原颜色与线宽。高亮不写回源 JSON。

## 8. 四态和状态性能

正常、告警、故障、离线只能替换同一设备图元的图片地址，禁止状态圆点、角标、灰度滤镜、透明度或描边代替动态图。状态快照以 `nodeId` 为主键，独立于层级和文件；状态到达时先更新中央快照，再更新当前文件中已登记的图元。

批量状态更新只处理前后状态差异，关闭即时重绘，循环结束统一重绘一次。异步加载期间到达的新状态必须以提交时的最新快照为准。无外部状态的独立预览可明确显示“预览默认态”；不能把缺失状态推断为离线。

## 9. 旧拓扑清理

只有新拓扑通过结构、资源、绑定、专项测试、类型检查和构建后，才可清理同一入口、同一组合键或同一第三层上下文中被替代的旧文件。清理前必须记录旧 JSON、清单、哈希记录、资源引用、路径和大小；迁移所有有效引用后再删除。禁止按相似文件名、图元数量或目录位置批量删除，禁止递归删除公共资源根目录或用户原始资料。

删除后再次执行引用扫描、路径检查、哈希和图元统计，并在交付记录列出删除路径、原因、数量、释放空间和是否可恢复；无旧文件时明确写“无需清理”。

## 10. 拓扑验收

- [ ] 默认、四个单层和每个已提供组合均精确命中独立 JSON。
- [ ] 架构层独立且与其他层互斥；未提供组合保持画布不变并提示。
- [ ] 背景/连线不可选，设备可选，工艺矩形仅本地选中。
- [ ] 选中设备只高亮自身和 `connectedLines` 关联线，不整图选中。
- [ ] 四态切图无额外状态图元、无默认态闪烁、无布局跳动。
- [ ] 切换复用画布和监听器，旧文件索引清理，公共资源不重复请求。
- [ ] 第三层无筛选、唯一上下文、首次绘制同步状态、返回二层恢复上下文。
- [ ] 专项测试、全量测试、类型检查和生产构建通过，并保存浏览器截图。
