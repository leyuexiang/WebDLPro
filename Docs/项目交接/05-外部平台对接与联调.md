# 外部平台对接与联调

## 1. 架构和信任边界

外部平台通过内嵌框架（网页内嵌，`iframe`）进入 `power-data-web` 根入口，再由子应用与 Unity 内层通信。平台不得直连 Unity，不得传入 Unity 方法、场景文件、模型/材质路径或任意坐标。

外层通道：`power-scene-topology-shell`；通信使用浏览器跨窗口消息（窗口消息，`window.postMessage`）；协议版本当前为 `2`。子应用只接受配置的精确父来源和当前父窗口。

每条消息必须包含通道、协议版本、消息类型、`instanceId`、`sessionId`、唯一 `messageId`；回复使用 `replyTo`。重复消息只返回缓存结果，不重复执行副作用。来源错误、版本错误、容量超限和释放竞争都返回固定脱敏错误。

## 2. 外层命令和事件

当前命令闭集以 `power-data-web/src/host-bridge/host-protocol.ts` 为准：

| 命令 | 用途 |
| --- | --- |
| `system.init` | 初始化会话和首个稳定视图 |
| `view.open` | 打开受控场景/视图，主要用于协议能力，不替代公开自测入口 |
| `workflow.trigger` | 按公开 `actionId` 执行原子工作流 |
| `process-detail.playback` | 控制已进入第三层的播放状态 |
| `device.states.update` | 提交完整设备状态快照 |
| `state.get` | 读取当前稳定状态 |
| `system.dispose` | 释放实例 |

事件闭集：`system.ready`、`system.ack`、`command.result`、`view.changed`、`topology.node.dblclick`、`scene.object.selected`、`state.snapshot`、`system.error`。

`system.ready` 只能声明当前构建实际安装的能力；Unity 全局可识别命令不代表当前业务场景一定支持。

## 3. 视图与动作语义

| 层级 | 必填 | 禁止混用 |
| --- | --- | --- |
| 第一层总览 | `sceneId: overview` | `topologyId`、`processDetailId` |
| 第二层业务 | 业务 `sceneId`、目标 `topologyId` | `processDetailId` |
| 第三层关键环节 | 业务 `sceneId`、`processDetailId` | 第二层 `topologyId` |

公开动作由结构清单解析，动作字段至少包括 `actionId`、目标场景、视图模式、可选拓扑/第三层、空参数白名单、受控 Unity 动作、失败策略和 `configVersion`。关键动作失败固定保留当前稳定上下文（`keep-current-context`）。

命名镜头按钮不是公开工作流动作，只发送内部受控 `moveCameraToPose({ cameraPoseId })`；不得用按钮点击改变流程、二维选择、第三层或设备状态。

## 4. 初始化、并发和释放

1. 结构清单、协议组合根和配置就绪后发送 `system.ready`，不等待 Unity。
2. 平台可立即发送 `system.init`；子应用同时等待 Unity 就绪和首个稳定视图。
3. 只有真实稳定视图提交后才能发送成功 `system.ack` 和 `view.changed`。
4. 同类快速命令使用单调事务编号取代旧事务；迟到回执不能覆盖新上下文。
5. 去重缓存、在途命令和等待槽设固定容量与超时；`system.dispose` 时统一清理监听器、材质、画布和缓存引用。

## 5. 节点和状态

二维双击事件只包含 `sceneId`、`topologyId`、`nodeId`。三维点击先由当前场景映射把 `sceneNodeId` 解析成唯一 `nodeId`，再发 `scene.object.selected`；不能把 Unity 对象名发给平台。

`device.states.update` 是完整快照，不是增量。状态项只使用稳定 `nodeId`、`deviceStatus`、`statusUpdatedAt` 等字段；状态值固定为 `normal`（正常）、`alarm`（告警）、`fault`（故障）、`offline`（离线）。缺失节点表示清除当前状态，不自动推断离线。二维状态先提交，三维同步失败不能回滚已接受的二维快照。

## 6. 沙盘建筑联动

总览中点击建筑只上报显式 `overviewBuildingId`，不直接拼接场景字符串。子应用校验总览上下文、活动实例和建筑注册表，再解析默认拓扑并形成受控视图意图；实际进入业务场景仍走公开 `workflow.trigger`/受控视图动作。

建筑故障视觉使用显式 `faultSourceNodeIds`，多个来源时按全部清除规则恢复；建筑标识不得当作业务 `sceneNodeId`、设备状态键或聚焦键。

## 7. 双方职责

我方负责：结构清单、动作和场景反向索引、二维拓扑、`nodeId`/`sceneNodeId` 显式映射、Unity 能力和事件、完整状态快照投影、错误脱敏、版本摘要和发布门禁。

平台负责：同源读取我方清单、平台内部 `nodeId → deviceId` 绑定、按公开动作生成菜单、发送完整状态快照、接收双击/反选/视图/错误事件，以及按发布标识部署和回滚。平台不得改写压缩产物、清单或向我方注入 `deviceId`。

## 8. 联调矩阵

| 用例 | 预期 |
| --- | --- |
| `system.init`/总览 | 返回真实 `system.ready`，首个稳定视图与清单一致 |
| `workflow.trigger` 进入场景 | 场景、默认拓扑、版本和 `view.changed` 一致 |
| 二维节点单击/双击 | 只使用 `nodeId`，有映射才聚焦三维 |
| 三维下层点击 | 唯一反选到 `nodeId`，不回发聚焦形成回环 |
| 地面/空白点击 | 清除二维选择并发送 `selectionCleared` 语义事件 |
| 完整状态快照 | 四态图片与状态文本一致，层级切换后不闪回默认态 |
| 第三层进入/退出 | 唯一上下文、无筛选、状态延续，退出恢复二层 |
| 快速命令/迟到回执 | 仅最新事务提交，旧回执不覆盖 |
| 未知标识/能力未声明/版本冲突 | 固定脱敏错误，保留当前稳定上下文 |
| 释放 | 画布、监听器、在途命令和运行时材质释放，无持续增长 |

## 9. 部署边界与待确认项

分别说明固定来源模式和运行时同源模式的父页面、子应用和 Unity 子页来源。合作方联调默认端口为 5575，本地测试默认端口为 5523；正式浏览器公开来源不得固化 `localhost`、`127.0.0.1` 或 `0.0.0.0`。部署前由合作方确认清单正式地址、刷新时机、绑定页展示 `resourceKey + nodeId + 设备号` 的方式、首份四态状态样例、双击后的业务打开动作、正式父页面/壳/Unity 来源和安全负责人。未确认项列为联调阻塞。
