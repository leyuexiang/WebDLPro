# 首屏区域高亮与轮询：外层 UI 调用指南

> 读者：最外层平台/父页面 UI 开发同事。前提：你们已按现有 `power-scene-topology-shell` 协议接入（`system.init` → `workflow.trigger` 等命令均已在用）。
> **本次对接对你们零协议改动**：8 个新按钮功能全部复用现有 `workflow.trigger` 通道，只是多了 8 个新 `actionId`。

## 1. 对接

按钮点击：`sendCommand('workflow.trigger', { actionId, expectedContextRevision: 最近收到的 contextRevision })`，`actionId` 按下表取值。回执、错误、并发版本语义与你们已接入的其他动作完全一致。

## 2. 新增的 8 个 actionId

| 按钮 | actionId | 点击后的三维效果 |
| --- | --- | --- |
| 调度中心 | `action.overview.area.dispatch-center` | 播放飞线动画（约 3.5 秒播完自动消失），同时调度中心围栏高亮（青绿色呼吸脉动+光晕） |
| 发电 | `action.overview.area.generation` | 五座发电站围栏统一高亮 |
| 输变电 | `action.overview.area.transmission` | 五座输变电站围栏统一高亮 |
| 配电 | `action.overview.area.distribution` | 配电站围栏高亮 |
| 用电 | `action.overview.area.consumption` | 居民/工业/机场围栏高亮 |
| 微电网 | `action.overview.area.microgrid` | 微电网围栏高亮 |
| 轮询（开始） | `action.overview.polling.start` | 从调度中心起播，按上表顺序**每 3 秒自动切换**，循环往复 |
| 轮询（停止） | `action.overview.polling.stop` | 停止循环，围栏/光晕/飞线全部恢复默认 |

高亮视觉统一为青绿色 #5DDDD8：围栏改色+亮度呼吸波动，底面同步变色，底部光晕粒子点亮。

## 3. 调用示例（与现有动作同格式）

```javascript
sendCommand('workflow.trigger', {
  actionId: 'action.overview.area.generation',
  // 可选但建议携带：取最近一次 command.result / view.changed 里的 contextRevision，
  // 版本过期会收到 context.revision.conflict 失败，防止旧操作覆盖新视图。
  expectedContextRevision: contextRevision,
}, '唯一消息编号');
```

- `sendCommand` 即你们现有的信封发送（`channel: 'power-scene-topology-shell'`、`version: 2`、`instanceId`、`sessionId`、唯一 `messageId`、`timestamp`），与现有调用完全一致。
- 这些动作**不带 parameters**，载荷只有 `actionId`（和可选 `expectedContextRevision`）。

## 4. 回执与错误

成功：`command.result` → `{ success: true, status: 'completed' }`，`contextRevision` 与调用前相同（这类动作不改变当前视图）。

失败（固定脱敏错误，无任何视觉副作用，保持当前画面）：

| 场景 | 返回 |
| --- | --- |
| 当前不在总览视图（第二层/第三层）时点击 | `action.execute.failed`（三维侧没有可用的区域控制器） |
| 传输过程中 actionId 被篡改/不在清单 | `action.unknown` |
| 携带未声明参数 | `action.context.mismatch` |
| expectedContextRevision 过期 | `context.revision.conflict` |

## 5. 按钮状态管理约定（重要）

- **六个区域按钮的"当前激活"标记由你们自己维护**：记录自己最后成功发出的区域 actionId 即可。三维端对重复点击同一区域是幂等的（保持高亮），切区域时前一个区域自动恢复默认——你们只需正常把按钮点亮/熄灭。
- **轮询按钮开关由你们自己维护**：第一次点击发 `polling.start`，再次点击发 `polling.stop`。
- **注意一个状态同步点**：轮询运行期间用户点了六个区域按钮中任意一个，三维端视为"手动接管"，**轮询会自动终止**。你们的轮询按钮需要同步回到"未开启"状态（当前协议没有"轮询被接管终止"的上行事件，按此约定处理即可；如你们需要该事件可提出，我们评估扩展）。
- 轮询期间三维端每 3 秒自动换区域；协议当前**没有**"当前轮询到哪个区域"的上行事件，如按钮栏需要跟随点亮，同样需要我们扩展状态快照后再做（先按"轮询按钮高亮、区域按钮不跟随"处理）。

## 6. 前置条件与联调

- 这 8 个动作只在**总览视图**有意义。建议：非总览视图时置灰这些按钮；若不置灰，点击会收到第 4 节的失败回执，画面不受影响。
- 新发布包的 `workflowActions` 动作摘要会自动多出这 8 项（你们按摘要自动生成菜单的流程不变）。
- 联调材料：我们会发一版本地测试包，其自测页含「首屏区域高亮与轮询操作」8 个演示按钮——即这 8 个动作的全链路（外层模拟页 → 嵌入壳 → Unity）样板，可直接对照实现。

## 7. 时序样例

```text
用户点[发电]      → workflow.trigger { actionId: 'action.overview.area.generation' }
                  ← command.result { success: true, status: 'completed', contextRevision: N }
用户点[轮询]      → workflow.trigger { actionId: 'action.overview.polling.start' }
                  ← command.result { success: true }（三维端开始每 3 秒自动轮换）
用户点[配电]      → workflow.trigger { actionId: 'action.overview.area.distribution' }
                  ← command.result { success: true }（三维端轮询自动终止，由配电接管高亮）
                  注意：此刻你们的轮询按钮应回置为"未开启"
用户再点[轮询]    → workflow.trigger { actionId: 'action.overview.polling.start' }
                  ← command.result { success: true }（从调度中心重新起播）
```
