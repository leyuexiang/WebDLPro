# 交接清单与故障排查

## 1. 开发交接清单

### 场景和沙盘

- [ ] 场景台账含 `sceneId`、Unity 路径、`unitySceneKey`、默认拓扑、能力和未确认项。
- [ ] `BusinessSceneCatalog.asset`、构建顺序和场景 GUID 已核对。
- [ ] Unity 骨架、相机、控制器、节点、四态、命名镜头和第三层引用无空引用/重复 ID。
- [ ] `overviewBuildingId → sceneId` 显式一对一；渲染器、碰撞体和故障来源配置齐全。
- [ ] `nodeId ↔ sceneNodeId` 映射表、反向选择边界和依据齐全。

### 拓扑

- [ ] JSON/ZIP 来源、哈希、层级、组合键、图元统计和缺失资源已登记。
- [ ] 架构层独立；每个已提供单层/组合对应一份完整 JSON；默认项唯一。
- [ ] 第三层按唯一 `topologyDataContextId` 登记，无筛选字段和筛选轨。
- [ ] 公共图片、四态、背景和标签资源去重并位于 `public/topology/shared/`。
- [ ] 每份文件的 `penId → nodeId → sceneNodeId` 显式绑定完成。
- [ ] 背景/连线不可选，设备/工艺节点选择语义符合规范，连线高亮可恢复。
- [ ] 中央状态快照跨层级保持，首次绘制已投影，无状态点/滤镜/布局跳动。

### 发布和平台

- [ ] 变更前后审计脚本输出已保存。
- [ ] 结构清单、场景反向动作、第三层目录、Unity 映射和发布摘要双向一致。
- [ ] 正向与负向门禁、专项测试、全量测试、类型检查、构建和第三层生产审计通过。
- [ ] 从源生成器生成全新发布目录，最终目录门禁为 `valid` 且问题数为零。
- [ ] 平台已收到发布标识、包类型、清单、能力矩阵、节点表、协议和回滚路径。
- [ ] 合作方使用 `workflow.trigger` 完成真实联调，不用内部捷径。

## 2. 上线和回滚

上线前确认同源清单、公开地址、父来源限制、协议版本、全屏、窗口缩放、长时间运行和监听器数量。回滚时停止新目录导流，恢复上一份完整门禁通过的目录，不混用新旧文件；清理失败发布缓存，重新执行握手、场景、状态、第三层和释放验证。

## 3. 常见故障定位

### 二维能选，三维不聚焦

检查节点是否有显式 `sceneNodeId`、是否在 `unitySceneMappings`、Unity `_nodes` 是否同 ID、目录是否声明聚焦能力、当前场景是否已激活。不要先改事件代码。

### 三维点击反选到控制系统

检查上层聚合是否错误设置为可反选，或同一渲染器是否进入多个反向索引。只允许规范下层物理节点回传。

### 四态声明存在但运行时失败

检查四态目标是否完整、渲染器是否重复归属、材质槽是否有可写颜色属性、适配器运行时能力是否通过。缺一项就降为不支持，不降低门禁。

### 沙盘入口不响应

先检查 `overviewBuildingId` 唯一性、目标场景一对一、碰撞体是否登记、当前实例是否为总览、来源是否可信；再检查默认拓扑。不要按对象名称猜场景。

### 拓扑切换整图被选中

检查源文件是否有覆盖全图的顶层 `combine`。只有明确要求独立选中且清单登记时才展平，并按父级比例换算所有子图元坐标；背景和连线仍禁用命中。

### 拓扑状态错位或闪回默认态

检查中央快照是否以 `nodeId` 为主键、是否在异步加载提交时重读最新快照、不同文件是否重新建立 `penId` 绑定、图片是否使用公共四态路径。禁止靠标题或数组序号补绑定。

### 平台握手成功但动作失败

分别检查外层命令是否安装、Unity 全局桥接是否声明、当前场景实际能力是否支持、版本是否一致。握手成功只代表协议可通信，不代表业务场景具备能力。

### 普通前端构建通过但不能交付

`npm run build` 不包含 Unity、结构清单、发布摘要和完整性清单。必须由源生成器生成新发布目录并通过 `validate:manifest` 和 `validate:release-artifact`。

### 改名后只有一侧生效

按破坏性变更处理：同步 Unity、拓扑、清单、动作、第三层、测试、版本和平台绑定；不能只改中文标题或一侧稳定 ID。

### 资料文档与现行代码冲突

《通用拓扑图参考0810_AI友好版.md》存在“第三层不渲染拓扑”的历史表述；当前代码和测试已经支持第三层独立完整 JSON。新增拓扑以新版拓扑规范、现行代码、测试和产物门禁为准，旧资料只用于图元—模型业务语义参考。
